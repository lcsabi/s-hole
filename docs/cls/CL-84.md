# CL 84: Dedup the dashboard query-filter params into one helper

## Description

Extract the shared query-filter param building in `internal/api/static/index.html`
into one `applyFilterParams(p)` helper that both `queriesURL` and `exportURL`
call. No behavior change; the produced URLs are byte-identical.

## Motivation

A `/code-review` pass over the CL 77-83 range flagged the export URL builder
(CL 81) as a verbatim copy of the recent-query URL builder. Both set the same
three params: `domain`, `client`, and the exclusive status picker that maps to
either `blocked` (true/false) or `outcome` (a failure token). The export comment
already admitted it "mirrors queriesURL's filter params".

The duplication puts the subtle status-picker mapping in two places. CL 81's
stated contract is that a filtered export is exactly the filtered view in bulk.
A later filter change (a new outcome value, a third status param, a rename) that
touched only one copy would make the export filter differently from the table the
operator sees. No test would catch it, because each function is exercised alone.
One shared helper makes that class of drift impossible.

## What it does

- **`internal/api/static/index.html`**: new `applyFilterParams(p)` sets the three
  filter params on a `URLSearchParams`. `queriesURL` calls it and adds `limit`;
  `exportURL` calls it and adds `format`. The status-picker comment moves onto the
  helper, its single home. The two callers keep the params each one owns.

## Design decisions

- **Extract a shared setter, not a shared URL builder.** The two endpoints differ
  in path (`/api/queries` vs `/api/queries/export`) and in the extra param each
  adds (`limit` vs `format`). A helper that sets only the common filter params
  keeps each caller in charge of its own path and extra param, so the shared part
  is exactly the part that must stay in step.
- **No behavior change, so no CHANGELOG bullet.** The rendered URLs are identical.
  This is an internal dashboard refactor, not an operator-visible change.

## Files changed

- `internal/api/static/index.html`: `applyFilterParams`, and the two callers
  reduced to it plus their own param.
- `docs/CL.md`: index row.

## Testing

- `make check` clean (fmt, vet, lint, lint-sh, test).
- The API tests that exercise the filter round-trip and the export filter parity
  (`internal/api/api_test.go`) stay green; they assert the server side that these
  URLs drive.
- Manual: the static file is `go:embed`, so no build step. Diffed the produced
  query strings for each filter combination (none, domain, client, blocked,
  allowed, unresolved, upstream error) before and after: identical.
