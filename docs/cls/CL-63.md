# CL 63: Surface an admin-server bind failure at startup (b/052)

## Description

**b/052** (main, api): a bad `api_listen` or a port conflict makes the admin
server fail to bind. Today the failure happens inside a background goroutine that
logs one ERROR line and exits, while `main` has already printed a startup banner
that advertises the admin UI as available. DNS keeps serving, but the operator is
told the UI is up when it is not, and the only signal is one easy-to-miss log
line that races the banner.

This CL binds the admin listener synchronously at startup, before backgrounding
the serve loop, so a bind failure is caught in order. On failure it logs a WARN
with remediation and the banner reports the admin UI as unavailable. DNS still
serves. This is a fail-open choice: the optional admin surface degrading must not
take DNS down.

## Motivation

`api.Server.ListenAndServe` binds the socket and then blocks serving, both inside
the `go func()` in `main`. So the bind result is only visible to that goroutine.
By the time it fails, `main` has already run `printNetworkHint`, which prints
`Admin UI -> http://<host>:<port>`. The banner and the goroutine's ERROR line
race, so they can print in either order, and the banner advertises a UI that is
not there. The admin server also serves `/healthz`, `/readyz`, and `/metrics`, so
a bind failure silently removes the health and metrics surface while DNS looks
healthy.

DNS is the critical service. A transient conflict on the admin port must not kill
it, so making the bind failure fatal (exit 1, symmetric with the DNS bind) is the
wrong trade here. The right behavior is to keep DNS serving and make the admin
degradation loud and the banner truthful.

## What it does

**Split bind from serve in `api.Server`.**

- Add `Serve(ln net.Listener) error`: it builds the `http.Server` with the
  existing slowloris timeouts, stores it in `httpServer` (so `Shutdown` still
  works), logs "admin UI listening" using `ln.Addr()`, and serves on the passed
  listener. `http.ErrServerClosed` is suppressed as before.
- Reimplement `ListenAndServe(addr string) error` as a thin wrapper:
  `net.Listen("tcp", addr)` then `Serve(ln)`. Existing callers and tests that use
  `ListenAndServe` keep working unchanged.

**Bind synchronously in `main`, then background the serve.**

- Before the goroutine, call `net.Listen("tcp", cfg.APIListen)`.
- On error: log a WARN naming `api_listen`, the error, and a remediation hint
  ("check for a port conflict or fix api_listen"); do not start the goroutine;
  mark the admin UI unavailable for the banner. DNS startup continues.
- On success: start `go apiServer.Serve(ln)` and mark the admin UI available.

**Make the banner honest.**

- `printNetworkHint` takes an `apiUp bool`. When the bind failed, it prints an
  explicit "Admin UI -> unavailable (api_listen bind failed)" line instead of a
  URL, in both the Unicode and ASCII banner branches. Because the bind now
  happens before `printNetworkHint`, the banner always reflects the real state
  and no longer races the serve goroutine.

## Design decisions

- **Fail-open, not fail-fast.** DNS is the reason the process exists. The admin
  UI is a convenience surface (LAN-trust, unauthenticated by design). A bind
  failure on the admin port degrades that surface loudly but leaves DNS serving.
  A fatal exit would let an admin-port conflict take DNS down, which inverts the
  priority.
- **Split bind from serve rather than probe-then-discard.** Doing a throwaway
  `net.Listen` just to test the port, closing it, and then letting the server
  bind again would reintroduce a race (the port can be taken in the gap) and a
  double bind. Handing the already-bound listener to `Serve` binds exactly once.
- **Keep `ListenAndServe` as the one-call form.** The existing tests and any
  external caller keep a bind-and-serve entry point. `Serve` is the new seam that
  `main` uses to separate the two phases.

## Files changed

- `internal/api/api.go`: add `Serve(net.Listener) error`; reimplement
  `ListenAndServe` on top of it; move the "admin UI listening" log into `Serve`
  using `ln.Addr()` (b/052).
- `internal/api/api_test.go`: `TestServe_OnBoundListener` (Serve on a bound
  listener answers `/healthz`, then Shutdown returns) and
  `TestListenAndServe_BindFailureSurfaces` (an occupied address returns a bind
  error synchronously) (b/052).
- `cmd/s-hole/main.go`: bind `cfg.APIListen` synchronously; WARN-and-continue on
  failure; background `Serve(ln)` on success; pass `apiUp` to `printNetworkHint`,
  which prints an unavailable line when the bind failed (b/052).
- `cmd/s-hole/main_test.go`: `TestPrintNetworkHint_AdminDownShowsUnavailable`
  (no URL, "unavailable" note when `apiUp` is false); the three existing banner
  tests pass `apiUp=true` (b/052).
- `docs/DESIGN.md`: admin-server section notes the synchronous bind and the
  fail-open behavior; the `ErrServerClosed` suppression now names `Serve` (b/052).
- `docs/BUGS.md`: b/052 (Fixed in CL 63).
- `docs/CHANGELOG.md`: `Fixed` bullet for the admin-server bind failure now being
  surfaced at startup (operator-visible).
- `docs/CL.md`: index row.
- `docs/cls/CL-63.md`: this file.

## Testing

- `TestServe_OnBoundListener`: `Serve` on a `net.Listen("127.0.0.1:0")` listener
  answers `/healthz`, then `Shutdown` returns.
- `TestListenAndServe_BindFailureSurfaces`: `ListenAndServe` on an occupied
  address returns a bind error synchronously (no hang), which is what main relies
  on to detect a bad `api_listen`.
- `TestPrintNetworkHint_AdminDownShowsUnavailable`: with `apiUp=false` the banner
  prints the unavailable note and no admin URL. The existing banner tests cover
  `apiUp=true` for both the Unicode and ASCII branches.
- `make check` green. `CGO_ENABLED=1 go test -race ./internal/api/ ./cmd/s-hole/`
  green (WSL). `GOOS=windows go build ./...` compiles. Coverage: api 90.9%
  (floor 85%); `cmd/s-hole` is not gated (43.3%).
