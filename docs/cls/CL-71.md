# CL 71: stabilize top-N tie ordering (b/056)

## Description

Give the top-N tally a deterministic tie-break (count descending, then name
ascending) so equal-count domains and clients keep a stable order across
dashboard polls. Fixes b/056.

## Motivation

The "Top Blocked Domains" panel in "Since start" mode reordered equal-count
domains on almost every 3 s poll, so the list of ties flickered. `Counter.topN`
built its slice from a Go map (randomized iteration order) and sorted with the
non-stable `sort.Slice` on the count alone, so ties landed in an arbitrary order
that was re-rolled on each `Snapshot`. "Top Clients" shared the defect. The "All
time" panel was already stable because it reads SQLite.

## What it does

- **`internal/stats/stats.go`** (`topN`): the comparator now falls back to
  `Name` ascending when counts are equal. The name key, not input order, pins the
  order, which is what a randomized map iteration plus a non-stable sort require.
- **`internal/querylog/db.go`** (`TopBlocked`): `ORDER BY cnt DESC, domain ASC`.
  This makes the SQLite path deterministic (a plain `ORDER BY cnt DESC` leaves the
  tie order unspecified) and, more usefully, orders ties by the same rule as the
  in-memory path, so the "Since start" and "All time" tabs agree on equal-count
  order.

No performance cost of note: both are the same `O(n log n)` sort that already ran
(the in-memory slice is bounded at `topNMaxEntries` = 4096; the SQL aggregate was
already sorted), the secondary key is compared only on a primary tie, and neither
runs on the DNS hot path.

## Testing

- `make check` clean; `stats` stays at 100 % coverage.
- `TestCounter_TopDomainsTieOrderStable` seeds six equal-count domains in
  reverse-alphabetical order and asserts the snapshot returns them in name order
  and identical across repeated snapshots (the reshuffle is gone).
- `TestDBLogger_TopBlockedTieOrder` asserts equal-count blocked domains come back
  in domain order from SQLite.
