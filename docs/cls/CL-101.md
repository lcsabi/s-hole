# CL 101: LAN scope and local names

## Description

s-hole now decides more strictly what is "LAN", both for the sources it
answers and for the names and reverse lookups it keeps off the internet:

- More reverse lookups (PTR) get a local NXDOMAIN under `dns.local_ptr`: the
  remaining RFC 6303 zones, the RFC 6598 shared address space
  (`100.64.0.0/10`), and the public IPv6 prefix of the host's own LAN.
- `fritz.box` is a built-in local domain. At startup, s-hole logs an INFO
  line for each search domain of the host that is not a local domain.
- An IPv4 interface subnet counts as LAN only inside the private ranges. A
  public or CGNAT IPv4 subnet on an interface is not admitted, and s-hole logs
  a WARN that names it.
- A failed read of the interface addresses gives a WARN, at most once an
  hour, with a hint about the systemd sandbox.
- A query whose source address s-hole cannot read gets REFUSED (b/100).
- Subnet masking stores nothing for a client value it cannot parse (b/101).

Review findings: PRIV-06, PRIV-07, SEC-15, SEC-16 (b/100), PRIV-11 (b/101),
and the `lan.go` log line of SEC-09. Target release: v2.1.0.

## Motivation

- **PRIV-06.** `dns.local_ptr` covered 10/8, 172.16/12, 192.168/16,
  fc00::/7, and fe80::/10. Reverse lookups for 127/8, 169.254/16, 0/8,
  `100.64.0.0/10` (CGNAT and Tailscale), `255.255.255.255`, `::`, `::1`, and
  the documentation ranges went to the public upstream, and so did reverse
  lookups for the LAN's own public IPv6 prefix. These tell the upstream which
  LAN addresses the devices talk to. An EUI-64 IPv6 address holds the
  device's MAC address, a stable device identifier.
- **PRIV-07.** AVM FRITZ!Box routers use `fritz.box`. Devices add the DHCP
  search domain to short names, so `laptop.fritz.box` and the like went to
  the public upstream. The same is true for any search domain that is not a
  local domain.
- **SEC-15.** The LAN check admitted every subnet of the host's interfaces.
  On a host with a public IPv4 address (a rented server with a /20) or a
  CGNAT address, every neighbor in the provider's subnet counted as LAN: it
  could use s-hole as a resolver and probe the cache.
- **SEC-09 (log line).** `net.InterfaceAddrs` needs `AF_NETLINK`. A systemd
  unit that does not allow it makes the read fail, and s-hole then refused
  clients on a public IPv6 prefix with no log line. The unit hardening itself
  is a separate change.
- **SEC-16 (b/100).** The LAN check ran only for a valid source address. A
  source that s-hole cannot read was answered. No current transport gives
  one, but the rules say that an unknown case fails closed.
- **PRIV-11 (b/101).** `MaskClientIP` in `subnet` mode returned a value it
  could not parse unchanged. The DNS handler passed no zone, but the
  allowlist audit line did: for a link-local IPv6 requester of the admin API
  (`fe80::1%eth0`), with `query_log.mode` recording queries, `clients:
  "subnet"`, and `admin.listen` on an IPv6 address, the line logged the full
  address. The docs sweep of this CL found that path.

## What it does

- **Reverse zones** (`internal/dnsserver/handler.go`): `privateReverseZones`
  is a set, built by `reverseZones`, with the locally served zones of
  RFC 6303 (0/8, 10/8, 127/8, 169.254/16, 172.16/12, 192.168/16, the three
  IPv4 documentation networks, `255.255.255.255`, `::`, `::1`, fc00::/7,
  fe80::/10, 2001:db8::/32) and the 64 zones of `100.64.0.0/10` (RFC 6598).
  `isPrivatePTR` looks up the name and each parent in the set, one map lookup
  per label.
- **Own IPv6 prefix** (`handler.go`, `lan.go`): `ip6Prefix` reads a name
  under `ip6.arpa` as the prefix it names (one nibble per label).
  `Handler.ownPrefixPTR` gives true when that prefix is inside a global IPv6
  subnet of the host's interfaces (`lanACL.ownGlobalV6`, from the same list
  as the LAN check). A name for a shorter prefix (the ISP's /56 above the
  LAN's /64) is not local. A miss reads the interfaces again, at most every
  30 s, as a source miss does, so a renumbered prefix needs no restart. Both
  kinds of local PTR answer are authoritative NXDOMAIN, are counted in
  `shole_local_ptr_total`, and are logged as synthesized, under
  `dns.local_ptr` only.
- **Router domain** (`internal/dnsserver/localnames.go`): `fritz.box.` is in
  `lanOnlySuffixes`. `suffixClass` holds the suffix part of `classify`, and
  `Handler.KeepsLocal` uses it to tell whether a domain is local.
- **Search domains** (`cmd/s-hole/resolvcheck.go`, `main.go`):
  `searchDomains` reads the `search` and `domain` lines of `/etc/resolv.conf`
  and `/run/systemd/resolve/resolv.conf` (lowercase, no trailing dot, each
  once, invalid entries and `.` skipped). `logSearchDomains` logs `a search
  domain of this host is not a local domain` (INFO, `domain`, `hint`) for
  each one that `KeepsLocal` does not cover. It runs once, at startup.
- **IPv4 interface subnets** (`internal/dnsserver/lan.go`, `refresh`): an
  IPv4 interface subnet goes into the LAN list only when it is inside
  `lanRanges` (`inLANRanges`). Every other IPv4 subnet is kept in
  `notAdmitted`, and a subnet that was not in the previous good read gets one
  WARN, `an interface subnet is not treated as LAN`, with `subnet` and a
  `hint`. IPv6 subnets keep the /64 rule.
- **Interface read failure** (`lan.go`, `refresh`): a failed read keeps the
  last good list and logs `interface address read failed` (WARN,
  `err`, `hint` about `AF_NETLINK` and `RestrictAddressFamilies`), at most
  once an hour (`readFailWarnInterval`).
- **Unreadable source** (`handler.go`, `ServeDNS`): a source that `remoteIP`
  cannot read gets REFUSED through `refuse`, so it counts in
  `shole_refused_total` and touches nothing else. The client value for the
  stats and the query log comes from the same checked address, unmapped and
  without a zone. `clientAddr` and its `unknown` value are gone.
- **Masking** (`internal/querylog/logger.go`, `MaskClientIP`): under
  `subnet`, a value that `net.ParseIP` cannot read gives `""`. `StaleRows`
  under `subnet` counts such a stored value as a row that holds more than the
  current setting writes.
- **Docs:** PRIVACY ("What leaves the network", "Who can query s-hole"),
  SECURITY (the LAN-only bullet), README (features, the configuration table,
  local names), `config.yaml` comments for `dns.local_ptr` and
  `dns.local_domains`, DESIGN, TROUBLESHOOTING (the three new log lines, the
  refused-device advice, the `dns.local_ptr` warning text), `CLAUDE.md` (the
  hot path), the `/metrics` help text, the `dns.local_ptr` warning text,
  CHANGELOG, b/100, b/101, and ROADMAP notes on #9 and the CL 94 item.

## Design decisions

- **NXDOMAIN for the own prefix, not an address.** A PTR answer must be a
  name, so `0.0.0.0` cannot be used. NXDOMAIN is the RFC 6303 answer and
  matches the private ranges. Decided with the maintainer: nothing leaves
  s-hole, not even toward the router, and `dns.local_ptr: false` (which
  already warns) sends them upstream as before.
- **Only the subnets of the host's interfaces.** A PTR for another /64 of
  the same ISP block still goes upstream: s-hole cannot know that the block
  belongs to the household, and a name for the /56 above the LAN's /64 is not
  under the LAN's own subnet.
- **No automatic search domains.** Decided with the maintainer: a search
  domain can be a real public domain that the router cannot answer, and its
  names would then get NXDOMAIN. The INFO line names the domain, so the
  operator can decide. A search domain is host configuration, not query
  data, and the line runs once, outside the DNS path.
- **`fritz.box` is built in.** AVM owns `fritz.box`, so no public name is
  under it, and it is a common router domain in Germany and other European
  countries.
- **No setting for public IPv4 LANs.** Decided with the maintainer: a LAN
  that uses public IPv4 addresses is refused, and a code change is needed to
  widen the rule. The WARN names each subnet that is not admitted, so the
  refusal is not silent. It warns once per subnet when the subnet appears,
  not on every refresh. A /32 (such as a Tailscale interface address) also
  gets the WARN: before this change it admitted only the host itself.
- **One hour between read-failure WARNs.** A sandbox that blocks the read
  makes every refresh fail, at most every 30 s. One line an hour keeps the
  cause visible without filling the journal.
- **One parser for the source.** The stored client now comes from the
  address that the LAN check read, so no second parser can see a value the
  check did not see.

## Privacy impact

- **Collects:** nothing new. No new stored field.
- **Sends:** less. Reverse lookups for the added zones and for the LAN's own
  IPv6 prefix, and names under `fritz.box`, no longer go to the public
  upstream (`fritz.box` names still go to a LAN upstream, such as the
  router).
- **Log:** three new lines. Two WARNs from the DNS path name the host's own
  interface subnet or the read error, never a client or a domain. The INFO at
  startup names a search domain from the host's resolver files.
- **Who can query:** fewer sources. Neighbors in a public or CGNAT IPv4
  subnet of the host are refused and leave no trace beyond
  `shole_refused_total`.
- **Masking:** fails closed for a value it cannot parse. The allowlist audit
  line no longer logs the full link-local address of an admin API requester
  under `clients: "subnet"`; it logs no address for that requester.
