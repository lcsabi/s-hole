# CL 86: DNS-over-TLS listener for LAN clients (ROADMAP #36, DoT part)

## Description

s-hole served LAN clients on plain UDP and TCP port 53 only. A client that
wants an encrypted channel to its resolver could not use s-hole. The main case
is Android's default Automatic Private DNS mode: a phone uses DNS over TLS (DoT,
RFC 7858) on the network's DNS server when it answers, without checking the
certificate, so a DoT listener encrypts most phones' LAN DNS with no phone
setup. In strict mode (a provider hostname) the phone uses only DoT and checks
the certificate, so such a phone bypassed s-hole entirely.

This CL adds an opt-in DoT listener (usually `:853`). It dispatches to the same
handler as the plain listeners, so blocking, the cache, stats, the query log,
and the CL 72 privacy mask apply to DoT queries unchanged. The operator
supplies the certificate. A reload re-reads it without a restart, and its
state (healthy, expiring, expired, or a failed reload) shows in the log,
`-check-config`, `/metrics`, `/api/stats`, and the dashboard.

## Motivation

DoT is the one encrypted transport a common client (Android Private DNS)
requires, and nothing else in s-hole could serve it. ROADMAP #36 also listed a
client-facing DoH endpoint. On a LAN it opens no new network path (DoH's usual
advantage, that port 443 is hard to block, does not apply), but it would reach
clients that speak DoH and not DoT, such as Windows desktops and browsers. That
did not justify its surface in the first cut, so it was split out as #39 and
deferred. The
per-transport metric #36 listed was split out as #38.

## What it does

- **Config (`internal/config`).** New `dot_listen`, `tls_cert`, `tls_key`
  (all empty by default; DoT is off) and their `S_HOLE_*` overrides.
  `Validate()` checks, when `dot_listen` is set, that the address is
  `host:port`, that both paths are set, and that `tls.LoadX509KeyPair` accepts
  them, so `-check-config` and the installer dry run catch a bad pair.
- **Listener (`internal/dnsserver/dot.go`, new).**
  - `CertReloader` serves the certificate through `tls.Config.GetCertificate`
    from an atomic pointer. `Reload` swaps it only when the new files load, and
    records the result. `Status` reports the SAN names, the expiry, the last
    reload result, a failure count, and a state (`ok`, `expiring`, `expired`,
    `reload_failed`, most severe first).
  - `ListenDoT` binds the port synchronously and wraps it in a connection
    limiter (256, a constant) and `tls.NewListener` (TLS 1.2 floor).
  - `limitListener` frees a slot exactly once per connection and wakes a
    waiting `Accept` on `Close`, so shutdown cannot hang on a full listener.
- **Server lifecycle (`internal/dnsserver/server.go`).** `EnableDoT` adds a
  third `dns.Server` (`Net: "tcp-tls"`) on the pre-bound listener, served
  through miekg/dns `ActivateAndServe`. `Start` is generalized from two
  listeners to N and still drains every slot. `Shutdown` also closes a DoT
  listener that never started.
- **Wiring (`cmd/s-hole/main.go`).** DoT is bound right after config
  validation, before anything else opens; a failure exits 1. The reload closure
  (`reloadWork`) re-reads the certificate first, then refreshes the blocklists;
  a certificate failure does not skip the refresh. `-check-config` moved into
  `runCheckConfig` and warns on an expired or soon-expiring certificate. The
  banner gains a DoT line. `SetDoTStatus` bridges the status to the api package.
- **Admin API (`internal/api`).** `/api/stats` gains a `dot` object
  (`{"enabled": false}` when off). `/metrics` gains
  `shole_dot_certificate_expiry_timestamp_seconds` and
  `shole_dot_certificate_reload_failures_total` when DoT is on. The dashboard
  header shows a certificate badge, and the header now wraps on a narrow
  screen.
- **Deploy.** The systemd unit gains `ExecReload=/bin/kill -HUP $MAINPID` and
  names port 853 in the capability comment (edited identically in the unit and
  the installer heredoc). The Dockerfile exposes `853/tcp`. The uninstaller
  names every entry in `/etc/s-hole` other than `config.yaml` in its prompt,
  and counts them in its summary, before deleting the directory. `prometheus-alerts.yml` gains two DoT alerts and
  `grafana-dashboard.json` two DoT stat panels. `config.yaml` ships a
  commented DoT block.

## Design decisions

- **DoT only.** The client-facing DoH endpoint is #39 (see Motivation).
- **Operator-supplied certificate; s-hole generates nothing.** The client
  checks the SAN against the name it dialed and needs to trust the issuer.
  Only the operator knows that name and can install trust, and a public CA
  cannot issue for a private name. Auto-generation and a `-gen-cert` helper were
  both weighed and rejected: they would not remove the trust step. The README
  documents an ACME DNS-01 route, `mkcert`, and per-platform commands to make
  clients trust a private CA, and warns that Android may not accept a
  user-installed CA for Private DNS.
- **Android gets the public-domain route, with the reasons stated.** The phone
  must resolve the Private DNS hostname through plain DNS (s-hole cannot answer
  a LAN name until ROADMAP #15), and it must trust the issuer (Private DNS
  probably ignores user-installed CAs). A public name and a publicly trusted
  certificate avoid both unknowns. The README also warns about DNS rebind
  protection on routers, and ROADMAP #15 records how local records would remove
  the public A record but not the trust requirement. The #36 acceptance test
  tries the cheaper mkcert route first.
- **Aimed at Automatic mode; strict mode is optional.** The docs were first
  written around strict mode, which needs a domain and a publicly trusted
  certificate. Automatic mode (the Android default) needs neither, so it reaches
  more phones with no setup, and the README now leads with it. It encrypts
  against passive snooping only, because the certificate is not checked.
- **The openssl self-signed certificate is `CA:FALSE`.** By default
  `openssl req -x509` marks the certificate as a CA (`CA:TRUE`, no key-usage
  limit), and its key is `tls_key` on the s-hole box. Trusted as a root, it
  would let anyone who takes that key sign a certificate for any site: a test
  certificate for `www.bank.test`, signed with the s-hole key, verified `OK`
  against it. Adding `-addext "basicConstraints=critical,CA:FALSE"` removes the
  risk instead of only warning about it. With it, the certificate still
  verifies as itself and s-hole serves it (`dig +tls` returned `0.0.0.0`), but
  the forged `www.bank.test` certificate fails with "invalid CA certificate".
  The README and the CONTRIBUTING smoke test use the `CA:FALSE` command.
- **One server certificate.** s-hole serves one certificate. The README uses
  openssl by default and mkcert when desktop DoT clients also need to check the
  certificate; phones in Automatic mode accept either.
- **Reload in the same CL.** ACME certificates are valid for 90 days or less, so
  a restart-to-renew design would be a recurring chore. The existing
  single-flight reload path already has four triggers (timer, API, SIGHUP, and
  now `systemctl reload`), so reload needed no new endpoint. A failed load keeps
  the current certificate.
- **Fatal bind and certificate errors.** The admin UI fails open because it is
  not the DNS service. An enabled DoT listener that silently did not start
  would cut off the clients that need it.
- **Fixed limits, no knobs.** The 256-connection cap, and miekg's 2 s read
  timeout (which also bounds the TLS handshake inside the first read), 8 s idle
  timeout, and 128 queries per connection.
- **Status computed in one place.** The 14-day window and the state precedence
  live in dnsserver; the api package receives a finished `DoTStatus` through a
  setter, so it does not import dnsserver. `expires_in_days` is computed on the
  server, so the browser clock does not matter.
- **Not done here:** "are clients using DoT?" needs the per-transport counter
  (#38). A "Restart s-hole" dashboard button was proposed and rejected (recorded
  under ROADMAP "Deliberately not planned").

## Testing

- `make check` clean; `-race` clean on the touched packages, with the DoT
  tests repeated to catch timing flakes.
- Coverage: `config` 100%, `dnsserver` 92.8%, `api` 91.5%.
- New tests: a real DoT query through the shared handler with the client
  address recorded; an untrusted client failing the handshake; reload serving a
  new certificate to new connections; a failed reload keeping the current one;
  concurrent reloads during handshakes; status and state precedence; the
  limiter (cap, release once, `Close` waking `Accept`); shutdown before start
  releasing the port; the N-way drain; the `dot` object and metrics; the reload
  closure; `-check-config` warning on an expired certificate; the banner line.
- Manual, on this machine: an `openssl` certificate, `dig +tls` (blocked
  answer `0.0.0.0`, allowed answer forwarded, wrong hostname rejected); SIGHUP
  swapping the served serial; a garbage file plus `POST /api/reload` keeping
  the old serial with a WARN and `reload_failed`; a busy port and a garbage
  certificate each exiting 1 at startup; the dashboard badge rendered in
  headless Chrome in the ok, expiring, and reload-failed states and at phone
  width; `promtool check rules` on the alerts; the uninstaller's file listing
  run against a temporary directory.
- **Not tested: desktop DoT clients.** The README's desktop table
  (`systemd-resolved` opportunistic and strict, stubby, macOS profiles, the
  Windows and browser limits) comes from each client's documentation. ROADMAP
  #36 lists a Debian VM check for `systemd-resolved`.
- **Not tested: a real Android device.** No Android phone in Private DNS mode
  was used, although it is the motivating case. The Android guidance in the
  README (that Automatic mode upgrades to DoT without checking the certificate;
  for strict mode, a publicly trusted certificate, the public A record, the
  off-LAN warning, and whether Android accepts a user-installed CA) comes from
  Android's documented behavior, not a test run. The README marks the Android
  steps as untested, and ROADMAP #36 keeps the acceptance test open.
