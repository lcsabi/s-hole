# CL 72: query-log privacy modes (write-time client anonymization)

## Description

Add a `query_privacy` config setting that controls how the client IP is stored in
the query log and shown in the dashboard. The modes are `raw` (store the address
as-is, the default and current behavior), `drop` (store no client), and `subnet`
(mask the host bits to IPv4 /24 or IPv6 /64). The client is masked once at a single
write-time choke point in the DNS handler, so the text log, the SQLite log, and the
in-memory Top Clients panel all see the same value. Implements ROADMAP #21.

## Motivation

The query log stored the raw client IP for every request, with no way to keep the
block and domain analysis while dropping per-device history. This CL adds the
privacy control and is the foundation for ROADMAP #22, #23, and #24, each a
read-time consumer of the stored row that must never reach behind the mask.

## What it does

- **Config (`internal/config/config.go`)**: a new `QueryPrivacy` field
  (`query_privacy`), defaulted to `raw`, overridable with `S_HOLE_QUERY_PRIVACY`,
  and validated in `Validate` the same way `block_mode` and `log_queries` are. A
  bad value fails startup and `-check-config`, not silently at the first query.
- **Masking choke point (`internal/dnsserver/handler.go`)**: a pure
  `maskClientIP(ip, mode)` helper applies the transform, and `ServeDNS` calls it
  once on the value from `clientAddr(w)`, before the `stats.Counter` and query-log
  calls. `raw` returns the address unchanged, `drop` returns the empty string, and
  `subnet` zeroes the host bits with `net.CIDRMask` (24/32 for IPv4, 64/128 for
  IPv6). A value `net.ParseIP` cannot read (the `"unknown"` sentinel, or any
  non-IP) passes through unchanged under `subnet`, so masking never invents an
  address.
- **API echo (`internal/api/api.go`)**: `/api/stats` carries a `query_privacy`
  string on the `statsResponse` wrapper (set from the config value through
  `SetQueryPrivacy`, the way `blocklist_size` and `sources` ride along), so a
  reader knows the active mode. It is display metadata only; the client is already
  masked in the handler, so the API never holds an unmasked address.
- **Dashboard (`internal/api/static/index.html`)**: the Top Clients panel
  describes itself from the mode, the way CL 70 made the graph adapt to
  `log_queries`. Under `drop` it shows a "clients not recorded" state instead of
  blank rows; under `subnet` it keeps the list and notes the entries are
  subnet-masked; under `raw` it is unchanged. The panel reads the existing
  `/api/stats` call, so no new fetch is added.

## Design decisions

- **Three explicit modes, not `full`/`anonymize` with a hidden prefix.** Each value
  names the transform applied to the client IP, so none of them makes an invertible
  privacy claim. The roadmap's `full` would read as "full privacy" under a
  `query_privacy` key while meaning the opposite (no masking). `drop` and `subnet`
  are peers, and the flat-LAN caveat (a `/24` truncation on a single-`/24` LAN
  collapses every client to one address) is documentation on `subnet` rather than
  a silent behavior flip.
- **Mask everywhere, at one choke point in the handler, not a logger decorator.**
  The roadmap proposed a `privacyLogger` wrapping `Multi`, but the stats counter
  (`Counter.RecordQuery`) receives the client IP directly from the handler, not
  through the `Logger` interface, so a logger-only decorator would leave the live
  Top Clients panel showing raw IPs. Masking once in `ServeDNS`, before both the
  counter and the logger calls, is a stricter single point and keeps the promise
  everywhere the mode is on. It needs no new logger type.
- **Fixed per-family prefixes (/24, /64), no knob yet.** These cover the common
  segmented-network case. A configurable prefix can be added later without a
  breaking change.
- **No `hash` mode.** A home LAN has a small candidate-IP space (a `/24` is 254
  addresses), so a salted hash is a trivially reversible preimage and would be a
  de-anonymization oracle on the unauthenticated LAN API. Hashing gives false
  privacy and is rejected here, not deferred.
- **Forward-only.** Rows written at `raw` keep their addresses. There is no silent
  bulk `UPDATE` of operator data; a one-shot scrub can be a later CL. A mixed-level
  DB shows both, which is expected.
- **`SetQueryPrivacy` setter, not a `New` parameter.** The `api.Server`
  construction already uses a setter for `EnablePprof`, and a new `New` parameter
  would churn every test caller. An unset value reads as `raw` on the payload.

## Testing

- `make check` clean; `-race` clean on the dnsserver package.
- `TestMaskClientIP` covers every mode against IPv4, IPv6, the `"unknown"`
  sentinel, a non-IP string, and an unrecognized/empty mode (both behave as `raw`).
- `TestServeDNS_MasksClientEverywhere` drives a blocked query through `ServeDNS`
  under `raw`/`drop`/`subnet` and asserts both the query-log sink and the stats
  counter's Top Clients see the masked value. It proves the mask reaches the stats
  counter, which a logger-only decorator would have missed.
- `TestStatsEndpoint_EchoesQueryPrivacy` asserts the payload defaults to `raw` and
  reflects `SetQueryPrivacy`.
- Config tests pin the default, the env override, the accept set, and rejection at
  both `Validate` and the `LoadAndValidate` stage.
- Manual smoke: ran each mode with `S_HOLE_QUERY_PRIVACY=<mode>` and confirmed the
  stored client (text log, SQLite `client_ip`, Top Clients) is raw, empty, or
  subnet-masked as expected, that the dashboard panel shows the matching state, and
  that a bogus value fails `-check-config`.
