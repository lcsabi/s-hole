# CL 83: Graduate the CHANGELOG to v1.0.0

## Description

Graduate the CHANGELOG's `[Unreleased]` section to `[1.0.0] - 2026-09-18` and add
a fresh empty `[Unreleased]` above it. This is the bookkeeping step that a
`v1.0.0` tag push needs: `.github/workflows/release.yml` draws the GitHub Release
notes from the matching `[1.0.0]` CHANGELOG section, so that section must exist at
the tagged commit. No workflow or Go code changes.

## Motivation

`v0.2.1` shipped on 2026-09-03. Since then the `[Unreleased]` section has
collected the operator-visible work from CL 70-82: the query-volume-over-time
graph and collapsible panels, query-log privacy modes, client name attribution,
query-log search/filter, the cache-hit and failed-query lines on the graph, Go
runtime gauges on `/metrics`, the Prometheus/Grafana examples, query-log export,
upstream validation at config time, the equal-count top-N ordering fix, and the
`outcome=` filter round-trip fix. These are shippable but have never carried a
version tag.

The project is now going to a live deployment (a Raspberry Pi 5). The config
surface, the REST API, the metrics names, and the on-disk query-log schema have
been stable across the 0.2.x line, and the roadmap features that shaped the
dashboard and the API (ROADMAP #20-24 and #26-31) have landed. Declaring `v1.0.0` marks
that first stable, deployable release rather than continuing the pre-1.0 0.x
line. The jump from `0.2.1` to `1.0.0` (rather than `0.3.0`) is the maintainer's
call: it is a stability declaration, not a signal of breaking changes.

## What it does

- Rename `## [Unreleased]` to `## [1.0.0] - 2026-09-18`, then insert a fresh empty
  `## [Unreleased]` above it.
- Bump the three illustrative version strings in `README.md` (the release tarball
  name, the `ghcr.io` pull comment, and the `-version` output example) from
  `0.2.1` to `1.0.0`, so the docs show the current release.

The graduated `[1.0.0]` section carries exactly the bullets already written under
`[Unreleased]`: two Fixed, ten Added, and two Changed (CL 70-82). The
internal-perf and doc-only CLs since `v0.2.1` have no operator-visible behavior,
so they carry no release-notes bullet.

## Design decisions

- **Graduation is its own CL, merged before the tag.** CONTRIBUTING's "Cutting a
  release" requires the tag to point at a commit whose CHANGELOG already carries
  the release section, or the `awk` notes extractor falls back to a placeholder.
  This CL lands that section first.
- **Bookkeeping CL, no CHANGELOG bullet of its own.** The graduation changes no
  runtime behavior, so it adds no entry to the new `[Unreleased]` section. The
  README example bump is documentation-only for the same reason.
- **No prose milestone note in the section.** The other release sections list
  bullets under `### Added/Changed/Fixed` with no prose intro. The `[1.0.0]`
  section keeps that shape so the format stays uniform and the release-notes
  extractor keeps working; the milestone rationale lives here in the CL.
- **The roadmap record is deferred to a post-tag commit.** The release-history row
  records each release with its real tagged commit and confirmed date. That commit
  lands after the `v1.0.0` tag is out, not here, so it can name the actual commit
  hash.

## Files changed

- `docs/CHANGELOG.md`: graduate `[Unreleased]` to `[1.0.0] - 2026-09-18`, add a
  fresh empty `[Unreleased]`.
- `README.md`: bump the three `0.2.1` example strings to `1.0.0`.
- `docs/CL.md`: index row for CL 83.

No Go code changed. `internal/version` already consumes the ldflags, so a build
tagged `v1.0.0` reports the tag with no source change.

## Testing

- `make check` (fmt + vet + lint + test) stays green; no Go code changed.
- Ran the release-notes `awk` extractor from `release.yml` against the graduated
  `docs/CHANGELOG.md` with `version=1.0.0`; it returns exactly the `[1.0.0]` body
  and nothing from `[0.2.1]`.
- End-to-end validation is a maintainer step: push `v1.0.0-rc1`, confirm the four
  archives plus `SHA256SUMS` land on a `--prerelease` Release, that
  `sha256sum -c SHA256SUMS` passes, that a downloaded binary reports
  `s-hole v1.0.0-rc1`, and that `docker pull ghcr.io/lcsabi/s-hole:1.0.0-rc1`
  runs and reports the same version without moving `:latest`. Then delete the rc
  and cut `v1.0.0`.
