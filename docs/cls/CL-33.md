# CL 33 — Wire up TopBlocked: all-time top-blocked endpoint + dashboard toggle

## Description

`DBLogger.TopBlocked` — exported, context-aware, and unit-tested since CL 2
but never called by any handler — is now wired to the dashboard:

- New `GET /api/top-blocked?limit=N` endpoint returns the all-time
  most-blocked domains from the SQLite query log, ordered most-blocked-first
  (`?limit=N`, default 50, capped at 1000 via the existing `parseLimit`).
  When query logging is disabled (`s.db == nil`) it returns an empty list and
  200, matching the `/api/queries` degradation contract.
- The dashboard's "Top Blocked Domains" panel gains a **"Since start / All
  time"** segmented toggle. "Since start" (default) renders the in-memory
  `top_domains` tally already in `/api/stats`; "All time" polls
  `/api/top-blocked`.

Roadmap item #4.

## Motivation

The roadmap called this out as the worst of three states: `TopBlocked` was
dead exported code (the same smell S1 flagged on `version.Short`), while the
only top-blocked view the dashboard offered came from the in-memory
`stats.Counter`, which **resets on every restart** and **prunes at
`topNMaxEntries` (4096)**. The persistent SQLite tally already existed and was
tested — it just had no caller. Wiring it up turns "since start" and "all
time" into a user-facing choice instead of leaving a tested query method
unreachable. Deleting the method was the alternative; wiring it up delivers a
genuine observability win (an operator can see the domains a network has
blocked most over its whole history, not just since the last restart), so it
won over deletion.

## Design decisions

**Two tallies, not one migrated source.** The in-memory counter and the
SQLite tally answer different questions — "since this process started" vs
"across all recorded history" — and have different cost/availability
profiles (the counter is always present and free; the DB tally needs
`query_db` and a round-trip). Rather than replace one with the other, the UI
exposes both behind a toggle and defaults to "Since start" so behaviour is
unchanged for the common `query_db`-off deployment (where "All time" is
simply empty).

**Handler owns the query, no stats plumbing.** Like CL 28 (blocklist size)
and CL 25, the lighter touch is the API handler, which already holds the
`*querylog.DBLogger`. No change to `stats.Snapshot`, no new field threaded
through the counter.

**Reuse `parseLimit`.** The clamp/default logic that guards `/api/queries`
against a `?limit=10000000` history dump applies verbatim; top-blocked gets
the same 50/1000 default/cap for free and one limit parser stays canonical.

**db-disabled returns `[]`, not an error.** Same contract as `/api/queries`:
the panel shows an empty state ("ensure query_db is set") instead of a failed
fetch, so the toggle is safe to expose even when logging is off.

**Independent fetch for the all-time list.** The UI fetches `/api/top-blocked`
separately from the `/api/stats` poll (function `refreshTopDomainsAllTime`) so
the toggle redraws instantly on click and each 3 s tick refreshes whichever
source is active — the stats poll is not blocked on the extra request when the
panel is in "Since start" mode.
