# CL 45: audit-log whitelist mutations and reload trigger source

## Description

Log state-changing admin actions in the application log. A whitelist add or
remove now emits an `Info` line with the domain and the requester address, and
each blocklist reload logs its trigger source so a `POST /api/reload` is
distinguishable from the periodic timer and a SIGHUP.

## Motivation

The admin API is unauthenticated by design (LAN-trust). A whitelist add un-blocks
a domain for the whole network, which is a security-relevant state change, yet it
left no trace anywhere: not in the application log, not in the query log (that is
per-DNS-query only), and not on disk (the runtime whitelist is in-memory only,
roadmap #13). A reload did produce log output, but the same `blocklist updated`
line fired for the 24h timer, a SIGHUP, and the API alike, so the trigger was not
recoverable from the log.

This was not a defect with a wrong behavior; it was a gap. The rest of the app
already logs successful state changes at `Info` (`blocklist.Update` logs
`loaded` and `blocklist updated`; `config.Load` logs dropped whitelist entries at
`WARN`). The whitelist API mutations were the outlier that logged nothing, so
closing the gap makes the logging consistent rather than introducing a new
philosophy.

## What it does

- `handleWhitelistAdd` and `handleWhitelistRemove` log `whitelist entry added` /
  `whitelist entry removed` at `Info` with the `domain` and the `client` address.
- `handleReload` logs `blocklist reload requested via API` with the `client`
  address before it dispatches. The periodic timer logs `blocklist reload
  requested via timer` at its call site in `main.go`. SIGHUP already logged
  `reload signal received` with the signal name, so its source was never
  ambiguous and stays unchanged.
- A small `clientIP` helper drops the ephemeral source port from `RemoteAddr` and
  falls back to the raw value if the address carries no port.

Deliberately kept out of scope: no UI audit panel (a documented non-goal), no
separate audit store, and no query-DB rows. slog to stdout (journald under
systemd) is the audit surface, consistent with the rest of the app. These lines
are low-volume admin actions, not per-query, so the query-log privacy work
(roadmap #21) does not gate them; anonymizing the client here later is a trivial
follow-up.

## Files changed

- `internal/api/api.go`: `Info` audit lines in the whitelist add/remove and
  reload handlers; new `clientIP` helper; `net` import; `handleReload` now names
  its request parameter.
- `cmd/s-hole/main.go`: the refresh ticker logs `blocklist reload requested via
  timer` before calling the reload closure.
- `internal/api/api_test.go`: a race-safe recording `slog.Handler` and tests
  asserting the add, remove, and reload-source audit lines, plus a `clientIP`
  unit test covering both branches.
- `docs/DESIGN.md`: admin-interface note on audit logging; refreshed coverage
  numbers.
- `README.md`, `docs/CHANGELOG.md`, `docs/CL.md`: doc sync.
