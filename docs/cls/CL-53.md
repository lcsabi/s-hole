# CL 53: add contention benchmarks and enable mutex/block profiling

## Description

Close the concurrency blind spot in the benchmark set. The existing benchmarks
all run on one goroutine, but the real hot path is one goroutine per query
(miekg/dns spawns them), so lock contention is invisible to them. Add
`b.RunParallel` variants of the three read paths, benchmarks for the reload swap
and the two cache-maintenance paths, and a query-log flush-throughput benchmark.
Then wire mutex and block profiling to the `enable_pprof` flag so an operator can
actually see the contention these benchmarks guard against.

## Motivation

The concurrency invariants that CLAUDE.md pins (the `RWMutex` swaps in `Store`
and `Cache`, the `stats.Counter` load order) are covered for *correctness* by
`-race` tests, but nothing measures *throughput* under contention. A change that
turns an `RLock` into an exclusive `Lock`, or moves real work under a mutex,
passes every serial benchmark and every race test while silently serializing the
hot path. The `_Parallel` benchmarks make that regression measurable.

The profiling half is the production counterpart. The `/debug/pprof/mutex` and
`/debug/pprof/block` endpoints were already registered (they dispatch off
`pprof.Index`), but they returned nothing: the Go runtime leaves mutex and block
profiling off until a rate is set, and the code never set one. For a
contention-sensitive DNS server this was the one diagnostic missing exactly when
it is needed, during a live latency incident. Enabling it alongside `enable_pprof`
keeps it opt-in and localhost-scoped, matching the existing pprof posture.

## What it does

Benchmarks (all test-only, so coverage is unchanged):

- `BenchmarkStore_IsBlocked_Parallel`, `BenchmarkCache_Get_Parallel`, and
  `BenchmarkHandler_ServeDNS_Parallel` run the read paths under `b.RunParallel`.
  The handler variant gives each goroutine its own `fakeWriter` (it records the
  reply) and shares the read-only request.
- `BenchmarkStore_Replace` measures the reload swap: build a fresh blocked set
  from a slice, then swap the map pointer under the write lock. This runs on
  every refresh inside the single-flight lock.
- `BenchmarkCache_Set_DropOnFull` measures the copy-then-drop cost a full cache
  pays on every miss, the branch `BenchmarkCache_Set` deliberately avoids.
- `BenchmarkCache_CleanupExpired` measures the once-a-minute sweep, an O(n) pass
  held under the write lock.
- `BenchmarkDBLogger_Flush` measures the batch commit, the single-connection
  drain budget (b/038) that bounds how fast the async writer clears its channel
  before `Log` starts dropping. `BenchmarkDBLogger_Log_Parallel` confirms the
  enqueue stays non-blocking under concurrent callers (23 ns/op on the dev box,
  even as the channel saturates and the drop branch runs).

Profiling (user-visible):

- `registerPprof` now calls `runtime.SetMutexProfileFraction(5)` and
  `runtime.SetBlockProfileRate(10_000)` (one sample per ~10 microseconds
  blocked). Both sample rather than record every event, to bound the hot-path
  cost while still surfacing a real regression. They are gated behind the same
  `enable_pprof` flag as the handlers, so the cost is paid only when an operator
  asks for profiling. The startup log line notes both are on.

## Files changed

- `internal/api/pprof.go`: enable mutex/block profiling with sampled rates.
- `internal/api/api.go`: note mutex/block profiling in the pprof startup log.
- `internal/api/pprof_test.go`: `TestPprof_MutexBlockProfilingEnabled` asserts
  the fraction is set and both endpoints serve.
- `internal/blocklist/store_test.go`: `_Parallel` and `Store_Replace` benchmarks.
- `internal/cache/cache_test.go`: `_Parallel`, `Set_DropOnFull`, and
  `CleanupExpired` benchmarks.
- `internal/dnsserver/handler_test.go`: `ServeDNS_Parallel` benchmark.
- `internal/querylog/db_test.go`: `Flush` and `Log_Parallel` benchmarks.
- `docs/DESIGN.md`: describe the new benchmarks; note mutex/block profiling in
  the API and security sections.
- `CONTRIBUTING.md`: add the mutex/block pprof commands and a note.
- `docs/CHANGELOG.md`: the `enable_pprof` behavior change.

## Testing

- `make check` clean.
- Ran each new benchmark: `go test -run=x -bench=. ./internal/...`.
- `go test -race -count=1 ./...` clean (the `_Parallel` benchmarks also run
  clean under `-race` via `-bench`).
- The pprof test confirms the mutex fraction is set and `/debug/pprof/mutex` and
  `/debug/pprof/block` return 200 when `enable_pprof` is on.
