# CL 43: v0.1.0 release workflow and CHANGELOG graduation

## Description

Add `.github/workflows/release.yml`, a tag-triggered release pipeline, and
graduate the CHANGELOG's `[Unreleased]` section to `[0.1.0]`. Pushing a `v*` tag
now builds the four supported targets, attaches per-target archives and a
`SHA256SUMS` file to a GitHub Release, and pushes a multi-arch container image to
`ghcr.io/lcsabi/s-hole`. Roadmap #2.

## Motivation

Before this CL there was no way to get a built s-hole without a Go toolchain: CI
cross-compiled all four targets only to throw the binaries away. `s-hole
-version` reported `dev` because no tag existed. This CL closes both gaps and
turns the CHANGELOG's running `[Unreleased]` section into the first shippable
version, so bug reports can name a real build.

## What it does

`release.yml` triggers on `push: tags: ["v*"]` with `contents: write` (create
the Release) and `packages: write` (push to ghcr). Three jobs:

- **build** (matrix: linux/amd64, linux/arm64, linux/armv7, windows/amd64,
  `CGO_ENABLED=0`). The version is the tag name (`github.ref_name`), injected
  with the same `-ldflags -X` triple the Makefile and CI use, so the tag name is
  authoritative on a tag push (no `git describe`). Each target is packaged into a
  staging dir (binary, `config.yaml`, `LICENSE`, `README.md`, plus the Linux
  `deploy/` scripts and unit for the Linux targets) and archived: `tar.gz` for
  Linux, `zip` for Windows.
- **release** downloads every archive, writes `SHA256SUMS`, extracts the
  `[0.1.0]` section from `docs/CHANGELOG.md` as the release body (an `awk` slice
  between the version heading and the next `## [`), and creates the Release with
  the preinstalled `gh` CLI. A tag with a `-` suffix (e.g. `v0.1.0-rc1`) is
  marked `--prerelease`.
- **docker** builds a multi-arch (amd64 + arm64) image via buildx and pushes it
  to `ghcr.io/<repo>`, tagged with the version. `:latest` moves only for final
  (non-pre-release) tags. The existing `Dockerfile` already accepts the
  `VERSION`/`COMMIT`/`BUILD_DATE` build-args.

The CHANGELOG's `[Unreleased]` body (everything accumulated since the initial
implementation) is renamed to `[0.1.0] - 2026-08-24`, a fresh empty
`[Unreleased]` is added above it, and a bullet describing the release channels is
recorded under 0.1.0.

## Design decisions

- **`gh release create`, not a third-party release action.** The `gh` CLI ships
  on the runner, so no new action dependency is needed for the Release step. This
  matches the project's dependency-minimalism. The Docker path does pull in the
  `docker/*` actions, which are the standard multi-arch buildx toolchain and have
  no lighter first-party equivalent.
- **Pre-release safety.** An rc tag is published as a GitHub pre-release and does
  not move the `:latest` image, so a release can be validated end to end (push
  `v0.1.0-rc1`, check the archives, checksums, and image) before the final
  `v0.1.0` becomes the default download and pull.
- **Archives, not raw binaries.** Each archive bundles the config sample, the
  license, and the deploy helpers, so an operator gets a runnable set from one
  download instead of fetching the config and scripts from the repo separately.

## Files changed

- `.github/workflows/release.yml` (new): the release pipeline.
- `docs/CHANGELOG.md`: graduate `[Unreleased]` to `[0.1.0] - 2026-08-24`, add a
  fresh empty `[Unreleased]`, record the release-channels bullet.
- `README.md`: new "Install a pre-built release" subsection and a `ghcr.io`

- `docs/ROADMAP.md`: flip item #2 to `done (CL 43)` and rewrite the section.

No Go code changed. `internal/version` already consumes the ldflags, so a
released build reports the tag instead of `dev` with no source change.

## Testing

- `make check` (fmt + vet + lint + test) stays green; no Go code changed.
- The release-notes `awk` extractor was run against the graduated
  `docs/CHANGELOG.md` and returns exactly the `[0.1.0]` body.
- End-to-end validation is a maintainer step: push `v0.1.0-rc1`, confirm the
  four archives + `SHA256SUMS` land on a `--prerelease` Release, that
  `sha256sum -c SHA256SUMS` passes, that a downloaded binary reports
  `s-hole v0.1.0-rc1`, and that `docker pull ghcr.io/lcsabi/s-hole:0.1.0-rc1`
  runs and reports the same version without moving `:latest`. Then delete the rc
  and cut `v0.1.0`.
