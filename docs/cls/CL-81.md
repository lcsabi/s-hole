# CL 81: query-log export (CSV / JSON)

## Description

Add `GET /api/queries/export`, a streamed bulk export of the SQLite query log in
CSV (default) or JSON. It reuses the CL 74 filter parameters, so a filtered
export is the filtered query in bulk. The Recent Queries panel gains Export CSV
and Export JSON links that download the current filter. Implements ROADMAP #24.

## Motivation

An operator who wants to analyze query history in another tool had no bulk path
out. The recent-query view is capped at 1000 rows for the in-memory JSON marshal,
and the flat `log_file` is a local, unstructured, unfiltered text stream that
needs shell access and is often not enabled alongside `query_db`. The export is
the remote, structured, filtered, tool-ready path.

This item also validates the CL 72 privacy placement. Because the client is
masked once at write time, a bulk dump of the table cannot leak more than
`/api/queries` already does. If masking were done at read time instead, an export
of the raw rows would silently undo the privacy setting.

## What it does

- **querylog (`internal/querylog/db.go`)**: the `WHERE`-building block is
  extracted from `Search` into a shared `QueryFilter.where()` helper, so `Search`
  and the new streaming `Export` cannot drift (the same "one query builder" rule
  CL 74 set for `Recent`/`Search`). `Export(ctx, f, n, yield)` runs the same
  filter with no `LIMIT` by default (`n > 0` bounds it to the newest `n`) and
  calls `yield` once per row as it scans, so a large export holds flat memory. A
  `yield` error stops the stream and returns to the caller, which the handler uses
  to abort on a write failure.
- **API (`internal/api/api.go`)**: `handleQueriesExport` selects the format
  (`?format=csv` default, `json`; anything else is a 400), reuses
  `parseQueryFilter`, and reads an optional `?limit=`. It sets a
  `Content-Disposition` attachment filename (with the privacy mode and a UTC
  timestamp), an `X-Shole-Query-Privacy` header, and an `X-Shole-Query-Logging`
  header. `exportCSV` writes a fixed column header then one row per query;
  `exportJSON` streams an envelope (`query_privacy`, `exported_at`, `logging`, the
  echoed `filter`, then the `queries` array). Both attach the CL 73 client label
  from the masked client value. When `query_db` is unset the export is a valid
  empty file (a header-only CSV or an empty `queries` array), the same
  degrade-not-fail contract as `/api/queries`.
- **Dashboard (`internal/api/static/index.html`)**: the Recent Queries header
  gains Export CSV and Export JSON links whose href tracks the active filter (the
  same params as the table, without the row cap). They grey out when the query log
  reports its mode is `off` or `none`, so an empty download is not offered. The
  mode is read from the existing `/api/history` `logging` field; until the first
  history response the links stay enabled rather than falsely greying.

## Security and robustness

- **CSV formula injection.** The queried domain is client-influenced and can start
  with a spreadsheet formula trigger (`= + - @`, tab, or CR). `csvSanitize`
  prefixes such a field with a single quote so a spreadsheet treats it as text.
- **Write-deadline interaction.** The admin server sets a 30s `WriteTimeout` as a
  slowloris guard. A legitimately long export would be truncated at 30s. The
  handler rolls the write deadline forward after each row through
  `http.ResponseController`, so a healthy stream of any length completes while a
  stalled client still trips the deadline on its next blocking write.
- **Concurrency guard.** Each export holds the single query-log connection
  (b/038) for its whole scan, so unbounded parallel exports on the unauthenticated
  LAN port could starve the async writer. A buffered-channel semaphore
  (`maxConcurrentExports = 2`) bounds in-flight exports; an excess request gets
  `429` with `Retry-After` rather than queueing. It does not throttle the cheap
  JSON endpoints the dashboard polls.
- **Privacy-mode exposure is not new.** The mode is already public on
  `/api/stats` and in the dashboard header, and it is a policy label, not a
  secret. The header and filename repeat what any caller can read.

## Design decisions

- **CSV stamp in the header, not a comment line.** The CSV body stays strictly
  parseable (no leading `#` row that Excel would read as data). The active privacy
  mode rides on the `X-Shole-Query-Privacy` response header and in the download
  filename. An operator can also read the masking from the values (`subnet`
  network addresses, empty under `drop`). JSON has a natural home for the stamp,
  so its envelope carries `query_privacy` as a field.
- **Uncapped by default.** Unlike `/api/queries` (capped at 1000 for the
  in-memory marshal), the export streams, so it returns the whole filtered log.
  The table is bounded in practice by `query_db_retention_days`. `?limit=N` is
  optional for "export the last N".
- **Single-connection hold, documented not redesigned.** A large export briefly
  blocks the async writer and prune while it holds the one connection (b/038). At
  home scale over the retention window this is immaterial, and a sustained drop
  shows in `shole_query_log_dropped_total`. The concurrency guard bounds the
  worst case. A multi-connection pool is not reintroduced.
- **Mid-stream error leaves a truncated file.** Headers are already sent once the
  stream starts, so a scan error is logged and leaves a short CSV or an
  unterminated JSON document (no closing `]}`), which is a detectable signal
  rather than a silent short read.
- **General API rate limiting is out of scope.** The export-only concurrency guard
  covers the one endpoint whose cost is unbounded. A broad limiter across every
  route is a separate, wider decision, filed as ROADMAP #34. It is not auth, which
  stays a settled non-goal.
