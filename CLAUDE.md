# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

s-hole is a single-binary DNS sinkhole (lightweight Pi-hole alternative) in Go: it answers LAN DNS queries, returns `0.0.0.0`/`::` (or NXDOMAIN) for blocklisted domains, forwards the rest upstream (DoH by default), and serves an embedded admin UI + REST API. Design identity: **private by default** and **auditable in an afternoon**: one binary, one YAML config, a tiny dependency graph (`miekg/dns`, `yaml.v3`, pure-Go SQLite, `x/sys` for the Windows service SCM, Event Log, and folder access list; `go.uber.org/goleak` is test-only, not linked into the binary). Don't add dependencies without strong justification.

## Privacy first (the first design rule)

s-hole sees every DNS query on the LAN, so it can hold the browsing history of every person in the household, with times that show when each one is home and awake. Privacy is the first design rule. When privacy conflicts with another goal (convenience, a richer dashboard, easier debugging), privacy wins unless the maintainer decides otherwise. **If a change makes s-hole collect, keep, show, or send more personal data, stop and ask the maintainer first.** `PRIVACY.md` is the user-facing inventory of every place s-hole keeps or sends data.

Personal data here: a client address and anything derived from it (a subnet, a `client_names` label), a queried name, a timestamp linked to either, the counts over time that show activity, and the EDNS options a client sends (Client Subnet, COOKIE).

Rules (review enforces them, and tests pin them):

- **Every default and every fallback is the most private option.** The defaults record nothing (`query_log.mode: "none"`, `clients: "drop"`, `database` and `file` off, retention 7 days, DoH upstreams). A config mistake falls back to the default, so it can never make s-hole less private; an unknown mode fails closed (`MaskClientIP` drops the client). A less private default needs the maintainer's agreement.
- **Every setting that is less private or less secure than its default warns, loudly, without an off switch.** `config.Warnings` lists them; `-check-config` and startup log each, and `privacyReport` repeats all of them with every stats line and on the dashboard. A new setting that can record more joins `config.Warnings` in the same change.
- **Mask the client in one place.** `ServeDNS` masks the client once with `querylog.MaskClientIP`. No other code reads `w.RemoteAddr()` to store, show, or log it. The Top Clients and Top Domains tallies get a client or domain only when `query_log.mode` records the query.
- **The application log carries no more than the query log.** A slog record from the DNS path names a domain only under `query_log.mode: "all"` and never names a client. Do not log a raw `net.OpError` from a client connection (its text holds the client address; use `writeErr`). Summarize per-query failures (`RunFailureReport`) instead of one line per query. The allowlist audit line is the one exception.
- **Keep query data where s-hole controls it.** Retention and purge must reach every place s-hole stores query data. If s-hole cannot delete data in a place (journald, Docker logs, Prometheus, backups), it does not write query data there by default, and the docs say that s-hole cannot delete it when the operator opts in.
- **Stored data is owner-only and deletable.** Files are created `0600` (umask `077`, `UMask=0077`), directories `0700`; on Windows the config folder gets an owner-only access list. The query database keeps `secure_delete=ON` and a TRUNCATE checkpoint after deletes, so a deleted row leaves the file. New stored data follows retention and is reached by `s-hole -purge` and `uninstall-linux.sh --purge`.
- **Never rewrite the operator's history on your own.** A stricter setting applies to new rows; `StaleRows` reports the older ones and the operator decides (purge or wait for retention).
- **LAN only, and LAN data stays on the LAN.** The DNS server answers LAN sources only (`lan.go`), with no setting to widen it. Do not forward names or options that only mean something on the LAN or identify a device: private PTR is answered locally, the upstream gets a fresh query with no client EDNS option or query ID (`edns.go`), and local-only names go to LAN upstreams only (`localnames.go`, CL 94).
- **No other outbound connections.** s-hole connects only to the configured upstreams and blocklist URLs (and the hosts a list URL redirects to; an HTTPS list never goes to a non-HTTPS URL, b/097), with `User-Agent: s-hole`. No telemetry, update check, crash report, or analytics; the dashboard loads nothing from a third party. A new outbound connection needs a ROADMAP decision first.
- **Keep metrics aggregate.** No per-client or per-domain label on `/metrics`. A URL that s-hole shows anywhere goes through `redact.URL`.
- **Respect the device's own privacy choices.** s-hole does not defeat a client's encrypted DNS, private relay, or address randomization.
- **Show what is stored.** The dashboard header, the warnings panel, and the startup log say what is recorded and for how long. A new stored field shows there.

Environment notes:
- On a Windows host without gcc, `-race` fails; run it in WSL: `CGO_ENABLED=1 go test -race -count=1 ./...` (CI also runs it on Linux).
- Measure **module-wide** coverage on Linux/WSL only: `go test -coverpkg=./... ./...`. A Windows Go install missing the `covdata` tool silently under-merges the profile, which once put a wrong number in three docs. Per-package `go test -cover` is fine anywhere.
- Lint requires **golangci-lint v2** (`make tools-install` uses the `/v2` module path; v1 cannot parse the `version: "2"` config). If lint fails with a config-load error right after a Go toolchain bump, it's the lint-binary-built-with-older-Go coupling; see the CL 24 addendum. The deliberate errcheck exclusions live in `.golangci.yml` with their rationale.
- `./internal/dnsserver` takes ~12 s on Linux: the DoT timeout tests wait for the real 2 s and 8 s deadlines (`-short` skips the 8 s idle test). Closed-port UDP tests add more on Windows (~17 s before CL 90; not measured again since). Expected, not a hang.
- If port-binding tests fail mysteriously on a Windows/Hyper-V host (bind errors or probe timeouts on ports that look free), check `netsh int ipv4 show excludedportrange protocol=udp`; Windows reserves large port blocks *per protocol* and the reservations shift when VMs start (b/029). `pickFreePort` in dnsserver already defends against this; new tests that bind ports should reuse it or copy its dual-transport random-probe approach.
- Run locally without root/port conflicts: `S_HOLE_DNS_LISTEN=:5354 go run ./cmd/s-hole -config config.yaml`, then `dig @127.0.0.1 -p 5354 doubleclick.net`. Port 5353 is taken by avahi (mDNS) on Raspberry Pi OS and most desktops (b/085). CONTRIBUTING.md has the full 8-step manual smoke test, which turns the query history on through `S_HOLE_*` variables.
- **`config.yaml` is a normally-tracked file; edit and commit it like any other.** The committed sample must keep the most private defaults (`query_log.mode: "none"`, `clients: "drop"`, `database: "off"`, `file: "off"`, `retention_days: 7`, `admin.listen: "127.0.0.1:8080"`, `admin.pprof: false`, the DoH-first upstreams); the release archives and the Docker image bundle it. Never commit a value that `config.Warnings` reports. For local testing, use the `S_HOLE_*` environment variables instead of editing the committed file (`internal/config` reads them over the YAML): `S_HOLE_ADMIN_LISTEN=0.0.0.0:8080` for the LAN dashboard, `S_HOLE_QUERY_LOG_MODE=all` and `S_HOLE_QUERY_LOG_DATABASE=queries.db` for a history.

## Architecture

Per-query hot path (one goroutine per query, spawned by miekg/dns):

```
ServeDNS (internal/dnsserver/handler.go)
  → lanACL.allows                  not a LAN source → REFUSED; not in the stats or the query log, only shole_refused_total (lan.go)
  → one question, opcode QUERY     else SERVFAIL / NOTIMP through send; not counted or logged
  → RD=1                           else REFUSED through send (RD=0 reads only the cache); not counted or logged
  → querylog.MaskClientIP          once, per query_log.clients (fail closed)
  → classify (localnames.go)       localhost → loopback; .onion/.invalid/.alt → NXDOMAIN;
                                   LAN-only name → LAN upstreams only, NXDOMAIN when none
  → blocklist.Store.IsBlocked      O(labels) suffix walk over two O(1) sets; allowlist overrides
  → stats.Counter + querylog fan-out (never blocks the query); tallies follow query_log.mode
  → blocked? write sinkhole reply (0.0.0.0/:: or NXDOMAIN) through send
  → cache.Cache.Get                key: question + CD + DO bits (b/096); TTL-respecting, 1-day cap;
                                   holds no OPT record; hit ends here
  → forward (upstream.go)          fresh query (upstreamQuery: question, RD/CD/AD/DO, random ID,
                                   own OPT 1232, DoH padded); DoH or UDP (TCP retry on TC); checkReply fails a
                                   reply that is not a QUERY response to the sent question; cooldown tracker skips
                                   recently-failed upstreams, second sweep retries them;
                                   all failed → *ForwardError → once-a-minute summary
  → stripOPT → cache.Set (caps TTLs at 1 day; never caches truncated/NXDOMAIN/empty)
  → send (edns.go)                 client ID, client OPT without options, fitUDP, DoT padding → reply
```

Wiring lives in `cmd/s-hole/main.go`, which owns three cross-cutting mechanisms that are easy to break from inside a package:

- **Single-flight reload**: one closure (`newReloadFn`) wraps the reload work (`reloadWork`: the DoT certificate when DoT is on, then `blocklist.Update` in `DownloadFirst` mode and `releaseMemory`; startup uses `CacheFirst`, b/060); the periodic ticker, `POST /api/reload`, and SIGHUP (also sent by `systemctl reload` through the unit's `ExecReload`) all go through it. Passes never overlap. A request during a pass queues one follow-up pass (b/061), and a queued pass is dropped once shutdown cancels `runCtx`. Once shutdown starts, a new request starts no pass, and `waitForReload` closes the gate (the `stop` func that `newReloadFn` returns) under the closure's mutex before it waits (b/070). The gate must stay in main; a mutex inside `api` was a P0 once (b/022) because the ticker bypassed it.
- **Shutdown ordering** (`shutdown`, invoked by `doStop`): cancel ticker ctx → stop DNS → drain HTTP → wait for in-flight reload (bounded) → close cache/loggers → exit. Reordering causes writes-to-closed-DB or half-written blocklist cache files. The order is unit-tested via injected `shutdownDeps` (`TestShutdown_TeardownOrder`, CL 48). `doStop` is the sole exit authority: the interactive path runs the DNS server in a goroutine and blocks in `blockUntilStopped` on a `done` channel that `doStop` closes only after `shutdown()` returns, so the process never exits mid-teardown (a returning `Start()` used to win that race and skip the later steps, b/043, CL 59). If `Start()` fails at runtime, `blockUntilStopped` calls `doStop`, waits for `done`, then exits 1 so systemd restarts s-hole (b/064). The DNS sockets are bound in main before `Start` (`dnsserver.Listen`, `ListenDoT`), so `Shutdown` can always close them (b/063). `drainHTTP` and `waitForReload` get separate timeout budgets so a slow drain cannot starve the reload wait. On Windows the SCM path sends `svc.Stopped` after `doStop` returns (b/044); do not restore an `os.Exit` inside `doStop`. If the DNS server stops without a stop request, `Execute` runs `doStop` and returns a service-specific exit code, and the recovery actions that `-service install` sets restart the service (b/065).
- **Platform split**: Windows SCM service loop vs. interactive signal handling (`signals_unix.go`/`signals_windows.go`, `umask_unix.go`/`umask_windows.go`, `internal/service` with a non-Windows stub). The service runs as the virtual account `NT SERVICE\s-hole` (not LocalSystem, b/086), and `-service install` gives the config folder an owner-only access list (a Go file mode does not restrict access on Windows). A service has no console, so under the SCM `setupLogger` routes slog to the Windows Event Log (source `s-hole`), and `-service install`/`uninstall` register and remove the event source; the handler lives behind the `eventWriter` interface in `internal/service/eventlog.go` (Linux-testable, only `eventlog.Open` is `windows`-tagged). Don't "fix" the stdout slog handler thinking Windows logging is broken; the query lines (`FileLogger`) are separate and need a `query_log.file` path under a service. Linux/systemd is unaffected (journald captures stdout). The SCM starts a service in `C:\Windows\System32`, so main changes to the config file's directory before it loads the config (`chdirToConfigDir`, b/066), and loads it through the absolute path that `chdirToConfigDir` returns (b/069); relative paths then resolve next to `config.yaml`.

**Package loggers** (every package, not only main): a package-level logger is `var logger = logging.For("<pkg>")`, never `slog.With(...)`. `slog.With` at package init binds slog's initial handler before `setupLogger` runs; every record then went through the `log` package into the real handler, formatted twice and always at INFO (b/062). `logging.For` looks up `slog.Default()` for each record. Under systemd, `logging.NewStdoutHandler` prefixes each line with its syslog priority (so `journalctl -p warning` works) and drops `time=` from text lines. A log message says what happened (`X failed`); put advice in a `hint` field. A log line carries no query data (see Privacy first). When you add or rename a message that `docs/TROUBLESHOOTING.md` quotes, update that page.

Concurrency invariants that tests pin (keep them green under `-race`):
- `stats.Counter`: in Snapshot, read every counter a query bumps *after* `total` (`blocked`, `localPTR`, `localName`, `cacheHit`, `forwardFailures`, `upstreamErrors`) *before* `total`, or the ratio can exceed 100% (b/021, b/033, b/036). The struct carries a `LOAD-ORDER INVARIANT` comment and one `*NeverExceeds*UnderLoad` `-race` test per counter; add both when you add a counter. Resolve top-N map pointers *inside* the mutex (R31: prune reassigns them). A purge resets the tallies and the timeline, never the counters, because a counter reset under load breaks the invariant. The per-minute timeline (`timeline.go`) is lock-free (atomic fields, CAS on the minute) and outside the invariant: it shows counts, not ratios.
- `blocklist.Store.Replace` swaps the map pointer under lock, so readers see old or new set, never partial.
- `querylog.DBLogger` and `querylog.FileLogger` drop on a full channel rather than blocking DNS; drops surface as `shole_query_log_dropped_total` and `shole_query_log_file_dropped_total`. A purge runs inside each writer goroutine, so no queued entry is written after it. The SQLite pool is pinned to one connection (`SetMaxOpenConns(1)`) so the async writer, the retention prune, and a purge can't collide with `SQLITE_BUSY` (b/038); don't reintroduce a multi-connection pool.
- **Package-level test seams** (`blocklist.maxBodyBytes`, the `swapLogger` and `captureLogs` logger swaps, and the `trustTLS` swap of `httpClient.Transport`, all in `blocklist`) are mutated only by tests and are safe only because each package runs its tests sequentially (no `t.Parallel`). Production never writes them. If you add `t.Parallel` to a package that mutates a package-level var, pass the value in instead of mutating the global, or the write races the production read under `-race`.

Config (`internal/config`, format 2.0): sections `dns`, `blocking`, `query_log`, `admin`, plus `stats_interval`. Precedence is `S_HOLE_*` env > YAML > defaults; a scalar setting's variable is `S_HOLE_` plus its key path in upper case with dots as underscores. `Load` walks the YAML node tree against one table of settings (`settings()`), so an unknown key, a 1.x key or variable, a duplicate, or an invalid value is a `Problem` and the setting keeps its default; only a malformed `dns.listen`, an all-malformed upstream list, and a broken DoT pair while DoT is on are fatal. Startup logs problems as WARN; `-check-config` fails on any. A new setting gets one `settings()` row (and a `renamedKeys` row if it replaces an old key), a default that is the most private value, and, if it can record more, a `config.Warnings` case.

Admin server (`internal/api`): no login yet. Authentication is a planned, separate CL (device pairing, see `docs/ROADMAP.md`); do not bolt on an ad-hoc password or token. Every route goes through `secure` (`security.go`): the Host check (IP literal, `localhost`, the machine's own hostname and `hostname.local`; 421 otherwise) against DNS rebinding, `http.CrossOriginProtection` against cross-site requests, and `no-store`, CSP, frame, `nosniff`, referrer, and resource-policy headers. A new route gets these automatically; keep it inside the mux that `secure` wraps. A JSON body requires `application/json` (`isJSON`). `POST /api/purge` is accepted only from the host itself (`fromThisMachine`). Defense-in-depth beyond that: localhost-only default bind (with a repeating WARN otherwise), slowloris timeouts, 64 KiB body cap, `?limit=` clamp, opt-in pprof. UI is a static `go:embed` file; it cannot read config (it reads `/api/stats`, including the `privacy` object and `warnings`); don't try to template it.

## Process conventions (enforced in review)

- **Every non-trivial change is a CL**: add `docs/cls/CL-NN.md` (description, motivation, files-changed, testing, and a *Privacy impact* block when the change touches personal data: what it collects, where it goes, how long it stays, who can read it) + a row in `docs/CL.md` + a `docs/CHANGELOG.md` bullet for user-visible changes. Trivial doc-only commits may skip the CL file. A change that adds, moves, or removes personal data updates `PRIVACY.md` in the same CL.
- **End every non-trivial change with a repo-wide documentation and comment sanity check, run by a fresh generic sub-agent.** After the code and the per-file doc syncs are in, delegate one complete pass to a cold `general-purpose` sub-agent (not a `fork`: a fork inherits this session's context and carries the author's assumptions, which defeats the point). It reads the docs and comments as a new reader and checks: consistency (every place that quotes a changed fact agrees, including the frequent-duplicates list below), up-to-date and desired-state (docs, comments, CHANGELOG, CL.md, ROADMAP, PRIVACY.md reflect the current intent), STE compliance for operator/maintainer-facing material, and comment quality (new comments match the local density and idiom, none describe old behavior). The sub-agent reports findings; apply the fixes.
- **The agent that wrote the code does not write its tests.** When an AI agent implements a change, a separate cold `general-purpose` sub-agent (not a `fork`) writes the tests for it. Give that sub-agent the requirements (the specification, the CL description, or the `b/NNN` bug report with the expected behavior) and the location of the code under test. Do not give it the diff or the implementer's reasoning. The sub-agent lists its own test cases from the requirements before it reads the existing tests, then writes the tests against the requirements. For a privacy requirement it writes negative tests: the data does not reach the upstream, the log, a file, or the API. It may also run mutation testing when it judges this useful: it breaks the code on purpose, checks that a test fails, and restores the code. The aim: every test can fail when the requirement is broken (no decorative tests), and the implementer's view of the code does not shape the tests. Run the tester before the documentation sweep, so the CL's Testing section can record its results. If a new test fails, treat it as a possible bug in the code; do not change the test to make it pass without the maintainer's agreement. The implementer may use red-to-green TDD while it builds the change, because a test seen failing first cannot be decorative. These tests share the implementer's reading of the requirements, so they do not replace the cold sub-agent's tests. The implementer may make mechanical updates that keep existing tests compiling after a refactor; a test that pins behavior the change replaces is removed and listed for the tester, not rewritten by the implementer. After the sub-agent reports, the implementer runs `make check` and reviews the new tests for local style only.
- **Open a PR; do not merge.** Do the work on a feature branch and open a pull request for review. Do not merge it. The maintainer reviews and tests the build (often on a VM or a Raspberry Pi) before merging.
- **Doc-vs-code drift is treated as a bug.** When behavior changes, sync every place that quotes it. Frequent duplicates: the privacy defaults and warnings (`config.go` defaults and `Warnings`, `config.yaml` comments, the README configuration table and Privacy section, `PRIVACY.md`, `SECURITY.md`, the TROUBLESHOOTING warnings table, the dashboard texts), coverage targets (README Development table, DESIGN testing paragraph, CONTRIBUTING all state the floors, not measured snapshots: a floor change syncs three docs, a routine coverage wobble touches none; see Coverage expectations below), REST routes (README table, DESIGN table, `api.go` package doc), config keys and defaults (README table, `config.yaml` comments, `config.go`, the 1.x mapping in the CHANGELOG), poll interval (README, DESIGN, CONTRIBUTING), the dependency list (README Dependencies table, `go.mod`, the intro line above), the systemd unit (`deploy/s-hole.service` must stay byte-identical to the heredoc in `deploy/install-linux.sh`), the smoke-test port (CONTRIBUTING, the Commands note above).
- **Historical records are immutable**: `docs/cls/CL-*.md` and `docs/BUGS.md` describe what was true at the time; never "fix" them retroactively.
- **ID conventions**: `b/NNN` = bug in `docs/BUGS.md`; `R/S/T NN` = staff-review findings (letter = review round), tracked in CL notes only. From CL 97 on, a review finding is `SEC-NN` (security) or `PRIV-NN` (privacy), not a round letter; cite these IDs in the CL notes. `/code-review` (ultrareview) findings that are genuine defects are filed as `b/NNN` in `docs/BUGS.md` (b/030–b/037 came from two ultrareview rounds; b/072–b/087 from the CL 93 privacy review), not CL-notes-only. Reference IDs in regression-test comments.
- **Commit style**: imperative subject, often prefixed (`docs:`, `test:`, or `s-hole:` for CLs), body explains why; CL commits end the subject with `(CL NN)`. **Do not add a `Co-Authored-By` trailer.** Maintainer preference for this portfolio repo; overrides any harness default that says to.
- **Writing style (STE-like)**: docs, code comments, and commit messages use short, active, plain sentences (Simplified Technical English in spirit). **No em-dashes (`—`)** in living files; use a period, colon, semicolon, or parentheses instead. Put the condition before the command in procedures. `docs/cls/CL-*.md` and `docs/BUGS.md` are immutable and exempt; new CL titles use `# CL N: title` (a colon, not an em-dash). The anti-slop tells (em-dashes, the triadic "A, B, and C" cadence, "not just X but Y" balancing, empty intensifiers) apply everywhere, design rationale and "why" comments included. The nuance exemption for rationale covers only mechanical brevity (no hard sentence-length cap, no approved-word list); keep the reasoning that makes those parts worth reading. This is a taste guideline to keep the AI-slop smell down, not a CI-enforced gate: the aim is that em-dashes stay rare, not that a build fails on one. Normal dashes are fine (hyphens, and en-dash ranges like `2000–5000`). `grep -n '—' <file>` is a convenience for the obvious cases, not proof: on the maintainer's WSL box `grep` is ugrep and has silently missed em-dashes, so read the changed prose rather than trusting a clean grep. Treat `/simple-english` as a manual tool for operator text (Quick Start, deploy steps, error strings, installer echoes, dashboard labels and empty states), not the enforced whole-repo standard; do not run it over rationale or "why" comments. STE compliance for operator- and maintainer-facing material is about understandability, not only removing the anti-slop tells: it also covers wording and readability (short active sentences, condition before command, one meaning per word, the can/will/must modal ladder). The `/simple-english` skill holds those rules and the self-check; run new operator-facing strings through it, not merely the em-dash scan.
- **Coverage expectations**: `stats`/`config`/`version`/`redact` 100%; `logging` ≥95%; `cache` ≥94%; `api`/`blocklist`/`dnsserver`/`querylog` ≥85%. Run `go test -cover ./...` before PR; if a number drops, add the test or justify in the CL. These floors are the source of truth; README/DESIGN/CONTRIBUTING quote them as targets, so keep measured `go test -cover` percentages out of prose (frozen snapshots drifted on every change and once put a wrong number in three docs). `cmd/s-hole` (bootstrap) and `internal/service` (platform glue) sit below the floors and are not gated; the `internal/service` event-log handler is Linux-testable behind the `eventWriter` interface, but the SCM, Event Log, and folder access list paths need Windows. Module-wide coverpkg measurement is fragile (empty merge on some toolchains); prefer per-package `go test -cover`.
- **Roadmap** (`docs/ROADMAP.md`): planned work rated by impact (never effort estimates), pending decisions, and settled non-goals; check it before proposing features; don't re-propose the non-goals list. When an item lands, flip its status row to `done (CL NN)`.
- **Dependabot PRs that touch the same file can merge-race**: a later PR branched from an older master can silently revert an earlier merged bump (setup-go v6 was lost this way; restored in 0d360d9). After batch-merging, verify the final file state, not the PR list.
- **Releases are tag-triggered** (`.github/workflows/release.yml`, added in CL 43; first release `v0.1.0`, 2026-08-24). Pushing a `vX.Y.Z` tag builds every release target, attaches archives (with `config.yaml`, `README.md`, `PRIVACY.md`, `LICENSE`) + `SHA256SUMS` to a GitHub Release (notes from the matching CHANGELOG section), and pushes a multi-arch `ghcr.io/lcsabi/s-hole` image; a `-rc` suffix marks a pre-release and holds `:latest` back. Graduate the CHANGELOG `[Unreleased]` section to `[X.Y.Z]` before tagging. Full procedure (rc dry-run, verify, final tag) is in CONTRIBUTING's "Cutting a release". A published final tag is immutable; ship fixes as the next patch.
