# CL 35 — Linux installer prints the installed build version/commit

## Description

`deploy/install-linux.sh` now ends with an "Installed build" box that prints
the version, commit, and build date of the binary it just installed. It
captures the identity by running `"$INSTALL_BIN" -version` immediately after
`install`-ing the binary (before the service starts) and renders the output in
a box above the existing "Router setup" block. If the binary produces no
`-version` output, the box falls back to a "could not read version" line
instead of an empty frame.

Roadmap item #11.

## Motivation

The installer never echoed which build it just placed, so a stale-binary
deploy was silent: the operator `scp`s a binary, runs the installer, and has
no signal that the running service predates the fix they meant to ship. This
bit a real deployment — a pre-CL-30 binary was live on a VM, so subdomain
blocking (CL 30) appeared broken until `s-hole -version` revealed the old
commit. Printing the build at the end of the install turns that invisible
class of mistake into an obvious one at exactly the moment the operator is
watching the terminal.

The version/commit is already embedded via the `make` ldflags
(`internal/version`), so this is a deploy-time guard rail with no runtime
behaviour change — rated Low, but cheap and high-signal.

## Design decisions

**Capture before `systemctl start`, print at the end.** The version is read
into `installed_build` right after `install -m 755 … "$INSTALL_BIN"`, so the
value reflects the binary that was just placed regardless of anything the
service does at startup, and the box prints as the script's final
confirmation (above router setup) where the operator will actually read it.

**Show the full `-version` identity, not just the version string.** The
stale-binary failure mode is about the *commit*, not the human version string
(`dev`, `v0.1.0-dirty`), so the box prints the whole multi-line `-version`
output — version, commit, build date — indented into the frame with `sed`. A
plain `go build` without the `make` ldflags prints the `dev`/`unknown`
placeholders; that is correct and expected for a non-release build.

**Fail soft.** `-version` is wrapped in `|| true` and the print is guarded on
a non-empty capture, so a binary that is missing, non-executable, or not
actually an s-hole build cannot abort the installer partway — it prints the
fallback line and the install completes.
