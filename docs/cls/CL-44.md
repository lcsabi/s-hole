# CL 44: resolve release notes for pre-release tags

## Description

Fix the release-notes extraction in `.github/workflows/release.yml` so a
pre-release tag resolves the same CHANGELOG section its final tag will. The
extractor now drops any pre-release suffix from the version before looking up
the heading (`v0.1.0-rc1` -> `0.1.0`).

## Motivation

Found during the `v0.1.0-rc1` release dry-run (the validation the rc exists to
do). The extractor derived the version as the tag minus the leading `v`, so
`v0.1.0-rc1` became `0.1.0-rc1` and it searched for a `## [0.1.0-rc1]` heading.
The CHANGELOG only has `## [0.1.0]`, so nothing matched, the notes file came out
empty, and the release fell back to the placeholder body `Release v0.1.0-rc1.`.

That is not just cosmetic for the rc: it meant the notes path could not be
validated by a dry-run at all. A notes problem would surface only after cutting
the real `v0.1.0` tag, which is exactly what the rc is meant to catch first.

## What it does

One added line after the `v` strip:

```sh
version="${GITHUB_REF_NAME#v}"   # v0.1.0-rc1 -> 0.1.0-rc1
version="${version%%-*}"          # 0.1.0-rc1  -> 0.1.0
```

`%%-*` removes everything from the first `-` onward, so any pre-release suffix
(`-rc1`, `-beta.1`, ...) maps to its base `MAJOR.MINOR.PATCH`. A final tag has no
`-` and is unchanged. When the base version genuinely has no CHANGELOG section
(e.g. a `v0.2.0-beta.1` before a `[0.2.0]` section exists), the existing
empty-file fallback still writes a placeholder body, so the behavior degrades the
same way it did before.

## Files changed

- `.github/workflows/release.yml`: strip the pre-release suffix before the
  CHANGELOG heading lookup.

No Go code changed. No product behavior changed; this only affects the body of
the GitHub Release page.

## Testing

- Ran the extractor against `docs/CHANGELOG.md` for `v0.1.0-rc2`, `v0.1.0`, and
  `v0.2.0-beta.1`: the first two resolve the 340-line `[0.1.0]` body, the third
  (no matching section yet) yields an empty result that hits the placeholder
  fallback.
- Re-validated end to end by cutting `v0.1.0-rc2` after this landed: the Release
  body rendered the `[0.1.0]` CHANGELOG section instead of the placeholder.
