# CL 104: Admin API hardening

## Description

Four hardening changes to the admin server:

- A Fetch Metadata check refuses a request that the browser marks as sent
  from another site, on every route. A link from another page still opens
  the dashboard.
- The allowlist API refuses a two-label public suffix such as `co.uk`, and
  adds at most 1,000 runtime entries (the config allowlist does not count).
- The dashboard script moves from an inline `<script>` to the embedded file
  `static/app.js`, the inline event handlers become `addEventListener` calls,
  and the Content-Security-Policy drops `'unsafe-inline'` from `script-src`.
- The admin `http.Server` gets an `ErrorLog` that replaces every IP address
  in net/http's own lines with `client` and logs them through the `api`
  logger at ERROR (b/103).

Review findings: SEC-10, SEC-11, SEC-19, PRIV-15 (b/103). Target release:
v2.1.0.

## Motivation

- **SEC-10.** `http.CrossOriginProtection` checks only state-changing
  methods, and the Host check accepts every IP literal. So a page on any
  site could send GET requests to `http://127.0.0.1:8080` through the
  operator's browser. It could not read the replies (no CORS headers,
  `Cross-Origin-Resource-Policy: same-origin`), but it could time them: a
  `/api/queries?domain=` reply for a name in the history takes longer, so a
  page could guess what the household looked up. It could also start exports,
  which hold the two export slots.
- **SEC-11.** The allowlist had no size limit. Any client that reaches the
  admin API (a LAN device when `admin.listen` is on the LAN, or any local
  process) could add entries without limit, with one INFO audit line each in
  the journal. An entry such as `co.uk` unblocked every site under that
  public suffix through the suffix walk.
- **SEC-19.** The CSP allowed inline script, because the page used an
  inline `<script>` and `onclick`/`onsubmit` attributes. No injection is
  known (`esc` escapes every data value), but if one ever slipped in, the
  CSP would not stop it.
- **PRIV-15 (b/103).** A panic in an admin handler made net/http log
  `http: panic serving <ip:port>` through the `log` package: at INFO, with
  no `pkg`, and with the client's address and port. The application log
  must not name a client, and `redact.NetError` cannot reach a line that the
  standard library writes.

## What it does

- **Fetch Metadata** (`internal/api/security.go`): `secure` calls
  `fetchAllowed` after the Host check and before `CrossOriginProtection`.
  `Sec-Fetch-Site` values `same-origin` (the dashboard), `none` (a typed URL
  or a bookmark), and no header (`curl`, Prometheus, the healthcheck, an old
  browser) pass. `cross-site`, `same-site`, and an unknown value get 403,
  unless the request is a top-level navigation to the dashboard: `GET /`
  with `Sec-Fetch-Mode: navigate` and `Sec-Fetch-Dest: document`. The 403
  reply carries the security headers, like every reply.
- **Allowlist limits** (`internal/api/api.go`,
  `internal/blocklist/store.go`): `handleAllowlistAdd` refuses a name for
  which `publicSuffixLike` is true (two labels, the first one of `co`,
  `com`, `org`, `net`, `gov`, `ac`, `edu`; case and a root dot ignored) with
  400 and a message that names the reason and an example. It then calls
  `Store.AddToAllowlistLimited(domain, maxAllowlistEntries)`, which checks
  the count and adds under one lock. The store keeps a second set,
  `runtime`, with the entries that this method added; only these count. With
  1,000 runtime entries, a new entry gets 409. A name that is already in the
  allowlist (config or runtime) is accepted and takes no place.
  `RemoveFromAllowlist` frees the place of a runtime entry, and
  `SetAllowlist` clears the set. A refused request writes no audit line.
- **Dashboard** (`internal/api/static/index.html`, `static/app.js`): the
  script is in `app.js`, loaded with `<script src="app.js">` at the end of
  the body. The three collapse buttons are wired by their `data-collapse`
  attribute; the Reload and Delete history buttons and the two forms get ids
  (`reload-btn`, `purge-btn`, `wl-form`, `check-form`). The allowlist form
  shows the server's message for a 400 or 409 reply.
- **CSP** (`security.go`): `script-src 'self'`. `style-src` keeps
  `'unsafe-inline'`, because the page and the script still use inline styles.
- **ErrorLog** (`internal/api/errorlog.go`, `api.go`): `Serve` sets
  `ErrorLog: newErrorLog()`. The writer runs `redactAddrs` over the line,
  which replaces an IPv4 address and a bracketed IPv6 address (each with an
  optional port) and a bare IPv6 address with `client`, when `netip` parses
  it. It logs `admin HTTP server error` at ERROR with `detail` (the first
  line) and `stack` (the rest).

## Design decisions

- **Refuse `same-site` too.** For an IP-literal or `localhost` origin,
  another port on the same host is the same site. A second web app on the
  s-hole host (Grafana, for example) must not reach the
  API either.
- **Allow the navigation to `/` only.** A link to the dashboard is useful
  and shows no data: the page then fetches the data from its own origin.
  A navigation to an API route (a cross-site link to an export URL) is
  refused, because it would start an export.
- **An unknown `Sec-Fetch-Site` value is refused.** The first design rule
  says a fallback is the safe option. A request with no header still
  passes: curl, Prometheus, and the healthcheck send none.
- **The check protects the default loopback bind only.** Browsers send
  Fetch Metadata headers only to a potentially trustworthy origin (HTTPS,
  `localhost`, a loopback address). A dashboard opened by its LAN address
  over plain HTTP gets no header, so only the Host check and
  `CrossOriginProtection` apply there. The docs say so. TLS for a
  non-loopback admin listener is planned in ROADMAP #42, which also makes
  the check apply on the LAN.
- **The cap counts only runtime entries, and it is not a setting.** Decided
  with the maintainer. The cap stops a client of the unauthenticated API, not
  the operator: only the operator can edit the config allowlist, so it has no
  limit, and a large imported list does not block the dashboard. Runtime
  entries are typed one at a time and are lost at a restart, so 1,000 is far
  above real use. A setting to raise the cap would be less secure than its
  default, so it would need its own permanent warning (`config.Warnings`) for
  a case that nobody has.
- **400 for a public suffix, 409 for a full allowlist.** A public suffix is
  a bad request. A full allowlist is a conflict with the current state that
  the operator can clear (remove an entry).
- **No Public Suffix List.** Decided with the maintainer: a small built-in
  set of second-level labels catches `co.uk` and `com.au` with no new
  dependency. `github.io` and other private suffixes still pass.
- **Replace every IP address in the ErrorLog line, not only the remote
  address.** One pattern covers the panic line, the TLS handshake line (once
  the admin server has TLS), and an address that a panic value could hold.
  A match that `netip` cannot parse (a time of day, a three-part version)
  stays.
- **No recover in `secure`.** The ErrorLog covers the panic line and the
  future TLS line at one point. A recover would not cover the TLS line.

## Privacy impact

- **Collects:** nothing new.
- **Log:** less. net/http's own lines no longer hold a client address or
  port; they now have `pkg=api` and level ERROR. The allowlist audit line is
  unchanged; a refused allowlist request writes no line.
- **Who can read:** a web page in the operator's browser can no longer time
  a GET reply from the admin API, so it can no longer guess what the query
  history holds.
- **Sends:** nothing new.

## Testing

A separate sub-agent wrote the tests from the requirements, without the
diff. It listed its cases first, then wrote:

- `internal/api/fetchmeta_test.go`: `cross-site`, `same-site`, and unknown
  values (`bogus`, `CROSS-SITE`, a comma list) get 403 on 24 routes and
  methods, and the handler does not run (no reload, no allowlist change).
  The `/api/queries?domain=` probe gets 403 and no JSON. `same-origin` and
  `none` pass on every GET route; the dashboard's own fetches and changes
  work; no header passes (`/api/stats`, `/api/queries`, `/metrics`,
  `/healthz`, `/`, `/app.js`). A navigation to `/` passes with every refused
  value. Refused: a navigation to any other path, `/` with another
  destination or mode, a missing mode or destination, and POST, HEAD, or
  OPTIONS on `/`. The 403 carries the security headers, and the Host check
  still runs first.
- `internal/api/allowlist_limit_test.go`: the seven labels are refused with
  400 in any case and with a root dot, the allowlist does not change, and a
  name under `co.uk` stays blocked; `example.co.uk`, `github.io`,
  `cobalt.uk`, `co.example.uk`, and similar names pass. 1,000 runtime adds
  succeed and entry 1,001 gets 409; the boundary, a DELETE that frees a
  place, 1,500 config entries that do not count, a config domain that takes
  no place, and a re-add at the cap. A refused add writes no audit line.
- `internal/blocklist/store_allowlist_limit_test.go`: the same rules on
  `AddToAllowlistLimited`, `SetAllowlist` clearing the runtime count, and
  400 goroutines against a limit of 50 giving exactly 50 accepted.
- `internal/api/dashboard_csp_test.go`: `script-src` is exactly `'self'` on
  12 kinds of reply, with no `script-src-elem` or `script-src-attr`; the
  other directives stay. `index.html` has no inline script, no `on...=`
  attribute, and no `javascript:` URL, and loads `app.js`; `app.js` builds
  no inline handler and uses no `eval`, `new Function`, or string timer;
  `/app.js` has a JavaScript Content-Type and the security headers. Every id
  that `app.js` looks up exists in `index.html`.
- `internal/api/errorlog_test.go` (b/103): the panic line for 11 address
  forms (IPv4 LAN, public, and loopback; IPv6; `::1`; IPv4-mapped; with a
  zone) and the TLS handshake line give an ERROR record with `pkg=api`,
  `client` in place of the address, and the stack trace kept. Bare addresses
  in a panic value are replaced, also next to a colon; non-address text (a
  time of day, `file.go:line`, pointers, a MAC address, a three-part version)
  stays.
  End to end through `Serve` on a real listener over `127.0.0.1` and `[::1]`,
  a panicking handler gives one ERROR record with no address or port;
  `http.ErrAbortHandler` gives none.

The sub-agent found one bug: a bare IPv6 address followed by `: ` (`dial
2001:db8::1: connection refused`) was not replaced, because the pattern took
in the colon and the match did not parse. `redactAddrs` now tries the match
with one colon at either end left outside. `TestErrorLog_BareIPv6BeforeColon`
caught it.

Mutation testing by the sub-agent, on a copy of the tree: 34 mutations, each
caught (among them: no Fetch Metadata check, `same-site` or unknown values
allowed, each part of the navigation exception dropped, `'unsafe-inline'`
back, no `ErrorLog`, no redaction, WARN instead of ERROR, no `pkg`, each
address form, config entries counted, `Remove` keeping the place, a split
lock in the store, an inline script or handler, a renamed id).

Not covered by a Go test: the browser check (Firefox and Chrome, no CSP
error in the console), the dashboard message for a 400 or 409 reply, and the
TLS handshake line end to end (the admin server has no TLS). A DELETE of a
config entry followed by an API add takes a runtime place; this is intended.

`make check` passes. Per-package coverage meets the floors (`api` 94.5%,
`blocklist` 99.6%).

Live check on this build, as a plain user on high ports: `Sec-Fetch-Site:
cross-site` and `same-site` on `/api/stats` get 403; no header, `none`, and
`same-origin` get 200; a cross-site navigation to `/` gets 200 and one to
`/api/queries/export` gets 403; `/app.js` is served as `text/javascript`
with `script-src 'self'`; `co.uk` gets 400, `github.io` passes, and the
