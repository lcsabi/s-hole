# CL 94: minimal upstream query and local names

## Description

s-hole no longer forwards the client's DNS message. It builds a fresh query
with only what the upstream needs, and it keeps names that only mean
something on the LAN away from public resolvers. This closes the last two
places where LAN data left the network (ROADMAP #41).

## Motivation

Before this change, the forwarder sent the client's own message upstream.
The upstream saw:

- the client's query ID;
- the client's EDNS options. A COOKIE (RFC 7873) is a per-device token, so an
  upstream could tell the household's devices apart behind one public
  address. A Client Subnet (RFC 7871) is part of the client's address;
- every name, also names such as `printer`, `wpad`, or `nas.lan` that only
  the router can answer. They tell a public resolver which devices and
  services the household has, and get NXDOMAIN back.

The cache stored the upstream's reply with its OPT record, so one client's
reply options (a server cookie for that client, an Extended DNS Error) went to
every other client that hit the same entry. CL 93 fixed the TTL damage to the
OPT record (b/072), not the sharing.

The CL 95 tests also found that a hosts list put `localhost.localdomain` into
the block set: the parser skipped only `localhost`.

## What it does

- **Fresh upstream query** (`internal/dnsserver/edns.go`, `upstreamQuery`):
  one question (with the client's letter case, for dns-0x20), opcode QUERY,
  the RD, CD, and AD bits, a random ID (`dns.Id`, `crypto/rand`), and
  s-hole's own OPT record: UDP size 1232 and the client's DO bit. Nothing
  else from the client's message. A DoH query goes with ID 0 (RFC 8484) and
  is padded to a multiple of 128 bytes (`packDoH`, RFC 8467).
- **Reply path:** `stripOPT` removes the upstream's OPT record (with every
  option) before the cache stores the reply. One writer, `send`, finishes
  every reply (forwarded, cached, sinkhole, local, and the SERVFAIL and
  NOTIMP error replies through `writeRcode`): the client's ID, an OPT
  record with the client's UDP size and DO bit and no options when the query
  had one, `fitUDP` truncation, and RFC 8467 padding to 468-byte blocks for a
  DoT reply when the client padded its query. An extended RCODE becomes
  SERVFAIL for a client with no OPT record, because it cannot be packed.
- **Opcodes and question count:** a query with an opcode other than QUERY
  gets NOTIMP, and a query with more than one question gets SERVFAIL. The
  fresh query can carry neither.
- **Local names** (`internal/dnsserver/localnames.go`, `classify`):
  - `localhost` and names under it: A 127.0.0.1, AAAA ::1, NOERROR with no
    answer for other types (RFC 6761). Checked before the blocklist.
  - `.invalid`, `.onion` (RFC 7686), `.alt` (RFC 9476): NXDOMAIN, never
    forwarded, not even to a LAN upstream.
  - LAN-only names: single-label names (except the zone-level types SOA, NS,
    DS, DNSKEY, RRSIG, NSEC, NSEC3, NSEC3PARAM, CDS, CDNSKEY), names under
    `.local`, `home.arpa`, `.internal`, `.test`, `.intranet`, `.private`,
    `.corp`, `.home`, `.lan`, `.localdomain`, and under a `dns.local_domains`
    entry. They go only to upstreams on the LAN (by the `lanACL` rule, so
    plain and DoH entries with a private, loopback, link-local, or on-link
    address). With none, s-hole answers NXDOMAIN.
  - A local answer counts in the new `local_name_count`
    (`stats.Counter.RecordLocalName`, `shole_local_names_total`, `local_names`
    in the stats line) and is logged as a synthesized record.
- **`dns.local_domains`** (`internal/config`): a list of extra suffixes for
  router domains such as `fritz.box`. Default empty, no environment
  variable. `.fritz.box`, `*.fritz.box`, `fritz.box.`, and any letter case
  are stored as `fritz.box`. A single label is valid. An invalid entry is a
  config problem and is dropped. Unlike the other list settings, an empty or
  null entry is reported too (`setListKeepEmpty`): there it is most likely a
  domain the operator meant to add.
- **Startup note:** `main` logs `no upstream on the LAN` (INFO) with a hint
  when no upstream is on the LAN.
- **Blocklist parser:** skips `localhost`, names under `.localhost`, and
  `localhost.localdomain` in every line format.
- **Docs:** README (features, privacy, configuration table, a new "Local
  names" section, architecture), `config.yaml`, PRIVACY (what goes upstream,
  local names), DESIGN (handler steps, a new "Minimal upstream query and local
  names" section, cache, stats, metrics, privacy), TROUBLESHOOTING (a new "A
  local name does not resolve" section, the stats line), CHANGELOG (upgrade
  note 7 and entries), ROADMAP #41 done, CLAUDE.md (hot path, privacy rule).

## Design decisions

The maintainer settled these on 2026-10-07:

1. **`dns.local_domains`** in addition to the built-in list, because routers
   use their own suffixes (`fritz.box`). It needs no `config.Warnings` case:
   it sends less, and records nothing.
2. **EDNS Client Subnet is always stripped.** No opt-in and no opt-out.
3. **No DNS cookies at all.** The fresh query drops the client's cookie, and
   s-hole sends no cookie of its own. A cookie is an identifier. s-hole
   behind NAT cannot see a change of the household's public address, so it
   could not rotate the cookie then, and the upstream could link the queries
   from before and after the change. Cookies also need per-upstream state and
   BADCOOKIE handling. They protect only against off-path spoofing on the
   plain path, which is a fallback by default, and they do nothing against an
   on-path attacker; only DoH does. The plain path keeps a random query ID
   (new in this CL; the client's ID was reused before) and a random source
   port per exchange (miekg/dns dials a new UDP socket each time), about 32
   bits against off-path spoofing. For no plain path at all, delete the plain
   upstreams.
4. **Padding follows RFC 8467:** DoH queries to s-hole's upstreams are padded
   (128-byte blocks). DoT replies are padded (468-byte blocks) only when the
   client's query carried a Padding option. Plain UDP and TCP are never
   padded.
5. **Testing:** a packet capture on the Raspberry Pi for the plain path, a
   local test DoH server for the encrypted path, and the router as a LAN
   upstream for local-name routing.

Decisions made in the implementation, within that frame:

- **AD is copied** with RD and CD. A stub sets AD in a query to ask for the
  AD bit in the reply (RFC 6840, glibc `trust-ad`); dropping it would remove
  DNSSEC status for those stubs. It identifies nothing.
- **Single-label names with a zone-level type are public.** A validating stub
  asks `com. DS` or `org. DNSKEY`; treating those as LAN names would break
  validation. dnsmasq's `domain-needed` draws the same line from the other
  side (it keeps only A and AAAA queries for plain names local).
- **`.onion`, `.invalid`, and `.alt` never go to the router either.** The
  RFCs ask resolvers not to look them up, and no LAN server answers them.
  `.test` is LAN-only (RFC 6761 lets a local server answer it).
- **A loopback upstream counts as a LAN upstream**, by the same rule as a
  client. It is often a local forwarder; a recursive resolver there (such
  as Unbound) asks the public DNS for a name it cannot answer, and the README
  says so. The same holds for a router.
- **Local answers have their own counter.** Counting them as local PTR would
  misname them, and counting them as forwarded would inflate the forwarded
  remainder and the cache-hit denominator.
- **Extended DNS Errors from the upstream are dropped** with the rest of the
  OPT record. Relaying them per reply while caching without them is possible
  later; nothing needs them now.

## Privacy impact

- **Collects:** nothing new. The new counter is an aggregate count with no
  domain or client.
- **Sends:** less. The upstream no longer receives the client's EDNS options
  (cookie, Client Subnet, padding, any other) or query ID. LAN-only names no
  longer reach a public upstream, and localhost and never-resolved names
  reach no upstream. A DoH query is padded, so its length shows less of the
  name.
- **Stores:** the cache now holds replies without an OPT record, so no
  upstream option for one client is kept for another.
- **Who can read it:** unchanged.
- `PRIVACY.md` "What leaves the network" now lists exactly what the upstream
  receives, and how local names are routed.

## Testing

**Tests by a cold sub-agent.** A separate `general-purpose` sub-agent wrote
the tests from the requirements (R1 to R15), without the diff. New files:
`internal/dnsserver/minimal_query_test.go`, `padding_test.go`,
`localnames_test.go`, `common_reply_test.go`, `internal/stats/localname_test.go`,
`internal/api/localnames_test.go`, `internal/config/local_domains_test.go`,
`internal/blocklist/localhost_test.go`. They cover:

- the upstream query: one question in the client's case, only RD, CD, and AD
  copied, a new random ID over UDP (64 queries), ID 0 over DoH, one OPT record
  (1232, version 0, client's DO) with no client option (COOKIE, ECS, Padding,
  NSID, a local option), the TCP retry equally minimal;
- DoH padding: the POST body a multiple of 128 bytes for 8 name lengths, and
  no option on UDP or TCP;
- the reply: the client's ID and name case, the OPT record mirrored with no
  options against an upstream reply that carries COOKIE, EDE, Padding, ECS,
  NSID, and a local option; no OPT for a client without one; an upstream
  BADCOOKIE becomes SERVFAIL for such a client;
- the cache: no OPT record stored; five clients in turn each get their own
  OPT record or none, with one upstream query;
- DoT padding for every reply kind (forwarded, cached, sinkhole in both modes,
  localhost, never-resolved, LAN-only NXDOMAIN, private PTR, SERVFAIL,
  NOTIMP), none without a Padding option or over UDP or TCP, and an end-to-end
  test over a real TLS connection;
- about 65 name classes (case, the suffix itself, label boundaries, single
  labels, all 10 zone types, the root), LAN-only routing with failover, no
  public upstream contact when every LAN upstream fails, and `HasLANUpstream`
  for 26 plain and DoH entries;
- the counter (`*NeverExceeds*UnderLoad` and cache-hit % at or below 100 under
  `-race`), `/metrics`, the stats line, the query-log record, the tallies for
  each `query_log.mode`, and no application log line for a local answer;
- NOTIMP for four opcodes, SERVFAIL for 0, 2, and 3 questions, nothing sent;
- the plaintext-fallback counter not counting a LAN-only name;
- `dns.local_domains` normalization, limits, 13 invalid shapes, empty and null
  entries reported (other list settings still skip them silently), no
  environment variable, no warning;
- the parser skipping 9 localhost spellings in 5 line formats.

The sub-agent ran 50 mutants: 49 were killed. The survivor moved the
`localName` load after `total` in `Snapshot`; it passes without `-race` and
fails with it, as for the existing `*NeverExceeds*` tests, so this guard
depends on CI's `-race` run. Its first run found one gap: an empty
`dns.local_domains` entry was dropped without a problem, because `setList`
skips empty entries. The code now reports it for this setting. It also noted
that the SERVFAIL and NOTIMP replies did not go through `send`; they do now
(`writeRcode`), and the sub-agent added tests for that (R15).

**Results.** `make check` passes (fmt, vet, golangci-lint, shellcheck, tests).
`CGO_ENABLED=1 go test -race` passes for `stats` and `dnsserver`. Coverage:
`dnsserver` 96.0%, `stats` 100%, `config` 100%, `blocklist` 99.6%, `api`
92.7%, all above the floors.

**Live checks** (the maintainer's decision 5):

- **Plain path, Raspberry Pi 5** (`tcpdump` on `wlan0`, s-hole on
  `127.0.0.1:5355`, upstreams `9.9.9.9:53` and the router `192.168.100.1:53`,
  `local_domains: [fritz.box]`). `dig` sent Client Subnet, a cookie, DO,
  padding, and a private option 65001. The wire showed only
  `[1au] A? example.com. ar: . OPT UDPsize=1232 DO` to 9.9.9.9, with a new ID
  and source port for each query. `printer`, `nas.lan`, `tv.local`,
  `box.fritz.box`, and `router.home.arpa` went to the router only;
  `localhost`, `x.onion`, and `y.invalid` went nowhere; `com DS` went to
  9.9.9.9.
- **Encrypted path, Debian 13 VM** (dig 9.20, DoT on `127.0.0.1:8853` with a
  self-signed certificate, DoH upstreams). A DoT query with `+padding` got a
  468-byte reply with a Padding option for a forwarded, a cached, a localhost,
  and an NXDOMAIN answer. Without `+padding`, and over UDP and TCP, the reply
  was 94 bytes with no padding. Quad9 and Cloudflare DoH, each alone,
  answered the padded ID-0 queries (AD set for signed zones, no forward
  failure).
- **No LAN upstream** (local, upstream on TEST-NET): `printer`, `nas.lan`,
  and `box.fritz.box` got NXDOMAIN at once, `no upstream on the LAN` was
  logged, and `shole_local_names_total` matched.
- **Mock upstream** (local): the client's cookie, Client Subnet, and the
  upstream's cookie and EDE did not cross s-hole in either direction.
- `-check-config` passes on the sample `config.yaml` and fails on invalid
  `local_domains` entries.

- **End to end with a router that serves names** (dnsmasq 2.91 on the Debian
  VM at `192.168.100.18:5390`, as a home router: a hosts file for `printer`,
  `nas.lan` (A and AAAA), `tv.local`, `box.fritz.box`, and
  `router.home.arpa`, `local=` for `.lan`, `.fritz.box`, `home.arpa`, and
  `.local`, no upstream of its own; s-hole on the Pi with upstreams
  `9.9.9.9:53` and the VM, `local_domains: [fritz.box]`, `tcpdump` on
  `wlan0`). Every local name resolved through the router, `unknown.lan` got
  the router's NXDOMAIN, and `example.com` went to 9.9.9.9 only. The router's
  query log and the capture both show only the ten local-name queries, each
  `OPT UDPsize=1232` with no Client Subnet or cookie (dig sent both), with a
  new ID and source port. With a 60 s TTL from the router, a repeated
  `nas.lan` was a cache hit and reached the router once (with dnsmasq's
  default TTL 0 for hosts names, s-hole correctly does not cache). With the
  router stopped, `tv.local` and `printer` got SERVFAIL, 9.9.9.9 received
  none of them, and the `queries could not be resolved` summary named only
  the router upstream and no domain.
