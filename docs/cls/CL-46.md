# CL 46: pin the IsBlocked zero-allocation invariant with a test

## Description

Add `TestStore_IsBlocked_ZeroAlloc`, which asserts that `Store.IsBlocked`
allocates zero times per call on both the hit path and the deep-miss path. The
test uses `testing.AllocsPerRun` and lives in a `//go:build !race` file.

## Motivation

DESIGN and the CL 30 suffix-walk notes claim the lookup "reslices the name in
place (no allocation)" and is zero-per-query allocation. That property was
asserted only by `BenchmarkStore_IsBlocked`'s `ReportAllocs`, which a reader has
to run and eyeball. `make bench` is a smoke, not a gate, so a refactor that
introduced a per-query allocation (for example building a `[]string` of labels
instead of reslicing) would pass the whole suite unnoticed.

This is the same kind of invariant the `stats` package pins with its load-order
`-race` tests: a documented property that is cheap to state and easy to break, so
it earns a standing regression test rather than a comment alone.

## What it does

`testing.AllocsPerRun(1000, ...)` calls `IsBlocked` and asserts the average
allocations per call is 0, for two probes:

- `ads.example.com` (hit, early return),
- `deep.sub.domain.example.org` (miss, the suffix walk to the TLD, which is the
  common allowed-query shape).

Both probes are already lowercase with no trailing dot, so `normalize` takes its
allocation-free path: `strings.ToLower` returns an all-lowercase ASCII string
unchanged, and the trailing-dot trim is a reslice. A mixed-case or FQDN-dotted
name allocates inside `ToLower`; that is a `normalize` concern, distinct from the
walk this test pins, so it is deliberately out of scope.

The test is build-tagged `!race`. The race detector's instrumentation allocates,
so `AllocsPerRun` reports non-zero under `-race` and a zero-alloc assertion would
flake there. The stdlib excludes its own alloc tests from `-race` the same way.
The test still runs under `make test` / `make check` and CI's non-race job.

## Files changed

- `internal/blocklist/alloc_test.go`: new `//go:build !race` file with the
  zero-alloc regression test.

Test-only. No product code, config, route, or user-visible behavior changed, so
no CHANGELOG entry.

## Testing

- `go test -run TestStore_IsBlocked_ZeroAlloc -v ./internal/blocklist/`: both
  subtests pass (0 allocs).
- `go test -race -run TestStore_IsBlocked_ZeroAlloc ./internal/blocklist/`:
  reports "no tests to run", confirming the `!race` tag excludes it from race
  builds; the package's race suite stays green.
- `make check` clean (fmt, vet, lint 0 issues, tests). `internal/blocklist`
  coverage unchanged at 90.4 %.
