# CL 75: bump golang.org/x/sys to 0.48.0 and raise the Go floor to 1.26

## Description

Take Dependabot's `golang.org/x/sys` 0.47.0 to 0.48.0 bump and the Go language
floor it forces. x/sys 0.48.0 declares `go 1.26.0` as its minimum, so `go mod
tidy` raises this module's `go` directive from `go 1.25.0` to `go 1.26.0`. Move
the CI and release jobs from Go 1.25 to 1.26 to match, and sync the docs that
state the build requirement.

## Motivation

Dependabot PR #64 (the x/sys 0.48.0 bump) failed CI on the `build / vet / test`
and `lint` jobs with:

```
go.mod requires go >= 1.26.0 (running go 1.25.14; GOTOOLCHAIN=local)
```

The bump raised the module's `go` directive to 1.26.0, but those two jobs still
pinned `go-version: "1.25"`, and Go 1.25 refuses to build a module that needs
1.26. The `govulncheck` job already ran on 1.26 (x/vuln needs it) and passed,
which localized the failure to the pinned build/test/lint toolchain, not the
dependency itself. This is a dependency bump that raises the minimum Go version,
not the same-file merge-race that b/029-era notes describe.

## What it does

- **`go.mod` / `go.sum`**: `golang.org/x/sys` 0.47.0 to 0.48.0, and the `go`
  directive 1.25.0 to 1.26.0 (both from `go mod tidy`).
- **`.github/workflows/ci.yml`**: `go-version` 1.25 to 1.26 in the `lint` and
  `build / vet / test` and `cross-compile` jobs. Update the lint comment
  (Go-1.25 to Go-1.26 module target) and the `govulncheck` comment (the
  build/test jobs no longer diverge on 1.25; the 1.26 pin there is still
  explained by x/vuln).
- **`.github/workflows/release.yml`**: `go-version` 1.25 to 1.26 in the build
  matrix job.
- **`Dockerfile`**: the requirement comment now reads Go 1.26+ and names x/sys
  as the driver (the `golang:alpine` base image already tracks the latest
  stable release, so no image change is needed).
- **Docs**: `README.md` (the "Go 1.25 or later" build requirement and the
  `-version` sample output line) and `CONTRIBUTING.md` (the "Go 1.25 or later"
  prerequisite) now state 1.26.

## Design decisions

- **Accept the 1.26 floor rather than hold the bump.** The maintainer chose to
  raise the minimum Go version so the x/sys bump lands. Go 1.26 is already
  available on the runners (the `govulncheck` job uses it), so the move is a
  version pin change, not new infrastructure.
- **Deliver as one branch, not on the Dependabot branch.** The workflow edits
  need to travel with the go.mod bump so CI is green in one PR. Carrying both
  here makes Dependabot PR #64 redundant; close it after this merges.
- **Bump the `cross-compile` and `release` jobs too, alongside build/test.** They
  build the same module, so they must satisfy the 1.26 floor as well. Leaving
  them at 1.25 would move the failure to the release path instead of fixing it.

## Files changed

- `go.mod`, `go.sum`: the x/sys bump and the `go 1.26.0` directive.
- `.github/workflows/ci.yml`: go-version pins and two comments.
- `.github/workflows/release.yml`: the go-version pin.
- `Dockerfile`: the requirement comment.
- `README.md`, `CONTRIBUTING.md`: the stated Go build requirement.
- Docs: `docs/CHANGELOG.md`, `docs/CL.md`.

## Testing

- `make check` clean on Go 1.26.5 (local WSL).
- `go build ./...` and `go vet ./...` pass on 1.26.
- `go mod verify` passes; `go.mod` matches Dependabot PR #64 byte for byte.
