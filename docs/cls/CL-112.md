# CL 112: Privacy docs for the admin server, Prometheus, and DoH-only upstreams

## Description

A documentation change, plus one warning text:

- The `admin.listen` warning detail (`internal/config/privacy.go`) now also
  says that the traffic is plain HTTP, so a device on the network path can
  read it. The README configuration table, the README admin section, the
  TROUBLESHOOTING warnings table, `config.yaml`, and `PRIVACY.md` say the same.
- `PRIVACY.md`, `SECURITY.md`, `config.yaml`, the README security notes, and
  DESIGN say that every account and process on the s-hole host can use the
  loopback admin API: read the history, export it, purge it, and change the
  allowlist. They recommend a dedicated host.
- ROADMAP #42 (device pairing) gets two requirements: authentication also on
  loopback for the data routes, and TLS for an admin listener that is not
  loopback.
- `PRIVACY.md` gets a row for the counter history that a Prometheus server
  keeps, and the README monitoring section says that s-hole cannot delete it.
- The README has a new "DoH only" section, and the `dns.upstreams` comment in
  `config.yaml` says how to set up DoH-only upstreams and what s-hole does
  when every DoH upstream fails.

Review findings: PRIV-02, SEC-14, PRIV-13, PRIV-14.

## Motivation

- **PRIV-02.** The query database is owner-only (mode `600`), but the API on
  loopback serves the same data to every local account and process, with no
  login. `fromThisMachine` accepts every loopback request, so any local
  account can also purge the history and change the allowlist. `PRIVACY.md`
  said only "the s-hole user only ... and anyone who can reach the
  dashboard", which hid that "anyone" includes every local account. On a
  shared machine (a family PC, a server with several users, a host with an
  untrusted local service), another person or a process can read the
  household's history.
- **SEC-14.** With `admin.listen` on the LAN, the history, the exports, and
  a future pairing pass cross the LAN in clear text. On Wi-Fi with a shared
  password, every device that knows the password can capture the traffic.
  The warning said only that there is no login.
- **PRIV-13.** A Prometheus server that scrapes `/metrics` keeps the
  since-start counters over time under its own retention. The counts over
  time show when the household is active, also under `query_log.mode:
  "none"`, and s-hole cannot delete them. `CLAUDE.md` names Prometheus as such
  a place, but `PRIVACY.md` did not list it.
- **PRIV-14.** A DoH-only `dns.upstreams` list already fails closed: when
  every DoH upstream fails, s-hole answers SERVFAIL. Only the failure-summary
  hint, TROUBLESHOOTING, and one `config.yaml` sentence said how to set it
  up, and none said that a router in the list is a plain fallback for public
  names too.

## Design decisions

- **Docs now, code with #42.** The maintainer decided (2026-10-08) that
  PRIV-02 and SEC-14 get documentation and a warning text now. The fix is
  part of the device pairing design (ROADMAP #42), which needs its own CL.
  An ad-hoc password or token is not the plan (see `CLAUDE.md`).
- **Which routes need a login on loopback.** The data routes: the stored
  queries and their export, the top-blocked list, the history, the Top lists
  in `/api/stats`, the purge, and the allowlist changes. The probes and
  `/metrics` stay open. They hold no domain or client, and the Docker
  healthcheck and Prometheus cannot pair a browser. A local process can
  still poll `/metrics` and build the same activity timeline that a
  Prometheus server keeps; #42 records this. The pairing design settles the
  other routes (`GET /api/allowlist`, `GET /api/check`, `POST /api/reload`,
  `/debug/pprof/*`, and the dashboard page).
- **TLS reuses the DoT certificate code.** A LAN admin listener needs HTTPS
  for the pairing pass. HTTPS also makes the LAN dashboard a trustworthy
  origin, so browsers send Fetch Metadata to it, which closes the limit
  that CL 104 documented.
- **No `require_encrypted_upstream` setting (PRIV-14).** A DoH-only list
  already gives this behavior, and CL 93 settled the default list with a
  plain fallback. A setting would add a second way to say the same thing.
  ROADMAP lists it under "Deliberately not planned".
- **The Prometheus row says "none" as the default.** s-hole runs no
  Prometheus. The operator opts in by setting one up, and the row says that
  a purge and retention do not reach it.

## Privacy impact

- **Collects:** nothing new.
- **Keeps:** nothing new. `PRIVACY.md` now lists the Prometheus counter
  history, which an operator's Prometheus kept before this change too.
- **Who can read:** unchanged. The docs now say that every local account and
  process can read the history through the loopback API, and that a LAN
  admin listener sends it in clear text.
- **Sends:** nothing new.

## Testing

A separate tester wrote the tests from the SEC-14 requirement, without the
diff (`internal/config/privacy_test.go`):

- `TestWarnings_AdminListenDetail`: for `0.0.0.0:8080`, `:8080`,
  `192.168.1.10:8080`, and `[::]:8080`, exactly one `admin.listen` warning.
  Its detail names the address and says that there is no login, that the
  history can be read and the allowlist changed, and that the traffic is not
  encrypted. Its hint names `127.0.0.1:8080`. The checks look for the facts,
  not the exact sentence.
- `TestWarnings_LoopbackAdminListenGivesNoWarning`: `127.0.0.1:8080`,
  `[::1]:8080`, and `localhost:8080` give no warning.

The tester broke the code eight ways (removed the plain HTTP clause, the
address, "no login", "history", "allowlist", the default in the hint;
warned for loopback; warned twice). A test failed for each, and the tester
restored the code.

- `make check` passes. `internal/config` coverage is 100%.
- Local run (WSL): with `admin.listen: "0.0.0.0:18089"`, `-check-config`
  printed the new warning detail. With two unreachable DoH upstreams
  (`192.0.2.1`, `192.0.2.2`) and no plain entry, `dig` got SERVFAIL after
  about 6 s (3 s for each upstream).
- A cold sub-agent checked the docs and comments repo-wide; its findings are
  applied.
