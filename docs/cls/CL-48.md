# CL 48: make the shutdown teardown order testable

## Description

Extract the shutdown teardown sequence from the `doStop` closure into a
`shutdown` function driven by an injectable `shutdownDeps` struct, then test the
order directly. `doStop` keeps the wiring and the `os.Exit`.

## Motivation

An invariant audit found the teardown order was the one high-consequence
invariant with no test. The order is required: cancel the tickers, stop the DNS
server so no query touches the cache or loggers, drain in-flight HTTP, wait for
an in-flight blocklist refresh to finish its `os.Rename`, and only then close the
cache and loggers. A wrong order risks a write-to-closed-DB or a half-written
cache file.

The order was expressed as a sequence of method calls inside `doStop`, a closure
that ends in `os.Exit(0)`. `os.Exit` kills a test, and the order was implicit in
concrete method calls, so nothing could assert it. The individual steps
(`waitWithDeadline`, ticker-stops-on-cancel) were tested, but the sequence was
exercised only by the manual smoke test.

## What it does

- `shutdownDeps` is a struct of `func` values, one per teardown action. `shutdown`
  runs them in the required order and returns (no exit), logging a `drainHTTP`,
  `closeFileLog`, or `closeDB` error rather than aborting. This matches the
  existing injectable-helper pattern (`newReloadFn`, `runTicker`,
  `buildMultiLogger`), so no new interfaces are added to the subsystems.
- `doStop` now wires the real subsystems into `shutdown` and calls `os.Exit(0)`
  after it returns. Behavior is unchanged.
- The order invariant is documented on `shutdown` itself (an enforcement-site
  comment), naming the test that guards it.

Two tests: `TestShutdown_TeardownOrder` asserts the exact sequence, and
`TestShutdown_ContinuesAfterErrors` asserts a drain or close error is logged and
the later steps still run. Making the sequence reachable from a test lifted
`cmd/s-hole` coverage from 36.0 % to 41.7 %.

## Files changed

- `cmd/s-hole/main.go`: add `shutdownDeps` and `shutdown`; `doStop` delegates to
  `shutdown`.
- `cmd/s-hole/main_test.go`: `TestShutdown_TeardownOrder`,
  `TestShutdown_ContinuesAfterErrors`.
- `README.md`, `docs/DESIGN.md`, `CONTRIBUTING.md`: refreshed coverage numbers

Refactor plus tests. No product behavior, config, route, or user-visible change,
so no CHANGELOG entry.
