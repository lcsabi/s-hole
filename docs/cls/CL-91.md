# CL 91: fixes from the code review of CL 85 to CL 90

## Description

This CL fixes every finding from the two-axis code review of CL 85 to CL 90
(`2242b6e..000c9aa`). It also fixes the review's open question and the items
that the review noted as older than the reviewed range.

Defects, filed in `docs/BUGS.md`:

- **b/067.** An upstream such as `HTTPS://1.1.1.1/dns-query` passed config
  validation, but the forwarder did not send it over DoH, so every query to it
  failed. `url.Parse` lowercases the scheme; the forwarder matches the exact
  prefix `https://`. The config now stores the normalized URL. A DoH URL with
  user info or with no path is dropped.
- **b/068.** A blocklist download that failed after the 200 status (a reset
  or a timeout during the body) skipped the stale-cache fallback, so a reload
  dropped that list's domains. Since CL 89 every reload downloads, so every
  reload could reach this path. It now takes the same fallback as a
  connection error.
- **b/069.** Under the Windows SCM, a relative `-config` path in a
  subdirectory was resolved again after the change to the config directory.
  The config now loads through the absolute path.
- **b/070.** A reload request after shutdown had started still started a
  pass, which shutdown did not wait for. A new request is now refused, and
  shutdown closes the gate under the reload closure's mutex before it waits.

Other findings:

- The DoT expiry warnings said what to do in `msg`. They are now `DoT
  certificate expired` and `DoT certificate expires soon`, with the advice in
  a `hint` field. The day count in the hint comes from
  `certExpiryWarnWindow`, not a literal.
- The pprof warning is now `pprof endpoints enabled`, with the advice in a
  `hint` field.
- The `dns server failed` record now has a hint on both paths (interactive
  and Windows service) that says what s-hole does and where to look.
- A DoH reply gets the query's ID, as a cache hit does.
- The Windows service sends a 15-second wait hint with `StopPending`.
- Comments: the `main.go` package doc names the DNS bind, the SCM directory
  change, and all four `doStop` callers. `isClosedListener` moved to
  `server.go` with a comment that covers every transport.
- Docs: the `-check-config` commands in the README and the troubleshooting
  guide run as the `s-hole` user. DESIGN calls the client-facing DoH server
  deferred (#39), not out of scope, and describes the DoH URL check. CLAUDE.md
  lists the package-logger rule apart from main's three mechanisms.
- Tests: the stress test's waits are bounded, the limiter test no longer
  relies on a sleep, and new tests cover the DoH TLS check and the Go and
  shell interface lists. See Testing.

## Motivation

The review graded the range on two axes. On the specification axis, R3 (DoH
URL validation) and R16 (DownloadFirst falls back to the cache on failure)
were implemented incorrectly, and R21 (advice in `hint`) and R29 (doc sync)
were partial. On the standards axis, it found four violations and seven
heuristic smells. The maintainer asked for every finding, the open question,
and the noted older items to be fixed in one CL.

## What it does

- **`internal/config/config.go`.** `normalizeDoHURL` replaces
  `isValidDoHURL`. It accepts an https URL (any case in the input) with an IP
  host, a path other than `""` and `/`, and no user info, and returns
  `parsed.String()`. `filterUpstreams` stores that string. The drop WARN
  logs a URL with user info through `redactUserInfo`, which replaces the user
  info with `redacted`, and its hint names the path and user-info rules. A
  URL that `url.Parse` rejects is redacted by hand: everything before the
  last `@` in the authority is replaced. The fatal empty-list error names the
  same rules.
- **`internal/blocklist/loader.go`.** In `fetchList`, a read error from
  `parseHostsFormat` or a close error on the `.tmp` file removes the `.tmp`
  file and takes the stale-cache fallback (`download failed, using stale
  cache`, `from=stale_cache`) when a cache file exists. Without one, the error
  is returned as before.
- **`cmd/s-hole/main.go`.**
  - `chdirToConfigDir` returns the absolute config path. main sets
    `*cfgPath` to it before `config.LoadAndValidate`.
  - `newReloadFn` returns `(reload, stop)`. `reload` refuses a request when
    the gate is closed or `ctx` is cancelled, and logs `reload refused during
    shutdown`. A queued pass also checks the gate. `waitForReload` calls
    `stop` before `waitWithDeadline`.
  - `certReloader.ExpiryWarning` returns `(msg, hint)`, and
    `warnCertExpiry` logs both.
  - New `pprof endpoints enabled` hint, and a `dns server failed` hint on
    the interactive path and on the Windows service path.
  - The package doc and the `doStop` comment.
- **`internal/dnsserver/dot.go`.** `expiryWarning` returns a message and a
  hint; the day count is computed from `certExpiryWarnWindow`.
  `isClosedListener` moved to `server.go`.
- **`internal/dnsserver/upstream.go`.** `exchangeDoH` sets `out.Id = req.Id`.
- **`internal/service/svc_windows.go`.** `stopWaitHint` (15000 ms) on both
  `StopPending` statuses.

## Design decisions

- **Normalize the DoH URL, do not require a lowercase prefix.** URL schemes
  are case-insensitive (RFC 3986), so `HTTPS://` is a valid way to write the
  URL. Storing `parsed.String()` makes the validator and the forwarder agree
  without a second rule.
- **Reject a DoH URL with no path.** Every documented DoH endpoint is a path
  on the server. A URL without one sends the POST to `/`, which the major
  providers do not serve, so the failure moved from every query to startup.
- **Reject user info, and redact it in the warning.** The upstream string is
  the `shole_upstream_transport_failures_total` label on the unauthenticated
  `/metrics` page, so a password in the URL would be on the LAN. The first
  VM run showed that the drop WARN then wrote the password into the journal
  instead, so the WARN replaces the user info with `redacted`.
- **Rewrite the DoH reply ID instead of failing over on a mismatch.** On UDP
  the ID check protects against spoofed replies. Over TLS the server is
  authenticated, so the check adds nothing there, and a failover would make a
  DoH server that does not echo the ID unusable. The cache-hit path already
  rewrites the ID.
- **Close the reload gate under the closure's mutex.** A `ctx.Err()` check
  alone does not order a caller's `wg.Add` before shutdown's `wg.Wait`,
  because `cancel` does not take the mutex. A `stop` call under the mutex
  does: a caller that got in first finished its `wg.Add` before `stop`
  returned, and a later caller sees the closed gate.
- **A refused request still returns false.** `POST /api/reload` then answers
  `"reload queued"`. This can happen only between the start of shutdown and
  the end of the admin HTTP drain, for a process that is stopping. A third
  return value would change the `api.New` contract for that window only.
- **The DoT expiry message rename is not a breaking change.** Those messages
  came with CL 86, which is not in a release yet. The pprof message is in
  v1.0.0, so the CHANGELOG lists its rename under Changed.
- **CHANGELOG entries only for released behavior.** CL 85 (DoH) and CL 90
  (the Windows directory change) are not in a release yet, so b/067, b/069,
  the DoH path and user-info rules, and the DoH reply ID go into the CL 85
  bullet or nowhere, as the DoT message rename does. b/068, b/070, the pprof
  message, and the wait hint change behavior that v1.0.0 has, so they get
  their own bullets.
- **15-second stop wait hint.** The teardown gives the HTTP drain and the
  reload wait 5 s each and then closes the query log.

## Testing

A separate cold sub-agent wrote the tests from the requirements (the b/067 to
b/070 reports and the review findings), without the diff. It listed its cases
before it read the existing tests. The implementer changed existing tests only
to keep them compiling after the signature changes (`newReloadFn`,
`chdirToConfigDir`, `ExpiryWarning`) and the DoT message rename.

- **`internal/config/config_test.go`.** `TestFilterUpstreams_DoHNormalizationAndDrops`
  (uppercase and mixed-case schemes stored as `https://`, bracketed IPv6
  kept; user info, no path, `/` path, a hostname, other schemes, and an
  unparsable URL dropped), `TestFilterUpstreams_MalformedURLReallyFailsParse`
  (proves that the malformed case makes `url.Parse` fail), and
  `TestLoad_NormalizesDoHAndWarnsOnDrops` (the stored list, one WARN per
  dropped entry, user info logged as `redacted` also for an entry that
  `url.Parse` rejects, and no user name or password anywhere in the log), and
  `TestRedactUserInfo_UnparsableURL` (the last `@` in the authority, an `@`
  in the path left alone). The `TestFilterUpstreams_DoH`
  comment no longer claims a malformed case that it did not have.
- **`internal/blocklist/loader_test.go`.** `TestUpdate_MidBodyFailureServesStaleCache`
  (a server that sends part of the body and closes the connection; both
  modes; the WARN, `from=stale_cache`, `Stale`, `LastRefresh` equal to the
  cache mtime, the cached domains kept, no `.tmp` left) and
  `TestUpdate_MidBodyFailureNoCacheFails`.
- **`cmd/s-hole/main_test.go`.** The four `TestChdirToConfigDir_*` tests
  rewritten for the new return value, and
  `TestChdirToConfigDir_NestedRelativeLoadsConfig` (b/069: the config loads
  through the returned path, and the original relative path no longer names
  it). `TestNewReloadFn_RefusedAfterCancel`, `_RefusedAfterStop`, and
  `_StopDropsQueuedPass` (b/070). The stress test's waits are now bounded.
  `TestVirtualIfacePrefixes_MatchInstaller` reads `deploy/install-linux.sh`
  and fails if its interface list differs from the Go list.
  `TestBlockUntilStopped_ServeErrorLogsHint`, `TestWarnCertExpiry_LogsOneWarnWithFields`,
  and `TestWarnCertExpiry_SilentWhenNoWarning`.
- **`internal/dnsserver/dot_test.go`.** `TestExpiryWarning` rewritten: exact
  messages, non-empty hints, and the day count checked against
  `certExpiryWarnWindow`. `TestLimitListener_CloseUnblocksWaitingAccept` no
  longer relies on a sleep: it waits until the goroutine is blocked in
  `Accept`, and a counting inner listener proves that the second `Accept`
  waited for a slot.
- **`internal/dnsserver/upstream_test.go`.** `TestForward_DoHReplyIDMismatchGetsQueryID`
  and `TestExchangeDoH_ProductionClientVerifiesTLS` (the production
  `dohClient` rejects an untrusted certificate).

Mutation testing: 40 mutations, all caught (26 in the first round, 6 for
the redaction, and 8 for the redaction of unparsable URLs and the hint; the
redaction set was run again against the final code). Among them: storing the raw DoH
string, allowing user info or a `/` path, no stale fallback on a read error,
the snapshot set to now, `chdirToConfigDir` returning the directory or the
unchanged path, the reload gate ignoring `closed` or `ctx`, the follow-up
ignoring `closed`, a 7-day window with "14" in the hint, removing the DoH ID
rewrite, `InsecureSkipVerify` on `dohClient`, a non-blocking limiter slot,
and "tap" removed from the Go interface list.

Not unit-tested: that config validation dials nothing (a unit test cannot
prove the absence of a dial), the `main()` wiring that loads the config
through the returned path under the SCM, and the Windows wait hint.

`make check` passes. `CGO_ENABLED=1 go test -race -count=1 ./...` passes, and
`GOOS=windows go vet ./...` is clean. Coverage: `blocklist` 97.9 %, `config`
100 %, `dnsserver` 93.7 %. One `-race` run failed to bind a port in
