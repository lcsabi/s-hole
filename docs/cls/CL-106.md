# CL 106: Linux and Docker deploy hardening

## Description

- **systemd sandbox.** `deploy/s-hole.service` and the identical heredoc in
  `deploy/install-linux.sh` keep their lines and add a sandbox: a private
  `/dev`; a private `/tmp` that is read-only; no access to kernel tunables, modules, logs, cgroups,
  the clock, or the hostname; a `/proc` that shows only s-hole's own process;
  only Unix, IPv4, IPv6, and netlink sockets; no new namespaces, set-user-ID
  files, or realtime scheduling; no writable and executable memory; the
  `@system-service` system-call filter without `@privileged` and
  `@resources`. A comment in the unit says why `AF_NETLINK` stays.
- **Hardened `docker run`.** Both README examples (host and bridge
  networking) add `--read-only`, `--security-opt no-new-privileges:true`, and
  `--cap-drop ALL --cap-add NET_BIND_SERVICE`, with a note that
  `--cap-drop ALL` alone stops the container at start.
- **Docker bridge and IPv6.** The README bridge section says why port 53 is
  published on the host's IPv4 address. `docs/TROUBLESHOOTING.md` has a new
  entry, "Every client shows as 172.17.0.1", and a row for the
  `operation not permitted` start error.

Review findings: SEC-09 (the unit part; the `lan.go` WARN shipped in
CL 101), SEC-13, SEC-20. Target release: v2.1.0.

## Motivation

- **SEC-09.** `systemd-analyze security s-hole` rated the unit 6.2 MEDIUM.
  s-hole needs none of the access that the new lines remove. The
  `RestrictAddressFamilies` line that the review proposed
  (`AF_UNIX AF_INET AF_INET6`) breaks the LAN check: Go's
  `net.InterfaceAddrs` reads the interface addresses through a netlink
  socket, so without `AF_NETLINK` s-hole refuses the devices on a public
  IPv6 LAN prefix.
- **SEC-20.** The README had no hardened `docker run`. `--cap-drop ALL`
  alone fails at exec, because the binary carries a file capability, so an
  operator who tries it gets a container that does not start.
- **SEC-13.** If port 53 is published without an address (`-p 53:53/udp`),
  Docker also listens on the host's IPv6 addresses and relays IPv6 queries
  into the IPv4-only bridge network, with the bridge gateway as the source.
  The LAN check sees a private address and cannot refuse a source from the
  internet, and every IPv6 client shows as the gateway. The README example
  was not affected (it publishes on `${HOST_IP}`), but it did not say why.

## Design decisions

- **Keep `AF_NETLINK`.** It is the price of the interface-subnet part of
  the LAN check. The unit comment and `SECURITY.md` say why, so a later
  tightening does not remove it. If a drop-in removes it, the WARN from
  CL 101 (`interface address read failed`) names `AF_NETLINK`;
  `docs/TROUBLESHOOTING.md` shows how to read the value that systemd uses.
- **The file limit stays high.** The Go runtime raises the soft limit for
  open files at startup. `@resources` blocks `setrlimit`, but Go uses
  `prlimit64`, which is in `@default`. Checked live: the soft limit is
  still 524287.
- **The private `/tmp` is read-only** (decided with the maintainer). With
  `PrivateTmp=true` alone, a query path under `/tmp` would no longer fail to
  write: the history would stay in the service's private `/tmp` until a
  stop or a restart, and systemd would delete it without the zero overwrite
  of a purge. s-hole writes only to `/var/lib/s-hole`, so
  `ReadOnlyPaths=/tmp /var/tmp` keeps the old result: such a path fails to
  write and keeps no data. The other services' files in `/tmp` stay hidden.
- **TCP listen backlog.** `ProcSubset=pid` hides
  `/proc/sys/net/core/somaxconn`, so Go uses a listen backlog of 128
  (`syscall.SOMAXCONN`) for the TCP DNS, DoT, and admin listeners instead of
  the kernel's value. This is enough for a home LAN; the TCP listeners cap
  open connections at 256.
- **Docker: `--read-only` needs no `--tmpfs`.** s-hole writes only to
  `/app`, and SQLite keeps its temporary data in memory
  (`temp_store=MEMORY`), so a `VACUUM` in a purge writes no temporary file.
- **No setting and no code change.** The change is in the deploy files, a
  test, and the docs. The Docker image is unchanged.

## Privacy impact

- **Collects, keeps, sends:** nothing new.
- **Docker bridge:** the README and TROUBLESHOOTING now explain the setup
  that hides IPv6 sources, so the LAN check refuses internet sources as
  designed.
- **`/tmp` paths under systemd:** a query path under `/tmp` fails to write,
  as before this CL, because the private `/tmp` is read-only.

## Files changed

- `deploy/s-hole.service`, `deploy/install-linux.sh`: the sandbox lines and
  `ReadOnlyPaths=/tmp /var/tmp` (the unit and the heredoc stay
  byte-identical).
- `cmd/s-hole/unit_test.go` (new): see Testing.
- `Dockerfile`: a comment only (`--cap-drop ALL` needs
  `--cap-add NET_BIND_SERVICE`); the image does not change.
- `CLAUDE.md`: the frequent-duplicates entry for the unit names the new
  test.
- Docs: `README.md`, `SECURITY.md`, `docs/DESIGN.md`,
  `docs/TROUBLESHOOTING.md`, `docs/CHANGELOG.md`, `docs/CL.md`, this file.

## Testing

A separate sub-agent wrote the tests from the requirements, without the
diff. It listed its cases first, then wrote `cmd/s-hole/unit_test.go`, next
to the existing test that reads the installer
(`TestVirtualIfacePrefixes_MatchInstaller`), so `make test` and CI run it:

- `TestInstallerUnit_MatchesServiceFile`: the installer heredoc, as bash
  writes it, equals `deploy/s-hole.service` byte for byte. On a difference,
  the test names the first line that differs. Before this CL, nothing
  checked the rule automatically.
- `TestInstallerUnit_HeredocIsQuoted`: exactly one heredoc writes the unit,
  it has a closing `EOF`, and its delimiter is quoted. Without the quotes,
  bash would expand `$MAINPID` in `ExecReload`.
- `TestUnit_HardeningLines`: in both copies, every sandbox line and every
  older hardening line is in `[Service]` with its exact value. A second
  assignment that overrides a line, or an empty one that resets a list,
  fails the test.
- `TestUnit_HardeningLines` also pins `ReadOnlyPaths=/tmp /var/tmp` once,
  next to `PrivateTmp=true` (the read-only `/tmp` decision).
- `TestUnit_AddressFamiliesAllowNetlink`: in both copies,
  `RestrictAddressFamilies` is an allow list with `AF_UNIX`, `AF_INET`,
  `AF_INET6`, and `AF_NETLINK`, and the comment above it names `AF_NETLINK`
  and the LAN check.

Mutation tests by the tester, each caught by at least one test: no
`AF_NETLINK` in both files or in the unit file only; `ProtectClock=false` in
the heredoc only; a trailing space on one heredoc line; no `ProtectHome`; no
second `SystemCallFilter` line; an empty `RestrictAddressFamilies=` reset;
an unquoted heredoc delimiter; no `AF_NETLINK` comment; `ExecReload` with
TERM; a deny list (`~AF_PACKET`); `PrivateTmp` in `[Install]`; no
`ReadOnlyPaths` line, one without `/var/tmp`, a second one, and
`PrivateTmp=false`. No new test
failed against the code.
