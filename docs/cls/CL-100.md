# CL 100: Graduate the CHANGELOG to v2.0.1

## Description

Graduate the CHANGELOG's `[Unreleased]` section to `[2.0.1] - 2026-10-08` and
add a fresh empty `[Unreleased]` above it. A `v2.0.1` tag push needs this step:
`.github/workflows/release.yml` draws the GitHub Release notes from the
matching `[2.0.1]` CHANGELOG section, so that section must exist at the tagged
commit. No workflow or Go code changes.

## Motivation

`v2.0.0` shipped on 2026-10-07. Since then the `[Unreleased]` section has
collected the operator-visible work from CL 97 (DNS answer integrity, b/096),
CL 98 (blocklist redirect policy, b/097), and CL 99 (activity data and
application log privacy, b/098, b/099). These are fixes that keep the config
format and the config defaults, so the release is a patch.

## What it does

- Rename `## [Unreleased]` to `## [2.0.1] - 2026-10-08`, then insert a fresh
  empty `## [Unreleased]` above it.
- Add a short intro to the section. It says that this is a patch release with
  privacy and security fixes, that the config does not change, that the
  dashboard graph is empty under the default `query_log.mode: "none"`, and
  that lines s-hole 2.0.0 wrote to the system journal stay there.
- Rewrap two Security bullets that had over-long lines. Their text does not
  change.
- Update the version in three README examples (the archive name, the
  `docker pull` tag, and the `s-hole -version` output) from 2.0.0 to 2.0.1.

## Design decisions

- **Graduation is its own CL, merged before the tag,** as CONTRIBUTING's
  "Cutting a release" requires and as CL 96 did for 2.0.0. Otherwise the
  release-notes extractor falls back to a placeholder.
- **The intro names the one visible change.** An operator who upgrades sees an
  empty graph on the default dashboard. The first lines of the GitHub Release
  say why, so it does not read as a defect.
- **The intro names the old journal lines.** CL 99 stops new query counts in
  the journal, but s-hole cannot delete what 2.0.0 already wrote there.
- **No CHANGELOG bullet of its own.** The graduation changes no runtime
  behavior.

## Files changed

- `docs/CHANGELOG.md`: graduate `[Unreleased]` to `[2.0.1] - 2026-10-08`, add a
  fresh empty `[Unreleased]`, add the intro, and rewrap two bullets.
- `README.md`: the version in three examples.
- `docs/CL.md`: index row for CL 100.
- `docs/cls/CL-100.md`: this file.

No Go code changed. `internal/version` reads the ldflags, so a build tagged
`v2.0.1` reports the tag with no source change.

## Testing

- `make check` stays green; no Go code changed.
- Ran the release-notes `awk` extractor from `release.yml` against the
  graduated `docs/CHANGELOG.md` with `version=2.0.1`. It returns the `[2.0.1]`
  body (79 lines, about 4.8 KB) from the intro to the last Security bullet, and
  nothing from `[2.0.0]`.
- End-to-end validation follows CONTRIBUTING "Cutting a release" after this CL
  merges: push `v2.0.1-rc1`, verify the archives, `SHA256SUMS`, `-version`, the
  `ghcr.io/lcsabi/s-hole:2.0.1-rc1` image, and the rendered notes, then delete
  the rc and cut `v2.0.1`.

## Privacy impact

None. The change edits release notes and documentation only. It collects,
stores, and sends no data.
