# CL 78: Go runtime gauges on /metrics

## Description

Add three Go-runtime gauges to the `/metrics` exposition so an external monitor
can watch the process for a goroutine leak or heap growth: `shole_goroutines`,
`shole_memory_alloc_bytes`, and `shole_memory_heap_inuse_bytes`. The gauges are
read from the sampled `runtime/metrics` API, once per scrape, in `handleMetrics`.
No new dependency and no config change. Implements ROADMAP #30.

## Motivation

`/metrics` exposed query, cache, blocklist, and upstream-failure metrics, but
nothing about the process itself. s-hole spawns one goroutine per query
(miekg/dns), so a handler path that stops returning leaks goroutines until the
process falls over. The goleak tests guard that property in CI, but production
had no signal for it, and no heap-growth signal at all.

A self-watchdog was rejected in the ROADMAP: a wedged or OOM-killed process
cannot log its own failure, and self-restart belongs to systemd `Restart=` and
the Windows SCM, not to code on the DNS path. Gauges on `/metrics` put the signal
where an external monitor already scrapes and hand alerting to the layer that can
act. This is the last-but-one item in the observability group and feeds #26
(Grafana/Prometheus examples): the goroutine gauge is a natural leak-canary alert.

## What it does

- **api (`internal/api/metrics.go`)**: `handleMetrics` calls a new
  `writeRuntimeGauges`. It builds a three-element `[]metrics.Sample` (the goroutine
  count and two heap classes), reads them in one `metrics.Read` call, and emits:
  - `shole_goroutines` from `/sched/goroutines:goroutines`.
  - `shole_memory_alloc_bytes` from `/memory/classes/heap/objects:bytes` (equals
    `runtime.MemStats.HeapAlloc`).
  - `shole_memory_heap_inuse_bytes` from `/memory/classes/heap/objects:bytes` plus
    `/memory/classes/heap/unused:bytes` (equals `runtime.MemStats.HeapInuse`:
    in-use span bytes, i.e. allocated objects plus span fragmentation).

  A sample whose `Kind` is not `KindUint64` (a name a future Go release dropped) is
  skipped rather than emitted as a garbage value; the heap-inuse gauge needs both
  its classes present.
- **api (`internal/api/api.go`)**: a new unexported `readRuntimeMetrics
  func([]metrics.Sample)` field on `Server`, defaulting to `metrics.Read` in `New`.
  It is the test seam that lets a test count reads per scrape and drive the
  KindBad path, mirroring the existing `upstreamTransportFailures` seam idiom.

## Design decisions

- **`runtime/metrics` sampled API, not `runtime.ReadMemStats`.** `ReadMemStats`
  triggers a stop-the-world pause; the sampled API does not, because the runtime
  maintains these values continuously and `Read` only copies them. The read is on
  the scrape path, never the query path, so even a brief pause would not touch DNS
  latency, but the sampled API removes it entirely and is the Go team's
  recommended direction. The tradeoff is that the class names map less obviously
  to the gauge meanings, so the mapping is documented in the code comment and in
  the DESIGN Metrics reference table.
- **`shole_` prefix, not `go_`-mirrored names.** Every other series is `shole_`
  prefixed. s-hole ships its own dashboard (#26), so the benefit of matching
  `client_golang`'s `go_goroutines` names (a stock community Grafana panel working
  unchanged) does not apply, and the single namespace is worth more. This resolves
  the "pick one convention" open question in ROADMAP #30.
- **One read per scrape.** The three samples are read in a single `metrics.Read`
  call, never one per gauge, so a scrape costs one sampled read. A test asserts the
  seam is called exactly once per `GET /metrics`.
- **No access gate.** Unlike pprof (opt-in by design), these gauges leak nothing
  sensitive, so they ride the existing `/metrics` endpoint with no new flag or
  config key.
- **GC-pause gauge deferred.** The ROADMAP lists it as optional, "if the heap
  gauges alone do not tell the story." The first cut stays minimal; it can be added
  later without a breaking change.

## Hot-path cost

None. The gauges are read only in `handleMetrics`, at scrape time, off the DNS
serving path, the same lazy pattern the existing counters use. No goroutine is
started and no shared state is added.

## Files changed

- `internal/api/metrics.go`: the `writeRuntimeGauges` helper, the three sample-name
  constants, and the call from `handleMetrics`.
- `internal/api/api.go`: the `readRuntimeMetrics` seam field, its default in `New`,
  the `runtime/metrics` import, and the `/metrics` route-doc line.
- `internal/api/api_test.go`: `TestMetricsEndpoint_IncludesRuntimeGauges` (asserts
  the three gauge type lines, a single read per scrape, goroutines > 0, and
  heap-inuse >= alloc against real data) and
  `TestMetricsEndpoint_OmitsRuntimeGaugesWhenUnavailable` (the KindBad path), plus
  the `parseMetricValue` test helper.
- Docs: `README.md` (the `/metrics` route row trimmed to a pointer, the
  Observability feature bullet), `docs/DESIGN.md` (three rows added to the Metrics
  reference table, the API-table row deduped to a pointer, the observability prose),
  `docs/CHANGELOG.md`, `docs/CL.md`, ROADMAP #30 flipped to done and the
  observability-group note and naming open-question updated.

## Testing

- `make check` clean (fmt, vet, lint, lint-sh, test); `-race` clean on `api`.
- Coverage floor held: `internal/api` at or above its 85% floor.
- Manual smoke: ran the binary with `S_HOLE_LISTEN=:5353
  S_HOLE_API_LISTEN=127.0.0.1:8080`, scraped `/metrics`, and confirmed the three
  gauges appear with `# HELP`/`# TYPE gauge` lines and plausible values
  (`shole_goroutines` a small positive number, `shole_memory_heap_inuse_bytes`
  above `shole_memory_alloc_bytes`). Drove queries and re-scraped: goroutines
  returned to baseline (no leak) and the heap bytes moved.
