# CL 90: DNS listener lifecycle, the Windows service failure path, and DoT test fixes

## Description

This CL fixes the listener findings from the code review of CL 86 and CL 88,
three bugs that the review exposed, and one bug that the Windows test of this
CL found.

- **b/063.** The UDP and TCP servers bound their own sockets inside `Start`.
  A `Shutdown` that ran before a server had started closed nothing, and that
  server then bound the port and served until the process exited. Now
  `dnsserver.Listen` binds both sockets in main, right after config
  validation, the same way `ListenDoT` binds the DoT port. `NewServer` takes
  the sockets, and `Shutdown` closes every socket itself.
- **b/064.** A DNS listener that failed while s-hole ran made main call
  `os.Exit(1)` at once, without the ordered teardown. Now `blockUntilStopped`
  calls `doStop`, waits for the teardown, and then returns 1.
- **b/065.** Under the Windows SCM, a DNS server that stopped with an error
  left the service reporting Running while it answered nothing. Now `Execute`
  also waits for the DNS server. If it returns first, `Execute` runs `doStop`
  and returns a service-specific exit code. `-service install` sets restart
  actions for that case.
- **b/066.** The Windows test showed that a service with the sample config's
  relative paths wrote its files into `C:\Windows\System32`, the working
  directory the SCM gives every service. When the SCM starts s-hole, main now
  changes to the config file's directory before it loads the config.
- **DoT timeouts.** The DoT server sets its read timeout (2 s, which also
  covers the TLS handshake) and idle timeout (8 s) explicitly. They bound how
  long a silent client holds one of the 256 connection slots. They matched the
  miekg/dns defaults before; now a change of those defaults cannot remove the
  bound.
- **Test fixes from the review.** The DoT untrusted-client test now asserts a
  certificate error, the `/api/stats` DoT tests assert the wire keys, the
  drain test `TestServer_StartDrainsEveryListenerOnError` and its 50 ms sleep
  are replaced by `TestServer_StartReturnsRuntimeListenerError`, which has no
  sleep, and new tests pin the TLS
  1.2 floor and the DoT timeouts.

## Motivation

The review of CL 86 and CL 88 found these as standards findings, notes on
correct requirements, and one open question:

- The 50 ms sleep in `TestServer_StartDrainsEveryListenerOnError` could flake, and goleak would
  then fail the whole `dnsserver` package. Its root cause was b/063, which
  CL 86 had fixed for the DoT listener only.
- A runtime serve error exited without the teardown. The review asked whether
  this path was reachable. DoT made it reachable, because the DoT port is
  bound before `Start`, so a DoT error comes from a running listener.
- Checking the Windows side of that question showed b/065: the service kept
  reporting Running with no DNS server behind it.
- The DoT idle timeout was a miekg/dns default that no s-hole code set or
  tested, and nothing tested the TLS 1.2 floor.
- `TestDoT_UntrustedClientFailsHandshake` passed on any error, so no s-hole
  defect could fail it. The `/api/stats` DoT tests decoded into the
  production struct, so a JSON tag rename could not fail them.

The maintainer chose to fix the Windows side in this CL too, with a test on
the Windows VM, instead of filing it for later.

## What it does

- **`internal/dnsserver/server.go`.** New `Listen(addr)` binds UDP, then TCP,
  and closes the UDP socket if the TCP bind fails. `NewServer(pc, ln,
  handler)` builds the two servers on those sockets. `serve` runs every server
  through `ActivateAndServe` and treats `net.ErrClosed` as a clean stop.
  `Shutdown` stops each server, then closes its socket; the three
  per-transport warnings became one `dns listener shutdown failed` with a
  `net` field. `EnableDoT` sets `ReadTimeout` and `IdleTimeout` from two new
  constants.
- **`cmd/s-hole/main.go`.** main calls `dnsserver.Listen` before the DoT bind.
  A failure logs `dns listen failed` with a hint and exits 1.
  `blockUntilStopped` takes `stop` and, on a serve error, calls it and waits
  for `done` before it returns 1. The Windows path passes a `func() error`
  that logs `dns server failed` at ERROR.
- **`internal/service/svc_windows.go`.** `Run` takes `func() error`. `Execute`
  selects on the SCM requests and on the DNS server's result. It also answers
  `Interrogate`. When the DNS server returns first, it reports StopPending,
  runs `stop`, and returns `(true, 1)`. `Install` calls `setRecovery`: three
  `ServiceRestart` actions 5 s apart, a 24-hour reset period, and
  `SetRecoveryActionsOnNonCrashFailures(true)`. A failure there is a warning,
  like the event-source registration.
- **`internal/service/svc_other.go`.** The stub `Run` returns `fn`'s error.
- **`cmd/s-hole/main.go` (b/066).** New `chdirToConfigDir(cfgPath, chdir)`
  resolves the config path, changes to its directory, and returns it. main
  calls it with `os.Chdir` only when `service.IsWindowsService()` is true,
  before `config.LoadAndValidate`; a failure logs `working directory change
  failed` and exits 1.
- **Docs.** CLAUDE.md (shutdown ordering, the Windows SCM note, the three
  seeded config fields, the `dnsserver` test time), README (Windows restart
  actions and the `sc.exe` commands for an existing install), DESIGN (the DNS server
  section, the DoT timeouts, the Windows service paragraph, the lifecycle
  tests), TROUBLESHOOTING (`dns listen failed` for a port conflict and
  for a missing permission, and a new section for a listener that fails while
  s-hole runs), CHANGELOG, CL.md, and b/063, b/064,
  and b/065 in BUGS.md.

## Design decisions

- **Bind in main, like DoT.** A mutex and a "closed" flag in `Server` would
  also stop a late `Start`, but binding early fixes the race by construction.
  It also moves a port conflict to the start of main, before the blocklist
  download, with a message that names it. Two alternatives were rejected:
  a wait for miekg's `NotifyStartedFunc` in `Shutdown` adds a wait to the
  stop path, and a test-only fix leaves the production race in place.
- **A runtime listener failure stops the process.** Degrading (keep the other
  listeners, mark one down) would need a "listener down" state in the badge,
  `/metrics`, and the alerts. It is also what CL 86 chose against at startup:
  a DoT listener that is silently down cuts off the clients that need it.
  With `Restart=on-failure` and the new Windows recovery actions, a failure
  repairs itself in about 5 s.
- **Exit non-zero after the teardown.** `doStop` has no exit code. If the
  serve error only called `doStop`, the process would exit 0, and systemd's
  `on-failure` would not restart it.
- **A nil return from the DNS server is a clean stop on Windows.** Only
  `Shutdown` makes `Start` return nil. Go can deliver a Windows shutdown event
  to main's signal handler as SIGTERM, which runs `doStop` outside the SCM
  loop. `Execute` then reports a clean stop, not a failure, so the SCM does
  not restart a service that the system is stopping.
- **Windows: a service-specific exit code plus non-crash recovery.** The SCM
  applies recovery actions to a crash by default. A service that reports
  Stopped with an error code is not a crash, so `Install` also sets the
  non-crash flag. Recovery actions are set only at install time. An existing service
  gets them with two `sc.exe` commands (`failure` and `failureflag`), which
  the README gives, so no reinstall is needed.
- **Set the DoT timeouts to the miekg defaults.** The values do not change.
  The CL makes the bound part of s-hole's code, where a test can pin it.
- **b/066: change to the config directory, in code.** A note in the README
  alone would leave the sample config writing into the system folder for
  anyone who follows it as written. The config directory is the natural
  base: `-service install` stores the config path as an absolute path, and it
  matches how the systemd unit (`/var/lib/s-hole`) and Docker (`/app`) place
  relative paths next to the data. Resolving each relative path against the
  config directory in `config` was the other option; changing the working
  directory once covers every path, including ones a later feature adds. Only
  the service changes directory, so an interactive run keeps the shell's
  directory, as a command-line tool does.
- **The idle-timeout test waits the real 8 s.** A test seam that shortens the
  timeout would test the seam, not the constant. The test is skipped with
  `-short`, and CLAUDE.md records the longer package time.

## Testing

A separate cold sub-agent wrote the tests from the requirements (the review
findings and the b/063 to b/065 behavior), without the diff. It listed its
cases before it read the existing tests.

- **`internal/dnsserver/server_test.go`** (rewritten). `pickFreePort` now binds
  through `Listen` and keeps both sockets open, with the b/029 random probing.
  Tests: `TestListen_BindsUDPAndTCPOnSamePort`,
  `TestListen_UDPBindFailureReturnsError`,
  `TestListen_TCPBindFailureReleasesUDP`, `TestNewServer_UsesGivenSockets`,
  `TestServer_ShutdownBeforeStartReleasesPorts` and
  `TestServer_ShutdownRacesStart` (b/063; 30 rounds with DoT on),
  `TestServer_StartShutdownLifecycle`, and
  `TestServer_StartReturnsRuntimeListenerError` (a UDP socket whose read fails
  with an error that is not `net.ErrClosed`; TCP and DoT keep answering until
  Shutdown; no sleep).
- **`internal/dnsserver/dot_test.go`.** The untrusted-client test asserts
  `x509.UnknownAuthorityError` or `*tls.CertificateVerificationError`. New:
  `TestDoT_SilentTCPClientIsDisconnected`,
  `TestDoT_SilentAfterHandshakeIsDisconnected`,
  `TestDoT_IdleConnectionClosedAfterIdleTimeout` (skipped with `-short`),
  `TestDoT_RejectsTLS11`, and `TestDoT_AcceptsTLS12`.
- **`internal/api/dot_test.go`.** The DoT stats tests decode into
  `map[string]any` and assert each documented key by name.
- **`cmd/s-hole/main_test.go`.** `TestBlockUntilStopped_WaitsForTeardown`
  (clean stop: returns 0, no `stop` call), and new
  `TestBlockUntilStopped_StartErrorStopsThenWaits`,
  `TestBlockUntilStopped_StartErrorRunsFullTeardown` (with the real
  `shutdown`), and `TestBlockUntilStopped_NilStartIgnored` (b/064).
- **`internal/service/svc_other_test.go`.** The stub `Run` returns `fn`'s error
  and never calls `stop`.
- **`cmd/s-hole/main_test.go` (b/066, written by a second cold sub-agent).**
  `TestChdirToConfigDir_AbsolutePath`, `TestChdirToConfigDir_RelativePath`
  (a nested and a bare relative config path, resolved against the working
  directory at call time), `TestChdirToConfigDir_ChdirError`, and
  `TestChdirToConfigDir_RealChdir` (with `os.Chdir` and `t.Chdir`: a
  relative `queries.db` created afterwards lands in the config directory).
  6 of 6 mutations caught. The call in `main()` under the SCM is not
  unit-testable; the Windows host test covers it.

Mutation testing: 17 mutations, 16 caught. Among them: `Shutdown` not
closing the sockets, `Listen` not closing UDP after a TCP failure,
`ErrClosed` treated as a failure, each DoT timeout at 30 s and the idle
timeout at 2 s, `MinVersion` at TLS 1.0, a DoT listener without TLS, and
`blockUntilStopped` returning before `done`, never calling `stop`, or calling
it twice. The survivor is removing the `MinVersion` line: Go's TLS server
already defaults to TLS 1.2, so no black-box test can see it. The explicit
floor stays as defense in depth. Removing the two DoT timeouts, which were
not among the 17 mutations, would also survive, because they equal the miekg defaults. The tests pin their values
instead: a 30 s read or idle timeout fails them.

VM test (Debian 13 VM, systemd service, 2026-09-29):

- **Startup and queries.** The service binds `[::]:53` for UDP and TCP and
  `[::]:853` for DoT. `dig` over UDP, TCP, and TLS gets the sinkhole answer.
- **Port conflict (b/063).** A second instance on port 53 stops at once,
  before the blocklist load: `level=ERROR msg="dns listen failed" listen=:53
  err="dns: listen udp :53: bind: address already in use"` with the hint, and
  exit code 1. The first run showed the protocol and address twice in `err`;
  `Listen` now wraps the net error without adding them again.
- **Stop.** `systemctl stop` took 0.09 s and left no s-hole socket on 53, 853,
  or 8080. The next start took them again.
- **Runtime failure (b/064).** With `gdb`, the agent injected
  `shutdown(fd, SHUT_RDWR)` on the running DoT listening socket. `Accept`
  failed with `accept4: invalid argument`, and s-hole logged `dns server
  failed`, `shutting down`, and the final `msg=stats` line, then exited with
  status 1. systemd restarted it after 5 s (restart counter 1), and the new
  process answered over UDP and DoT. (`ss -K` cannot destroy a listening
  socket, and closing the descriptor would leave `Accept` parked in the
  poller, so a real socket error needed the injected call.)
- **DoT timeouts.** A TCP client that sent nothing was closed after 2.2 s. A
  TLS 1.3 client that sent one query and then nothing was closed after 8.4 s.
- **Windows.** VirtualBox on this host could not run a Windows 11 guest
  (the host is Windows 10 Home with WSL2, so VirtualBox runs on Hyper-V and
  its firmware hung while it started the second CPU). The maintainer ran the
  test on the Windows 10 Home host instead, as a service on
  `127.0.0.1:5354`, and the agent checked each phase from WSL:
  - `-service install` set a reset period of 86400 s, three restart
    actions 5000 ms apart, and `FAILURE_ACTIONS_ON_NONCRASH_FAILURES: TRUE`.
    The service runs as LocalSystem with auto-start.
  - DNS over UDP and TCP answered `0.0.0.0` for a blocked name, and the
    queries reached the `log_file`. The Event Log entries have separate
    fields and the right severity (b/062 on Windows).
  - A second instance on the same port exited 1 with `dns listen failed`.
    The Windows error text is "Only one usage of each socket address
    (protocol/network address/port) is normally permitted"; the
    troubleshooting guide now quotes it next to the Linux text.
  - `Stop-Process -Force` on the service: the SCM logged event 7031 and
    restarted it 5 s later with a new process, and DNS answered again.
  - `-service stop`: `STOPPED` with exit code 0, the `shutting down` and
    `msg=stats` lines, and no restart within 15 s.
  - The README's two `sc.exe` commands gave the same recovery settings as
    `-service install`.
  - Not tested: the `Execute` branch for a DNS server that fails while the
    service keeps running (b/065). Windows has no tool here to make a
    listener fail at runtime; the same failure was forced on Linux with
    `gdb`, and the recovery actions it relies on passed above.
  - b/066: with the sample's relative `query_db: "queries.db"` and
    `cache_dir: "."` and a relative `log_file`, a service from the build
    before the fix wrote `queries.db`, `queries.log`, and both blocklist
    cache files into `C:\Windows\System32` and none into its own folder.
    The fixed build (`bedeb1f`) logged `working directory set to the config
    directory dir=C:\s-hole-cwd-test` and wrote all four files there, and
    none into `System32`. The test script refused to run if any of those
    names already existed in `System32`, and removed only the files it found
    there.
  - `nslookup -port=5354` timed out against the service while raw DNS
    queries from PowerShell got answers, so `nslookup` is not a usable tool
    for a non-standard port here.

`make check` passes. `CGO_ENABLED=1 go test -race -count=3` on `dnsserver`
and `cmd/s-hole` passes, and 30 runs of the port and lifecycle tests showed no
flake. Coverage: `dnsserver` 93.7 %, `api` 91.5 %. The Windows `Execute` path
and the recovery actions cannot run on Linux; they pass `GOOS=windows go vet`
and need the Windows VM.
