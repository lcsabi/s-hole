# CL 67: Tighten the installer's identity and port-53 checks (after CL 66)

## Description

A two-axis code review of CL 66 left four small follow-ups. This CL closes them.
Two harden `deploy/install-linux.sh`; two are doc-drift fixes that CL 66 missed.
No Go code and no runtime behavior change.

## Motivation

CL 66 hardened the deploy path but the review found gaps that could still let a
bad input or a stale doc through:

- The pre-install `-version` exec proved only that the file ran, not that it was
  s-hole. An unrelated ELF that exits 0 on an unknown `-version` flag would pass
  the gate and be installed as `/usr/local/bin/s-hole`.
- The port-53 preflight probed UDP only. The `systemd-resolved` stub holds both
  UDP and TCP `:53`, so a TCP-only hold would go undetected.
- `CONTRIBUTING.md` did not mention the installer's `--free-port-53` flag, which
  `README.md` documents. The two docs disagreed.
- `CLAUDE.md`'s `make check` line still read `fmt + vet + lint + test` after CL 66
  folded `lint-sh` into `check`. `README.md` and `CONTRIBUTING.md` were synced;
  this one place was not.

## What it does

- **Binary identity.** The pre-install check now pipes `-version` through
  `grep -q '^s-hole '`. `version.String()` starts with `s-hole `, so a runnable
  but non-s-hole ELF is now rejected before install, not just a file that fails
  to run.
- **Port-53 preflight probes TCP too.** `ss -H -lun` becomes `ss -H -lunt`, so
  the stub is detected whether it holds UDP, TCP, or both.
- **`CONTRIBUTING.md`** documents `deploy/install-linux.sh` and `--free-port-53`
  in the "Running the binary" section, matching README.
- **`CLAUDE.md`** `make check` line now reads `fmt + vet + lint + lint-sh + test`.

## Files changed

- `deploy/install-linux.sh`: assert s-hole identity in the pre-install exec; add
  TCP to the port-53 probe.
- `CONTRIBUTING.md`: document the installer and `--free-port-53`.
- `CLAUDE.md`: sync the `make check` enumeration with the `lint-sh` addition.
- `docs/CHANGELOG.md`, `docs/CL.md`, `docs/cls/CL-67.md`: changelog, index, this
  file.

## Testing

- `shellcheck deploy/*.sh` clean; `bash -n deploy/install-linux.sh` clean.
- Confirmed a real build prints `s-hole dev` on `-version`, so the `^s-hole `
  grep matches the identity it gates on.
- The root/systemd paths (identity rejection of a swapped or wrong file, the
  TCP-only port-53 case) are exercised by the ROADMAP #1 VM installer rehearsal,
  not by unit tests. `deploy/*.sh` sits below the gated coverage floors.
