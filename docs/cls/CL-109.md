# CL 109: the DoH redirect and log leak tests do not fail on a reused port

## Description

Tests in `internal/dnsserver` failed now and then (b/106):

- **Leak scans.** Five tests search the application log text for the fake
  client's address and port (`33333`, `44444`). The text also holds each
  record's time stamp, which has nanosecond digits, and some summaries name
  an upstream test server whose port the OS picks. Either can hold the
  number.
- **Failover count.** `TestServeDNS_DoHRedirectFailsOverAndIsCounted`
  expects one new transport failure for its upstream. The package shares one
  upstream tracker, keyed by URL. When the OS gave the test server the port
  of an earlier upstream that failed, that URL was still in cooldown. The
  forwarder skipped it, and no failure was counted.

A shared helper, `appLog.scanText`, gives the leak scans the log records
without the `time` field and with the addresses that the log must name
removed. The failover test clears the cooldown of its URL before it
measures.

No production code changes. The comment on `forwardTracker` now says that
the ServeDNS tests share it.

## Motivation

A flake in `dnsserver` fails the whole package in CI and in `make check`.
One `make check` run during CL 108 failed in
`TestServeDNS_DoHRedirectSummaryNamesNoQuery`; a stress run reproduced it and
the failover count.

## Design decisions

- **Remove the known addresses, do not change the client port.** Any port
  number can collide with a port that the OS gives a test server. Removing
  the address that the summary must name keeps the scan strict for
  everything else: the client address and port, the query name, and the
  redirect target.
- **One helper for every leak scan.** The time stamp hazard is in every scan
  of the raw log text, so all five use `scanText`, not only the test that
  failed.
- **Clear the cooldown, do not reset the tracker.** `recordSuccess` removes
  only the cooldown entry of this URL. The cumulative failure counts stay,
  and the test still measures a difference.
- **No cold tester.** The change is in test code, not in implemented code,
  so the CLAUDE.md rule for a cold tester does not apply. The evidence is the
  stress run and the mutation check below.

## Files changed

- `internal/dnsserver/privacy_test.go`: `appLog.scanText`; the
  write-failure scan and `assertNoQueryData` use it.
- `internal/dnsserver/redirect_test.go`: the two redirect tests (b/106).
- `internal/dnsserver/failures_test.go`, `internal/dnsserver/admission_test.go`:
  the leak scans use `scanText`.
- `internal/dnsserver/upstream.go`: the `forwardTracker` comment only.
- `docs/BUGS.md`: b/106.
- `docs/CL.md`, this file.

## Testing

- Before the fix, a stress run of the redirect and DoH tests (4 processes,
  `-test.count=150` each, `-test.run 'Redirect|DoH'`) failed in all four
  processes: `TestServeDNS_DoHRedirectFailsOverAndIsCounted` several times,
  and `TestServeDNS_DoHRedirectSummaryNamesNoQuery` once with
  `127.0.0.1:33333` as the upstream. After the fix, the same run passes in
  all four processes.
- Mutation check: a log line planted after the summary with the client
  address (`192.168.1.100:33333`), the client port, or the query name still
  fails `TestServeDNS_DoHRedirectSummaryNamesNoQuery` and
  `TestServeDNS_UnresolvedSummaryNamesNoQuery` (all three modes).
- `make check` passes.
