# CL 57: route slog to the Windows Event Log under the SCM

## Description

When s-hole runs as a Windows service, route its `slog` application log to the
Windows Event Log instead of stdout. `-service install` registers the event
source and `-service uninstall` removes it. Implements ROADMAP #7.

## Motivation

A Windows service process has no console, so the stdout-bound slog handler is
discarded under the SCM: startup errors, config-load failures,
blocklist-refresh failures, and the admin audit lines are all silently lost.
This is the application log stream, separate from the `log_file` query log (the
`FileLogger`'s per-query `ALLOW`/`BLOCK` lines): the query log has a file sink,
the slog stream had none. Linux is unaffected because journald captures stdout.

The Windows Event Log is the fix over a file: it is where an operator looks for
service logs (Event Viewer > Windows Logs > Application), and it adds no new
dependency, because `golang.org/x/sys` was already vendored for the SCM
integration and `.../windows/svc/eventlog` is a subpackage of it. A file would
reintroduce the "where does it live, is the directory writable, who rotates it"
questions and need a new config key.

## What it does

- **`eventLogHandler`** (`internal/service/eventlog.go`, no build tag): a
  `slog.Handler` that renders each record with an inner `slog.TextHandler` into a
  shared, mutex-guarded buffer, then writes the text to an `eventWriter` at the
  severity mapped from the record level (`>= Error` to `Error`, `>= Warn` to
  `Warning`, else `Info`). A `ReplaceAttr` drops the top-level `time` and `level`
  attributes, because the Event Log stamps its own timestamp and carries the
  severity out of band. `WithAttrs`/`WithGroup` share the writer, mutex, and
  buffer and delegate to the inner handler, so attribute and group propagation is
  correct. The `eventWriter` interface (`Info`/`Warning`/`Error(uint32, string)`)
  is what keeps this logic build-tag-free and testable on Linux; `*eventlog.Log`
  satisfies it, and a fake satisfies it in the test.
- **`NewEventLogHandler`** (`eventlog_windows.go`, tag `windows`):
  `eventlog.Open(svcName)` wrapped by `newEventLogHandler`. A `!windows` stub
  (`eventlog_other.go`) returns `errNotSupported` so `main` compiles with no
  platform conditionals of its own.
- **`setupLogger`** (`cmd/s-hole/main.go`): when `service.IsWindowsService()` is
  true, install the event-log handler; if opening the source fails, fall through
  to the stdout handler, so the process is never left with no logger (never worse
  than today). The interactive `-service` subcommands are not SCM-launched, so
  their console output is unchanged.
- **Install/uninstall** (`svc_windows.go`): `Install` calls
  `eventlog.InstallAsEventCreate` after creating the service (an already-existing
  source is not an error, and any other registration failure is a warning, not a
  fatal install error, since the service still runs and logs against the default
  source). `Uninstall` calls `eventlog.Remove` (a missing source is not an
  error), so both stay idempotent.

## Files changed

- `internal/service/eventlog.go`: `eventWriter`, `eventLogHandler`,
  `newEventLogHandler` (new, no build tag).
- `internal/service/eventlog_windows.go`: `NewEventLogHandler` (new, `windows`).
- `internal/service/eventlog_other.go`: `NewEventLogHandler` stub (new,
  `!windows`).
- `internal/service/eventlog_test.go`: severity mapping, time/level stripping,
  `WithAttrs`/`WithGroup` propagation, concurrent `Handle` under `-race`,
  `Enabled` threshold (new, no build tag).
- `internal/service/svc_windows.go`: event-source register in `Install`,
  deregister in `Uninstall`.
- `cmd/s-hole/main.go`: `setupLogger` Event Log branch; lifecycle package-doc
  note.

## Testing

- `make check` clean; `-race` on `internal/service`.
- `GOOS=windows GOARCH=amd64 go build ./...` green (the tagged files and the stub
  compile).
- `eventlog_test.go` pins the level-to-severity mapping, that `time`/`level` are
  stripped while `msg` and custom attrs survive, that `With`/`WithGroup`
  attributes reach the message, and that concurrent `Handle` calls are safe.
- Windows manual smoke (not CI, which is Linux): build for windows,
  `-service install` (event source registered), `-service start`, confirm the
  `starting s-hole` Info event from source `s-hole` in Event Viewer > Windows
  Logs > Application; point a blocklist at an unreachable URL and confirm a
  Warning event on refresh failure; `-service uninstall` and confirm the source
  is removed.
