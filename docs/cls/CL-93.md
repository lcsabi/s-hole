# CL 93: privacy hardening, private by default

## Description

This CL makes privacy the first design rule of s-hole. Every default is now
the most private choice, every config mistake falls back to it, and every
setting that records more is an opt-in that s-hole warns about, loudly and
repeatedly. It also fixes the privacy and security defects that a staff-level
review found (b/072 to b/087), plus seven defects found while testing: the
banner (b/088), a missing cache directory (b/089), a `.gitignore` entry that
hid new source files (b/090), an offline purge that could report success
from the wrong directory (b/091), and three defects that the pre-merge test
found (b/092 and b/093 in the installer, b/094 in the Windows purge).

The review combined four independent passes: an earlier agent's table, the
author's own review, and two cold sub-agents (one saw the earlier table, one
saw only the request). Every finding was checked against the code, and the
important ones were reproduced on a Debian 13 VM, a Raspberry Pi 5, Docker on
WSL, Windows 10, and local builds.

## Motivation

s-hole sees every DNS query on the LAN. Before this CL a fresh install
recorded every query with the device's full address and kept it forever
(`log_queries: all`, `query_privacy: raw`, retention 0), wrote the same stream
to the system journal, where retention and purge never reach, and stored it
readable by every local account. A web page in the operator's own browser
could read the whole history through DNS rebinding, or unblock a tracker for
the whole LAN with a cross-site POST, even with the dashboard on localhost.
The application log held query names whatever the settings said, the
retention prune left deleted rows in the file, and s-hole answered queries
from any source. A privacy tool has to start from the opposite position.

## What it does

- **Config format 2.0** (`internal/config`): sections `dns`, `blocking`,
  `query_log`, `admin`, plus `stats_interval`; "off" disables an output;
  `S_HOLE_<KEY_PATH>` variables. `Load` walks the YAML node tree, so an
  unknown key, a 1.x key or variable, a duplicate, or an invalid value is a
  problem that keeps the default; only a malformed `dns.listen`, an
  all-malformed upstream list, and a broken DoT pair are fatal.
  `-check-config` fails on any problem. `whitelist` becomes `allowlist`
  everywhere.
- **Private defaults:** `query_log.mode: "none"`, `clients: "drop"`,
  `database` and `file` off, retention 7 days, DoH upstreams (Quad9, then
  Cloudflare) with plain fallbacks. An unknown client mode drops the client.
- **Loud warnings** (`config.Warnings`, `cmd/s-hole/report.go`): each less
  private or less secure setting at `-check-config` and startup, one combined
  line after every stats line, and the dashboard's warnings panel; no off
  switch. Runtime warnings for stale stored rows, plaintext fallbacks, refused
  queries, and a host that uses s-hole as its own resolver.
- **Admin browser defenses** (`internal/api/security.go`): a Host check on
  every route (421 for a foreign name), `http.CrossOriginProtection`, JSON
  required on JSON endpoints, and `no-store`, CSP, framing, `nosniff`,
  referrer, and resource-policy headers.
- **Log hygiene:** no domain in a WARN line unless mode is `"all"`, never a
  client address; write errors without socket addresses; unresolved queries
  summarized once a minute with a clock hint; the query-line output is
  asynchronous, has no stdout fallback, and is `0600`; the Top lists follow
  the mode.
- **Data at rest:** a `077` umask, a `0600` database (existing files
  tightened), `UMask=0077`, a `0700` data directory, `secure_delete` with a
  TRUNCATE checkpoint after each prune, UTC timestamps with a migration, and
  a read-only check for stored rows that hold more than the current settings.
- **Purge:** `s-hole -purge`, `POST /api/purge` (from the host only), and a
  dashboard button delete the stored queries (with the row counter), the log
  file, the blocklist cache, the Top lists, the graph, and the DNS cache;
  `uninstall-linux.sh --purge` runs it.
- **LAN only** (`internal/dnsserver/lan.go`): REFUSED for any source outside
  loopback, private, link-local, unique-local, and the host's own subnets.
- **Dashboard:** what is recorded, a per-device badge, the warnings panel, a
  24-hour graph from in-memory per-minute counts, "Stored" instead of "All
  time", a purge button, `sessionStorage` for the filter, and an `esc()` that
  escapes quotes.
- **Fixes:** b/072 (OPT TTL in the cache), b/081 (UDP reply size), b/082
  (domain case), b/083 (memory after reload), b/084 (armv7 on a 64-bit
  kernel), b/085 (smoke-test port), b/088 (the banner named addresses
  s-hole did not listen on), b/089 (a missing cache directory), b/090 (the
  `.gitignore` entry for the binary also hid `cmd/s-hole/`), b/091 (an
  offline purge that reported success from the wrong directory), b/092 (a
  reinstall could not use the kept data), b/093 (a failed upgrade left the
  new binary installed), b/094 (an offline purge failed on Windows), a
  cut-off graph label, and a blocklist cache-write
  failure that dropped the list.
- **Packaging:** a non-root Docker image with a pinned builder,
  `$BUILDPLATFORM`, `-trimpath`, a `HEALTHCHECK` (`s-hole -healthcheck`), and a
  permission hint for old root-owned data; a Windows service under
  `NT SERVICE\s-hole` with an owner-only folder; installer and uninstaller
  changes (kept data to root, purge, journal command, a "keep the host off
  s-hole" box).
- **URLs and requests:** `redact.URL` on every URL s-hole shows,
  `User-Agent: s-hole` on outbound requests, `-trimpath` builds.
- **Docs:** `PRIVACY.md` (new), README (Privacy section, configuration table
  with defaults, allowed values, and warnings, host-resolver walkthroughs,
  Docker with host networking), SECURITY, DESIGN, TROUBLESHOOTING,
  CONTRIBUTING, CLAUDE.md ("Privacy first" and a full privacy and security
  review), ROADMAP (#1, #40 to #42), CHANGELOG (upgrade notes), BUGS.

## Design decisions

The maintainer decided these in the review:

- **Whose privacy:** everyone's, the household members first. The network
  owner is trusted and chooses what to record; the global `query_log.clients`
  setting stays, with no per-device opt-in list.
- **Every default and every fallback is the most private option.** Retention
  is 7 days; `0` (forever) is allowed with a warning.
- **Warnings for every less private setting, repeated, with no off switch.**
  A plain upstream fallback is not a warning by itself: it leaks nothing until
  it is used, so it is an INFO note at startup and a WARN (with a count) each
  time a query goes out unencrypted. A DoH-only list is an INFO note too: its
  risk is availability, not privacy.
- **Upstreams:** Quad9 DoH, Cloudflare DoH, Quad9 plain, Cloudflare plain. Google is
  left out; the docs do not give a reason.
- **Host check without a setting:** IP literals, `localhost`, and the
  machine's own names only; an `api_hosts` list would add a knob and a way to
  get it wrong.
- **LAN only, with no opt-out.**
- **No automatic scrub of stored rows** when a setting gets stricter: the
  operator controls the database. s-hole reports the rows and the purge
  command instead.
- **Purge reaches everything s-hole writes**, keeps the allowlist (it is
  configuration), and prints, but does not run, the journal command.
- **Device privacy tools are respected:** s-hole does not block a device's own
  encrypted DNS or private relay.
- **Docker:** host networking is the recommended Linux setup; a fixed non-root
  user with a `chown` hint, not a root entrypoint that drops privileges.
- **Authentication** is reopened as a later CL (device pairing, ROADMAP #42).
- **Step 6 of the review plan** (a fresh upstream query without client EDNS
  options, local-only names to LAN upstreams only, padding) is its own CL
  (ROADMAP #41, planned as CL 94). This CL fixes only the cache's OPT TTL
  corruption (b/072).
- **Release:** the format and default changes are breaking, so the next
  release is 2.0.0.

One decision differs from the review plan: **a purge does not reset the
since-start counters** (total, blocked, cache hits, failures). Resetting them
while queries are in flight can make a ratio exceed 100 %, the load-order
invariant `stats.Counter` protects, and making a reset safe would need a
counter restructure or a clamp that hides real regressions. The counters are
counts, not history; the purge empties the Top lists, the per-minute graph,
and every store that names a domain or a client.

## Privacy impact

- **Collected:** less. By default no query, domain, or client address is
  stored or logged. New: per-minute counts (total, blocked, cached, failed)
  in memory for 24 hours, with no domain or client; they show activity over
  time and are emptied by a restart or a purge.
- **Where it goes:** query data no longer reaches the system journal or the
  container log unless the operator sets `query_log.file: "stdout"`. The
  upstream hop is encrypted by default. No new outbound connection.
- **How long:** stored history 7 days by default, erased from the file;
  everything deletable at once with a purge.
- **Who can read it:** owner-only files on Linux and Windows; the admin API
  refuses rebinding and cross-site requests; the dashboard sends `no-store`.
- **Still open:** client EDNS options and local-only names reach the upstream
  (CL 94); a dashboard on the LAN has no login (ROADMAP #42).
