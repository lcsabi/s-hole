# CL 58: Graduate the CHANGELOG to v0.2.0

## Description

Graduate the CHANGELOG's `[Unreleased]` section to `[0.2.0] - 2026-08-28` and add
a fresh empty `[Unreleased]` above it. This is the bookkeeping step that a
`v0.2.0` tag push needs: `.github/workflows/release.yml` draws the GitHub Release
notes from the matching `[0.2.0]` CHANGELOG section, so that section must exist at
the tagged commit. No workflow or Go code changes.

## Motivation

`v0.1.0` shipped on 2026-08-24. Since then the `[Unreleased]` section has
collected the operator-visible work from CL 45 and CL 53-57: admin audit logging,
mutex/block profiling under `enable_pprof`, the cache drop metric with
expired-slot reclaim, per-source blocklist health, the `/api/check` diagnostic,
and Windows Event Log routing under the SCM. These are shippable but have never
carried a version tag. Cutting `v0.2.0` turns that running section into a named
release so bug reports can name a real build. A minor bump is correct: the work
adds features, not only fixes.

## What it does

- Rename `## [Unreleased]` to `## [0.2.0] - 2026-08-28`, then insert a fresh empty
  `## [Unreleased]` (empty Added/Changed/Fixed) above it.
- Drop the empty `### Fixed` heading from the graduated `[0.2.0]` section; it has
  no entries this release.
- Bump the three illustrative version strings in `README.md` (the release tarball
  name, the `ghcr.io` pull comment, and the `-version` output example) from
  `0.1.0` to `0.2.0`, so the docs show the current release.

The graduated `[0.2.0]` section carries exactly the bullets already written under
`[Unreleased]`: five Added (CL 45, 54, 55, 56, 57) and one Changed (CL 53). The
release-tooling, test-pinning, doc, and internal-perf CLs since `v0.1.0` (CL 44,
46-52) have no operator-visible behavior, so they get no release-notes bullet.

## Design decisions

- **Graduation is its own CL, merged before the tag.** CONTRIBUTING's "Cutting a
  release" requires the tag to point at a commit whose CHANGELOG already carries
  the release section, or the `awk` notes extractor falls back to a placeholder.
  This CL lands that section first.
- **Bookkeeping CL, no CHANGELOG bullet of its own.** The graduation changes no
  runtime behavior, so it adds no entry to the new `[Unreleased]` section. The
  README example bump is documentation-only for the same reason.

## Files changed

- `docs/CHANGELOG.md`: graduate `[Unreleased]` to `[0.2.0] - 2026-08-28`, add a
  fresh empty `[Unreleased]`, drop the empty `### Fixed` from `[0.2.0]`.
- `README.md`: bump the three `0.1.0` example strings to `0.2.0`.
- `docs/CL.md`: index row for CL 58.

No Go code changed. `internal/version` already consumes the ldflags, so a build
tagged `v0.2.0` reports the tag with no source change.

## Testing

- `make check` (fmt + vet + lint + test) stays green; no Go code changed.
- Ran the release-notes `awk` extractor from `release.yml` against the graduated
  `docs/CHANGELOG.md` with `version=0.2.0`; it returns exactly the `[0.2.0]` body
  (the five Added bullets and the one Changed bullet) and nothing from `[0.1.0]`.
- End-to-end validation is a maintainer step: push `v0.2.0-rc1`, confirm the four
  archives plus `SHA256SUMS` land on a `--prerelease` Release, that
  `sha256sum -c SHA256SUMS` passes, that a downloaded binary reports
  `s-hole v0.2.0-rc1`, and that `docker pull ghcr.io/lcsabi/s-hole:0.2.0-rc1`
  runs and reports the same version without moving `:latest`. Then delete the rc
  and cut `v0.2.0`.
