# CL 95: wildcard blocklists and a warning for unread lists

## Description

s-hole now reads wildcard blocklist lines (`*.example.com`) and warns about a
list whose lines it cannot read. The domain check that every blocklist line
and allowlist entry passes now also rejects names that DNS cannot have.

## Motivation

During the CL 93 checks on the Raspberry Pi, oisd's "big" list in its
"domains (wildcards)" format loaded 0 domains. Its lines look like
`*.example.com`, which the parser dropped as invalid. The log showed only an
INFO line (`domains=0`), so the operator saw a list that "loaded" and blocked
nothing.

The first plan was a WARN for a list that loads 0 domains. A live run showed
that this is not enough: EasyList, an Adblock-format list of about 80,000
lines, loaded one "domain". Its URL rule `-728.90.` passed `ValidDomain`,
which allowed a label that starts with a hyphen. So the warning compares the
lines s-hole reads with the lines it skips, and `ValidDomain` rejects such
labels.

## What it does

- **Wildcard lines** (`internal/blocklist/loader.go`, `parseHostsFormat`): a
  one-field line that starts with `*.` is stored without the `*.`. The store's
  suffix walk already blocks a plain entry's subdomains, so `*.example.com`
  blocks `example.com` and every name under it, as oisd defines it. The rest
  must pass `ValidDomain`, so `*.com` (no interior dot) cannot block a whole
  TLD, and `*.*.example.com` is dropped.
- **Skipped-line count:** `parseHostsFormat` counts the non-blank,
  non-comment lines that give no domain, and `fetchList` passes the count up
  through `sourceMeta` for a download, a cache load, and a stale-cache load.
- **Warning for an unread list** (`warnUnreadList`, called by `Update` after
  each list's `loaded` line): `blocklist has no domains` for an empty list,
  and `blocklist lines skipped` (with `read` and `skipped`) when s-hole skips
  more lines than it reads. Both carry the redacted URL and a hint that names
  the formats s-hole reads. A hosts list skips only a few lines (`localhost`,
  `broadcasthost`), so it does not warn.
- **Stricter `ValidDomain`:** no empty label (`a..com`) and no label that
  starts or ends with a hyphen. The root dot of an FQDN is still allowed. The
  check scans the bytes and does not allocate. The same function validates
  allowlist entries from the config and the dashboard, so those are stricter
  too.
- **Docs:** README (features, configuration table), `config.yaml`, DESIGN
  (blocklist loading, `ValidDomain`), TROUBLESHOOTING (the two new WARN
  lines), CHANGELOG, ROADMAP #43 (Adblock-format lists with `@@` exceptions).

## Design decisions

The maintainer decided these:

- **No Adblock parsing in this CL.** Reading `||example.com^` lines without
  the list's `@@` exceptions would block more than the list's author meant.
  ROADMAP #43 records the plan: read both, with each list's exceptions kept
  with that list.
- **The warning compares read and skipped lines**, not only zero domains,
  because a stray rule can pass the domain check (EasyList).
- **`ValidDomain` is stricter in this CL**, although the allowlist uses it
  too: a name with an empty or hyphen-edged label cannot be queried, so
  rejecting it loses nothing.

## Privacy impact

None. The change reads public blocklists and logs only the operator's list
URL, redacted. No query data is collected, stored, logged, or sent.
