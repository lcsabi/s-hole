# CL 42: Act on ultrareview findings (b/040, b/041)

## Description

An ultrareview round flagged three items. This CL acts on the two that are
self-contained code and comment fixes:

- **b/040** (blocklist): `ValidDomain` accepted a bare TLD written as an FQDN,
  such as `"com."`. A whitelist typo like `whitelist: ["com."]` then disabled
  blocking for the entire `.com` TLD, silently.
- **b/041** (config): the `applyEnvOverrides` docstring still claimed "the config
  package deliberately avoids logging", which stopped being true when CL 31 added
  a package logger.

The third finding (leaked tool-call XML at the bottom of CL-32/33/34.md) touches
immutable historical records and is handled separately.

## Motivation

b/040 is a genuine hole in a defense-in-depth check whose own CL 31 docstring
claims to prevent exactly this class of typo. The guard caught `"com"` but not
`"com."`, one keystroke apart, and the CL 30 suffix walk turned that single
whitelist entry into a TLD-wide blocking bypass with no WARN and `/readyz` still
green. b/041 is doc-vs-code drift, which CLAUDE.md treats as a bug: the stale
rationale is a tripwire that could get the CL 31 WARN removed by a later
contributor.

## What it does

**b/040.** `ValidDomain` now requires an interior dot. It rejects when the first
dot is at index 0 (a leading dot) or at the last index (a trailing dot on a
single label). A real FQDN with a root dot (`"example.com."`) still has an
interior dot and stays valid, and `normalize` strips its trailing dot as before.
The fix sits in `ValidDomain`, the single gate shared by the config whitelist
filter, `POST /api/whitelist`, and the dashboard whitelist form.

**b/041.** The docstring drops the false "deliberately avoids logging" claim and
states the real policy: env overrides are best-effort container knobs, so a
per-typo WARN on every restart is noise, and the only invariant is that a bad env
var never blocks startup. It also records why the invalid-whitelist path in
`Load` does WARN (a dropped whitelist entry can widen blocking to a subtree).
