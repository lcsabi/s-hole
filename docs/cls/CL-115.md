# CL 115: Graduate the CHANGELOG to v2.1.1

## Description

Graduate the CHANGELOG's `[Unreleased]` section to `[2.1.1] - 2026-10-09` and
add a fresh empty `[Unreleased]` above it. A `v2.1.1` tag push needs this step:
`.github/workflows/release.yml` draws the GitHub Release notes from the
matching `[2.1.1]` CHANGELOG section, so that section must exist at the tagged
commit. No workflow or Go code changes.

## Motivation

`v2.1.0` shipped on 2026-10-09. Its Linux binaries and its image carry
`golang.org/x/net` v0.57.0, which `govulncheck -mode=binary` flags with five
HTTP/2 advisories that do not affect s-hole. CL 114 updated the module to
v0.60.0. The weekly scan (`.github/workflows/vulncheck.yml`) reads the
binaries of the latest release, so the fix reaches it only in a release. The
release changes no behavior and no config, so it is a patch.

## What it does

- Rename `## [Unreleased]` to `## [2.1.1] - 2026-10-09`, then insert a fresh
  empty `## [Unreleased]` above it.
- Add a short intro to the section. It says that this is a patch release
  that updates one dependency for a clean scan of the release binaries.
  Behavior, the config format, and the config defaults do not change, and no
  change is needed at an upgrade from 2.1.0. An upgrade from 2.0.1 or earlier
  needs the actions in the 2.1.0 notes, so the intro points to them.
- Shorten the last sentence of the CL 114 bullet: the 2.1.1 binaries and
  image carry the update.
- Update the version in five README examples from 2.1.0 to 2.1.1: the archive
  name, the archive and image `gh attestation verify` commands, the
  `docker pull` tag, and the `s-hole -version` output (with a build time
  after the 2.1.0 tag). The two notes that say "From 2.1.0" stay:
  attestations started with 2.1.0.

## Design decisions

- **Graduation is its own CL, merged before the tag,** as CONTRIBUTING's
  "Cutting a release" requires and as CL 96, CL 100, and CL 113 did.
- **The intro says that no change is needed at upgrade.** The only change is
  a dependency version. The advisories are in the module's `http2` package,
  which s-hole does not link, and the packages that s-hole links (`ipv4`,
  `ipv6`, and their helpers) are the same in v0.57.0 and v0.60.0. An operator
  can upgrade at any time.
- **The intro points to the 2.1.0 notes.** The 2.1.1 Release is marked
  Latest and shows only its own section, so an operator who skips 2.1.0 needs
  the pointer to its upgrade actions.
- **The date is the planned tag date.** If the tag moves to another day, a
  follow-up edit changes the date before the tag.
- **No CHANGELOG bullet of its own.** The graduation changes no runtime
  behavior.

## Files changed

- `docs/CHANGELOG.md`: graduate `[Unreleased]` to `[2.1.1] - 2026-10-09`, add
  a fresh empty `[Unreleased]`, add the intro, and shorten the CL 114 bullet.
- `README.md`: the version in five examples and the sample build time.
- `docs/CL.md`: index row for CL 115.
- `docs/cls/CL-115.md`: this file.

No Go code changed. `internal/version` reads the ldflags, so a build tagged
`v2.1.1` reports the tag with no source change.

## Testing

- `make check` passes; no Go code changed.
- Ran the release-notes `awk` extractor from `release.yml` against the
  graduated `docs/CHANGELOG.md` for `v2.1.1` and `v2.1.1-rc1`. It returns the
  `[2.1.1]` body, from the intro to the CL 114 bullet, and nothing from
  `[2.1.0]`.
- End-to-end validation follows CONTRIBUTING "Cutting a release" after this CL
  merges: push `v2.1.1-rc1`, check the archives, `SHA256SUMS`, `-version`,
  the image, the notes, the attestations, the image SBOM, and that `govulncheck
  -mode=binary` exits 0 for every release binary; then delete the rc and cut
  `v2.1.1`.

## Privacy impact

None. The change edits release notes and documentation only. It collects,
stores, and sends no data.
