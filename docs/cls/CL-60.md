# CL 60: Stop the upstream second sweep from re-trying just-failed upstreams (b/045)

## Description

**b/045** (dnsserver): `forwardWith` in `internal/dnsserver/upstream.go` runs two
sweeps. Sweep 1 skips upstreams in cooldown and tries the rest. Sweep 2 is meant
to retry only the upstreams that were already in cooldown at function entry. The
sweep-2 gate reuses the entry-time `now` in `shouldSkip`, but sweep 1 records
each fresh failure with `recordFailure(upstream, time.Now())` at a time after
`now`. So for an upstream that just failed in sweep 1, `now.Sub(last)` is
negative, `negative < 30s` is true, `shouldSkip` returns true, and the gate
re-exchanges it. Sweep 2 retries exactly the upstreams it was written to skip.

The comment at lines 99 to 104 claims the entry-time `now` prevents this. It does
not.

## Motivation

On a total upstream outage every upstream is contacted twice per query. With
timeout (black-hole) upstreams the query burns the full 10 s `queryDeadline` and
returns `context deadline exceeded` instead of the faster "all upstreams failed".
The result is doubled failure-path latency and doubled upstream load during an
outage. The client-visible result is unchanged (SERVFAIL either way), so this is
a robustness and efficiency defect, not a resolution-correctness defect.

The existing test cannot see it. `TestForward_AllFailReturnsError` uses
connection-refused ports, which fail instantly, and asserts only `err != nil`, so
a double attempt is invisible to it.

## What it does

Track the set of upstreams actually attempted in sweep 1 and skip exactly that
set in sweep 2. Do not re-derive "not yet tried" from timestamps that sweep 1
just mutated.

- Add a local `tried := make(map[string]bool)` in `forwardWith`.
- In sweep 1, mark `tried[upstream] = true` when an upstream is exchanged (that
  is, when it is not skipped by cooldown).
- In sweep 2, skip an upstream when `tried[upstream]` is set; the `shouldSkip`
  timestamp check is no longer used to gate sweep 2.
- Rewrite the lines 99 to 104 comment to describe the set-based approach and drop
  the false claim about entry-time `now`.

## Design decisions

- **A per-call set, not a timestamp reinterpretation.** The bug is that sweep 2
  reads state that sweep 1 mutated. An explicit "attempted this call" set is
  immune to that. It is a few words of allocation on the cache-miss failure path
  only, which is already the slow path.
- **Cooldown semantics unchanged.** The tracker still records failures and skips
  recently-failed upstreams on sweep 1 of later queries. This CL changes only
  how sweep 2 of a single query decides what it has already tried.
