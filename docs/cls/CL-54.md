# CL 54: add cache drop metric and reclaim expired slots before dropping

## Description

Make the cache's drop-on-full behavior observable, and stop it firing on
entries that are already dead. Add a `shole_cache_dropped_total` counter, and
make `Set` reclaim an expired slot before it drops a new entry when the cache is
full. Record the eviction rationale (including why LRU is not used) in DESIGN and
ROADMAP.

## Motivation

`Cache.Set` drops new entries once the cache holds `cache_size` of them. That is
a deliberate simplicity trade-off, but it was invisible: no metric reported how
often it happened, so an operator could not tell whether `cache_size` (default
2000) was too small for their working set.

Adding a raw drop counter alone would have been misleading. `Get` treats an
expired entry as a miss but does not delete it (lazy expiry); the entry stays in
the map until the once-a-minute `cleanupExpired` sweep. So a cache can be "full"
of not-yet-swept corpses and refuse every insert for up to a minute, even though
those slots are effectively free. A drop counter would climb from that timing
artifact and look like capacity pressure that raising `cache_size` cannot fix.

Reclaiming an expired slot on insert removes that false signal, so the counter
reports what an operator can act on: the cache is full of *live* entries.

## What it does

- `Cache` gets an atomic `dropped` counter and a `Dropped() uint64` accessor,
  modelled on `DBLogger.Dropped()`. `handleMetrics` exposes it as
  `shole_cache_dropped_total` inside the existing cache block. `CacheStatser`
  (the `/metrics` interface) gains `Dropped()`.
- `Set`, when full, calls `reclaimOneExpired`: a bounded scan of at most
  `reclaimScanLimit` (8) entries that deletes the first expired one it finds and
  frees a slot. Go randomizes map iteration order, so the bounded scan samples
  the map. If the scan finds no expired entry, the cache is full of live entries
  and the new entry is dropped and counted. Reclaimed inserts are not counted.
- A shared `isExpired(e, now)` helper now backs `Get`, `cleanupExpired`, and
  `reclaimOneExpired`, so the three cannot disagree about when an entry is dead.
- `reclaimOneExpired` is O(8) under the write lock `Set` already holds; it does
  not touch `Get`, which stays a bare `RLock` read.

Docs:

- DESIGN eviction bullet rewritten: the reclaim behavior, the drop metric as the
  "raise `cache_size`" signal, and the real reason LRU is rejected (move-to-front
  is a write on the read path and would serialize readers, the contention
  `BenchmarkCache_Get_Parallel` guards; CLOCK/SIEVE would be the read-only way in

- ROADMAP: the "LRU cache eviction" non-goal upgraded from "simplicity
  trade-off" to the read-path reason; a new "Pending decisions" item gating
  sampled TTL-aware eviction on the drop metric showing real pressure.
- Metric name added to the DESIGN and README `/metrics` lists.
