# CL 92: the truncating-upstream test helper binds both ports through pickFreePort

## Description

`TestForward_TruncatedUDPRetriesOverTCP` could fail with `listen tcp
127.0.0.1:NNNNN: bind: address already in use` (b/071). Its helper,
`startTruncatingUpstream`, bound UDP on `127.0.0.1:0` and then bound TCP on
the same port number. The UDP bind proves nothing about TCP, so another test
package that runs at the same time could hold that TCP port.

When the test needs TCP, the helper now takes its port and both sockets from
`pickFreePort`, which binds UDP and TCP together through `dnsserver.Listen`
and probes again when either bind fails. A UDP-only caller keeps
`127.0.0.1:0`, because it needs no second transport.

No production code changes.

## Motivation

One `CGO_ENABLED=1 go test -race -count=1 ./...` run during CL 91 failed this
way, and the next three runs passed. A flake in `dnsserver` fails the whole
package in CI. CLAUDE.md already says that a test that binds ports reuses
`pickFreePort` (b/029); this helper is older than that rule.

## What it does

- **`internal/dnsserver/upstream_test.go`.** `startTruncatingUpstream` calls
  `pickFreePort` when `withTCP` is true and serves the returned `PacketConn`
  and `Listener`. The separate `net.Listen("tcp", addr)` call is gone. The
  doc comment says why (b/071).

## Design decisions

- **Reuse `pickFreePort`, do not add a retry loop in the helper.**
  `pickFreePort` already binds both transports in one step, probes random
  ports, and closes both sockets at cleanup. A second copy of that logic
  would drift.
- **Keep `127.0.0.1:0` for the UDP-only caller.** With one transport the OS
  allocator cannot collide, so the simpler bind stays.
- **No new test.** The change is in test code, so the CLAUDE.md rule for a
  cold tester (tests for implemented code) does not apply. The evidence is
  the reproduction below.
- **Other `net.Listen("tcp", addr)` calls in `server_test.go` stay.** They
  check that a port is free, or hold a port on purpose to force a conflict,
  and the conflict tests already probe random ports.

## Files changed

- `internal/dnsserver/upstream_test.go`
- `docs/BUGS.md` (b/071 fixed), `docs/CL.md`, `docs/cls/CL-92.md`

## Testing

- **Reproduction.** A script held 14115 of the 28232 TCP ports in the
  ephemeral range (32768 to 60999) on 127.0.0.1, so a UDP port from the OS
  allocator had about an even chance that its TCP twin was taken. Under that
  load, `go test -count=300 -run 'TestForward_TruncatedUDPRetriesOverTCP$'`
  failed 149 of 300 runs with `address already in use` on the old helper
  (`master`), and 0 of 300 runs, in two runs of 300, with the new helper.
- `make check` passes. `CGO_ENABLED=1 go test -race -count=3
  ./internal/dnsserver/` passes.
