# CL 65: Close the stop-before-store window in the admin server (b/054)

## Description

**b/054** (api): CL 64 made `api.Server.httpServer` an `atomic.Pointer`, which
removed the data race between `Serve`'s write and `Shutdown`'s read. A
second-order timing gap survived it. `main` binds the listener synchronously
(CL 63) and then runs `Serve` in a background goroutine, so a stop signal can
arrive after the goroutine starts but before `Serve` stores the server. In that
window `Shutdown` loads a nil pointer and no-ops, and `Serve` then blocks in
`hs.Serve(ln)` with no one left to stop it. Raised as the open question in the
CL 64 code review.

The gap is harmless in practice: the process is already exiting, so the blocked
serve goroutine is reaped by process exit, and a stop that early has no in-flight
admin request to drain. This CL closes it by construction anyway, so a later
change to the drain path cannot turn the latent hazard into a real one.

## Motivation

`Shutdown` and `Serve` coordinated only through the `httpServer` pointer, which is
nil until `Serve` stores it. A stop that read that nil had no other record that a
stop had been requested, so `Serve` could not know it should not start serving.
Relying on `main` to store the pointer before a stop can arrive is the same
call-order dependency that CL 59 and CL 64 removed by construction elsewhere.

## What it does

Add a second field, `shutdownRequested atomic.Bool`, and double-check it.

- `Shutdown` sets `shutdownRequested` before it loads `httpServer`.
- `Serve` checks `shutdownRequested` right after it stores the server. If the
  flag is set, nothing has served on the listener yet, so `Serve` closes the
  listener and returns instead of entering the serve loop.

The two set/load pairs cross, so a stop in the window cannot be lost: either
`Shutdown` loads the stored pointer and drains it, or `Serve` sees the flag and
stops itself. The public API (`Serve`, `ListenAndServe`, `Shutdown`) is
unchanged, and the normal path (stop after the server is serving) behaves exactly
as before.

## Design decisions

- **A second atomic, not a lock or a channel.** The coordination is one bool set
  once and read once, which `atomic.Bool` covers with no mutex and no new
  dependency. Go's atomics are sequentially consistent, so the crossed set/load
  pairs admit no both-miss interleaving; the field comment records that argument
  so a later reader does not re-derive it.
- **Guard the type, not the caller.** Like CL 64, the fix lives in `Server` so it
  holds regardless of how `main` sequences the bind, the goroutine, and the stop.
- **Close the listener in the flag branch.** A `Serve` that skips the serve loop
  never registered the listener with the `http.Server`, so `Shutdown` cannot
  close it. `Serve` closes it directly to avoid leaking the socket.
- **No user-visible behavior change, so no CHANGELOG bullet.** The window drained
  nothing; this is an internal robustness fix, matching how CL 64 was recorded.

## Files changed

- `internal/api/api.go`: add `shutdownRequested atomic.Bool`; `Shutdown` sets it
  before the `Load`; `Serve` checks it after the `Store` and closes the listener
  if set (b/054).
- `internal/api/api_test.go`: `TestShutdown_BeforeServeStopsTheServeLoop` calls
  `Shutdown` before `Serve` to hit the window deterministically and asserts
  `Serve` returns instead of blocking (b/054).
- `docs/DESIGN.md`: the admin-server section notes the stop-request flag and why.
- `docs/BUGS.md`: b/054 (Fixed in CL 65).
- `docs/CHANGELOG.md`: no user-visible behavior change, so no bullet.
- `docs/CL.md`: index row.
- `docs/cls/CL-65.md`: this file.

  `Serve` on a bound listener in a goroutine, and requires `Serve` to return
  within 3 seconds with a nil error. The pre-fix code blocks in Accept forever
  here; the flag makes `Serve` close the listener and return.
- `TestServe_ConcurrentShutdownIsRaceFree` (CL 64) and
  `TestShutdown_BeforeListenIsNoOp` stay green: the normal serving path and the
  never-served no-op path are unchanged.
- `make check` green. `CGO_ENABLED=1 go test -race ./internal/api/` green (WSL).
