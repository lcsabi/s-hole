# CL 119: Privacy lint, first part (client address, outbound, server error log, metric labels)

## Description

A new package, `internal/privacylint`, checks the code against the
"Privacy first" rules of `CLAUDE.md`. It is a test: `TestRepository` runs it
under `make test`, so it runs in `make check` and in CI. `make privacy-lint`
runs it alone. It is the first part of ROADMAP #45; CL 120 adds the
application-log rule and CL 121 the storage inventory.

How it works:

- The loader runs `go list -deps -export -json` and type-checks each package
  of the main module from source with `go/types`. Imports come from the
  export data in the build cache (`importer.ForCompiler` with a lookup), so
  the lint uses only the standard library. It runs once for the host GOOS and
  once for Windows, so the `_windows.go` files are checked too. Test files are
  not checked. The go command runs with `-mod=readonly`, so it does not
  change `go.mod` or `go.sum`, and with `GOWORK=off`, so a workspace file
  does not change the build. If the module cache does not have a
  module that a build needs, the go command downloads it, as `go test` does,
  and `go.sum` checks it. The plan was `GOPROXY=off`, but a fresh clone, or a
  cache filled by a Linux build only, does not have the modules that only the
  Windows build uses (`go-isatty` and `go-strftime` through `modernc.org/libc`),
  and the Windows pass then failed.
- Rules match functions, variables, and types by their full name
  (`types.Func.FullName`, such as `net/http.Get` or
  `(*net/http.Client).Do`), not by how the code spells them. A package sees
  another package through export data, so names are the stable key across
  packages. `client-address` matches a method `RemoteAddr() net.Addr` by its
  signature, so it covers every type with that method.

The rules:

| Rule | Fails | CLAUDE.md rule |
|---|---|---|
| `client-address` | a call of a `RemoteAddr() net.Addr` method, a use of the `RemoteAddr` field of `http.Request`, or a call of a function marked `//privacy:source client-address`. A type assertion that keeps only the type (`_, udp := w.RemoteAddr().(*net.UDPAddr)`, `edns.go`) is not a read | Mask the client in one place |
| `outbound` | a call that dials, looks up a name through the system resolver, or starts a program; `http.DefaultClient`, `http.DefaultTransport`, `net.DefaultResolver`; a value of `http.Client`, `http.Transport`, `net.Dialer`, `net.Resolver`, `tls.Dialer`, or `dns.Client` (a composite literal, `new`, a `var` with no value, a struct field) | No other outbound connections |
| `server-errorlog` | an `http.Server` literal whose `ErrorLog` is not `newErrorLog()`, an `http.Server` made in a way that the lint cannot check, and `http.ListenAndServe`, `ListenAndServeTLS`, `Serve`, `ServeTLS` | The application log carries no more than the query log (b/103) |
| `metric-labels` | a metric label key that is not `upstream` or `url`; a label value from a format verb whose argument does not call `redact.URL`; a label value that the lint cannot check (not the format of `fmt.Fprintf`, `Sprintf`, or `Printf`, or an explicit argument index) | Keep metrics aggregate |

Exceptions:

- `//privacy:allow <rule> <ID>: <reason>` allows the findings of its rule on
  the lines that it covers. On its own line
  it covers the simple statement, declaration, or struct field that starts on
  the next line (for a compound statement, its first line only); after code,
  its own line. The ID is `PRIV-NN`, `SEC-NN`, `b/NNN`, or `CL NN`.
- `//privacy:source client-address <ID>: <reason>` goes in a function's doc
  comment. A call of the function is a read of the client address, and the
  reads inside it are allowed. `remoteIP` (`lan.go`) and `clientIP`
  (`api.go`) carry it, so the one read in `ServeDNS` and the audit line's
  read in `auditAttrs` are visible exceptions.
- The lint fails a comment that is not valid (unknown verb, rule, or kind;
  no ID, colon, or reason; a space after `//`) and a comment that allows
  nothing. Under several GOOS passes, a comment is used when any pass used it.
- `internal/privacylint/exceptions.txt` is generated: one line per used
  comment (file, function, kind, rule, ID; no line numbers, so an unrelated
  edit does not change it). `TestRepository` fails when the file and the code
  are different. `go test ./internal/privacylint -run TestRepository -update`
  rewrites it. So a new exception always shows in the diff of that file, and
  CODEOWNERS covers `internal/privacylint/`.

## Motivation

Review and behavior tests enforced the privacy rules. A reviewer has to
remember every rule on every diff, and a behavior test pins only the code
that exists. Neither one catches a new outbound client, a new read of
`RemoteAddr`, a new `http.Server`, or a new metric label that is added later.
A lint pins the rule, so it also covers code that is not written yet. The
exceptions are in the code with a reason, and one generated file lists them,
so a reader can see every place that comes close to a rule.

Decisions (maintainer, 2026-10-11): three CLs (119, 120, 121); the
PRIVACY.md ids of CL 121 as HTML comments; a generated `exceptions.txt` with
`-update` (option C) over a hand-written list or comments only; argument
summaries in CL 120, with a fallback to ROADMAP if they give more than a few
false positives.

## Testing

A separate sub-agent wrote the tests from the requirements, without the diff
(`privacylint_test.go`, `rules_test.go`, `directive_test.go`):

- `TestRepository` is the gate: the module has no finding, and
  `exceptions.txt` equals what the code needs (`-update` rewrites it).
- 24 rule fixtures: each line that must be reported carries a `// want`
  marker, and the test compares the file, the line, and the rule. A meta test
  (`TestFixtures_EveryRuleHasBoth`) fails a rule that has no fixture that it
  must report, or no fixture that it must pass.
- 29 malformed comment forms, the valid ID forms, unused comments, the lines
  that a comment covers, source placement, source callers in another file,
  exception names and order, and `FormatExceptions`.
- `Run` on temporary modules: test files are not checked, a `_windows.go`
  finding shows only in the Windows pass, a comment used by one GOOS pass is
  used, a directory below `go.mod` checks the whole module.

The first run found four gaps in the code; the code was fixed and the tests
were not changed:

1. A label value written by `%q` (`shole_x{client=%q}`) was not read, so a
   key that is not on the allowlist passed. The label parser now reads a
   value with quotes, a value up to the next comma, and a literal that stops
   inside the label set.
2. `Run` from a directory below `go.mod` checked only that directory. The
   loader now finds the module root.
3. `/*privacy:allow ...*/` with no space was ignored. It is now a
   `directive` finding.
4. A type-only assertion through `var _, ok = ...`, or on a source function
   (a plain identifier), was reported as a read. Both are now type-only.

Mutation testing: the tester changed the code 41 times (dropped table
entries, removed exemptions, broke the verb count, loosened the ID pattern,
made the last GOOS pass win, loaded test files, and more). The tests caught
39. The other 2 give the same line and rule with another message (an
explicit argument index still fails on the format literal; an allow for
`directive` still fails as unused).

Results: `go test -cover ./internal/privacylint/`: pass, 94.8 % of
statements (floor 90 %). `golangci-lint` for Linux and Windows: 0 issues.
A warm `make privacy-lint` run takes about 1 to 2 s; the first run after a
cache clear compiles the export data for both GOOS values.

## Privacy impact

None collected. The lint reads source code only and runs in the test process.
Its only connection is the go command's module download for a module that
the cache does not have, which `go test` does too. It narrows what later code
can do.

## Limits

The lint finds accidents, not deliberate evasion. It matches calls, types,
and string literals; it does not follow data from one variable to another
(CL 120 adds that for the application log). It does not find a connection
that a function value, reflect, or a listening socket opens, or a client
address that comes through an interface with no `RemoteAddr` method.
