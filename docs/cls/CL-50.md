# CL 50: trim per-query allocations on the handler and lookup hot path

## Description

Two hot-path optimizations found by profiling the benchmarks. `clientAddr` reads
the source IP from the concrete address type instead of formatting and re-parsing
a "host:port" string, and `normalize` folds ASCII case inline instead of calling
`strings.ToLower`. Both are measured wins confirmed with `benchstat`.

## Motivation

Offline profiling of the hot-path benchmarks (`go test -bench -cpuprofile
-memprofile`, then `go tool pprof`) surfaced two per-query costs:

- In the blocked path, `net.JoinHostPort` and `net.IP.String` were a large share
  of allocations. `clientAddr` did `net.SplitHostPort(addr.String())`:
  `addr.String()` on a `*net.UDPAddr`/`*net.TCPAddr` builds "ip:port" (allocating),
  and `SplitHostPort` then parses the port back off only to discard it. Two
  allocations per query for a value we throw away. `clientAddr` runs on every
  query (it feeds the stats top-clients tracker and the query log), so it is not
  skippable.
- `normalize`'s `strings.ToLower` was ~18% of `IsBlocked` CPU. Source-reading
  suggested this was irreducible (ToLower has an all-lowercase-ASCII fast path),
  but the benchmark disagreed: an inline ASCII fold is measurably faster.

## What it does

- `clientAddr` type-switches on the address. For `*net.UDPAddr`/`*net.TCPAddr` it
  returns `a.IP.String()` directly (one allocation, no port parse). The
  `SplitHostPort` path stays as a fallback for any other `net.Addr`, and nil
  forms return "unknown".
- `normalize` scans the name once: if it is all-lowercase ASCII it returns the
  input unchanged (no allocation, the common case); an ASCII uppercase letter
  triggers a single fold pass; a non-ASCII byte defers to `strings.ToLower` for
  exact Unicode folding. Behavior is unchanged, and the zero-allocation invariant
  on an already-normalized name still holds (`TestStore_IsBlocked_ZeroAlloc`).

## Measured effect (`benchstat`, n=8-10)

| Benchmark | Before | After | Time | allocs/op |
|---|--:|--:|--:|--:|
| `Handler_ServeDNS/Blocked` | 396.6 ns | 317.4 ns | -20.0% | 7 -> 5 |
| `Handler_ServeDNS/Cached` | 719.8 ns | 549.6 ns | -23.7% | 9 -> 7 |
| `Store_IsBlocked` (hit) | 58.3 ns | 47.7 ns | -18.2% | 0 -> 0 |

`Store_IsBlocked_Miss` is unchanged (p=0.16): `normalize` is a smaller fraction of
the five-label walk. All the significant deltas have p < 0.01.

## Files changed

- `internal/dnsserver/handler.go`: `clientAddr` type switch.
- `internal/dnsserver/handler_test.go`: `TestClientAddr` covering UDP, TCP, IPv6,
  nil, typed-nil, and the non-net.Addr fallback branches.
- `internal/blocklist/store.go`: inline ASCII fold in `normalize`, with the
  non-ASCII fallback to `strings.ToLower`.
- `internal/blocklist/store_test.go`: a non-ASCII `TestNormalize` case.
- `README.md`, `docs/DESIGN.md`: refreshed coverage (blocklist 91.4 %,
  dnsserver 90.3 %, module-wide 80.4 %).

The new tests raised coverage rather than lowering it (blocklist 90.4 -> 91.4 %,
dnsserver 88.5 -> 90.3 %). No user-visible behavior changed, so no CHANGELOG
entry.
