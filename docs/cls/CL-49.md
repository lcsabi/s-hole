# CL 49: link two invariants to their guard tests at the enforcement site

## Description

Add a guard-test reference to two enforcement-site comments that stated an
invariant but did not name the test that pins it: `Store.Replace` (atomic swap)
and `Store.IsBlocked` (zero per-query allocation).

## Motivation

The project documents non-obvious invariants at the code that upholds them, next
to the invariant, so the note cannot drift away from what it describes. Most
sites already cite a stable id (b/NNN, R/S/T, or a finding like T1); the tests
reference the same id, so the id links code and guard.

Two sites had no stable id and did not name their test, so the invariant-to-test
link was invisible from the code:

- `Store.Replace` states "old or new, never partial" but named no guard.
- `Store.IsBlocked` named only `BenchmarkStore_IsBlocked`, which guards the walk
  speed. The zero-allocation property is now guarded by a separate test
  (`TestStore_IsBlocked_ZeroAlloc`, CL 46) that the comment did not mention.

## What it does

- `Store.Replace`: append "TestStore_ReplaceIsAtomic guards this."
- `Store.IsBlocked`: split the guard note so it names the benchmark for speed and
  `TestStore_IsBlocked_ZeroAlloc` for the zero-allocation property.

Comments only. Where a stable id exists the site keeps citing the id (the
lower-drift form); naming the test is reserved for these two, which have no id.

## Files changed

- `internal/blocklist/store.go`: two comment additions.

No code, config, route, test, or user-visible change, so no CHANGELOG entry and
no coverage change.

## Testing

- `make check` clean (fmt, vet, lint 0 issues, full suite). No behavior touched.
